# Запись 20 — дорожная дорожка prepare-потока: ступень обочин — свой поток, тёплый старт Парижа 9.7 → 8.3 с

Статус: фикс заезда 10 (`planned/08-road-lane.md`) · замеры живого Парижа
(два базовых и два правочных прогона, снапшот-хиты, одно состояние машины под
`caffeinate -i`, `QWE_PERF_NOAPPNAP=1`/`NOVSYNC`), офлайн-бенч
(`map_meshing paris`), временная инструментировка фаз снята до коммита
(`git restore src/map/roads.rs` — дифф был только замеры).

**Было.** Тёплый старт Парижа 9.57/9.59 с (запись 19; в этой сессии —
9.70/9.11). Стену `build_world_meshes` держала дорожная дорожка: 6.0/5.7 с
за **обе ступени обочин в одном потоке** — `build_roads` звался
последовательно по ступени (`map/prepare.rs`). Бенч одной ступени — 3.26 с
(запись 19), в этой сессии 3.12–3.14. Остальные дорожки: полимеш 4.6/4.5,
здания 2.3–2.4, заборы 2.6–2.9, мелочь 1.3 — всё стояло в тени дорожной.

**Атрибуция.** Двухраундовый разрез фаз `build_roads` (временные `eprintln`,
до коммита; бенч, ближняя ступень, Париж — **3129 мс**):

Распределение **плоское**: ни одной «арки» записи 19 (одного линейного
скана, чью цену отделяет разрез) — шесть фаз по 260–650 мс, каждая со своей
структурой записей. «До лент» — 1.43 с (та же цифра в строке отчёта
`road meshing:`), ленты 0.62, после лент ~1.07.

**Правка — одна.** Ступени обочин разъехались по потокам: в
`build_world_meshes` вместо одной группы «дороги, обе ступени
последовательно» — поток на ступень (`std::thread::scope`, результаты
собираются по номеру ступени — порядок `WorldMeshes.roads` сохранён).
Сборки независимы давно: обе зовут чистый `build_roads` от одной и той же
финальной `MapData` (гейты и состав деревьев к дорожкам отыграли), списки у
каждой свои. `rebuild_roads` не тронут — пересборка стилем/солнцем/формой
строит одну ступень, как и раньше; строка лога «roads (verge steps)» стала
двумя, «roads (verge step N)».

**Отвергнуто — параллелизация внутри `build_roads` (пункт (б) спеки).**
Разрез показал, что прецеденты зданий сюда не ложатся целиком: у зданий
была одна доминанта с независимыми единицами (экструзия, тени) и одна
«арка»; здесь шесть фаз по 260–650 мс, и каждой нужна своя операция —
свои мини-сборщики, слияние через `MeshBuilder::append`, у обочин — перенос
`Scraps`/`pieces` в результат улицы. После разъезда ступеней дорожная
дорожка (3.7 с) **больше не стена** — выигранные внутри неё секунды тёплый
старт не увидят; единственный выгодоприобретатель — пересборка живым
солнцем/стилем (одна ступень, 3.7 с в живом лейне). Цена — хирургия в пяти
фазах, включая `kerb_returns` (531 мс), параллелизация которого уже
отвергалась записью 14 (самый волосатый код репозитория). Не взято:
соотношение риск/выигрыш не то; пунктир для будущего — обочины (478 мс,
независимые по улице) и `green_scraps` (650 мс, независимые по лоскуту).

**Что дальше.** Стеной мешинга стал **полимеш** (4.6–4.7 с, панель Navmesh
включена по умолчанию) — навигационная работа, в очередь заезда не входила;
после него в стене whole set заборы 2.6–2.9. Вне мешинга — последовательно:
гейты 1.44 с и шторм warmup ~1.7–2.0 с (заявки на входе, записи 14/18).
Очередь прежняя: шторм warmup (следующий заезд), рендер-сторона шторма
(`AssetChangeCheck`, запись 15 «Отвергнутое»), kerb_returns поузлово
(запись 14), `planned/07` (кровь/кеш материалов).

**Метод.**

- Прогон: `BRP_PORT=15703 QWE_PERF_NOAPPNAP=1 QWE_PERF_NOVSYNC=1
  QWE_PERF_FRAME_SPIKES=30 caffeinate -i cargo run`, фоном; фазы — по
  временам строк лога (снапшот-хит → `warmup:`), лейны — по строкам
  `map meshes:` потока. Перезагрузка города для второго прогона —
  `brp res set City . '"Paris"'`: BRP-запись помечает ресурс изменённым,
  `retuned` уводит в загрузку даже без смены значения.
- Разрез — временные `eprintln` в теле `build_roads` (макрос-баннер по фазам
  + накопители внутри ленточного прохода), второй раунд — сверление топ-фаз;
  снят `git restore`-ом, пока дифф файла состоял только из замеров.
- Верификация геометрии без скриншот-пар: счётчики вершин отчёта
  `road meshing:` на живой ближней ступени против бенча базы (та же чистая
  функция, тот же вход) — бит-в-бит.
- Полимеш строится всегда (`PolymeshDebug::enabled` — `true` по умолчанию),
  так что его 4.7 с — стена дефолтной конфигурации, не артефакт настроек
  сессии.
