# NOTES — обзор №43 (угол: кросс-процессный детерминизм живьём — реплей-контракт, вынесенный из одного процесса в два реальных бута; вердикт: контракт держится вне процесса — 5/5 бутов бит-в-бит, рестарт живьём реплеит прогон, навмеш свежей заливки == снапшоту содержимым; неожиданная находка: BRP-запрос в первых тиках уводит прогон на альтернативную траекторию — отложено в план с рецептом разреза; зонд TEMP, коммитов нет)

Задача: сорок третье звено — обзорная форма (меню оптимизаций исчерпано,
№37–41). Угол свежий: скилл determinism прямо пишет «Not claimed» про
кросс-процессный повтор (HPA — rayon-сборка грида не аудирована), а вся
проверка реплея жила в одном процессе (тест-двор + acceptance-пример).
master на старте 08fdd29b.

## Методика

Worktree perf43 (сид кеша rsync, target засеян; settings — Тула, seed 42,
Astar, deterministic=true — файл `.settings/settings.toml` положен до
первого запуска, сидирование из системных настроек не срабатывало вовсе).
TEMP-зонд: exclusive-система в FixedUpdate после `TickStage::Dispatch`,
env-гейт `QWE_REPLAY_PROBE`, каждые 64 тика печатает Fingerprint мира
(аппарат `determinism/replay.rs` — FNV-1a по (species, pawn_id, x_bits,
y_bits, state) + killed/escaped/moving), на тике 64 — хеш всей сетки
навмеша через is_passable (3800×2850). Восемь бутов одного бинаря,
сравнение последовательностей отпечатков по тикам.

## Найдено

- **Кросс-процессный детерминизм подтверждён**: буты A и B (снапшотный
  путь, без ранних BRP-вызовов) — бит-в-бит на всех 66 семплах
  (тики 64–4160, ~105 убийств по дороге): одинаковый хеш навмеша
  `f095ba1753e96f77` и одинаковый отпечаток на каждом тике при разных
  pid, кадрах и настенных часах. Самая сильная форма контракта, которую
  скилл не заявляла, — и она держится.
- **Навмеш из свежей заливки == снапшотному бит-в-бит** в каждом буте с
  полной заливкой (D/E/F/H — один и тот же `f095ba…`): rayon-пайплайн
  fill+gates+prune (114/15535 — база №42) воспроизводит содержимое, а не
  только счётчики. HPA-оговорка скилла остаётся неаудированной (проба
  шла на Astar), плоский путь закрыт.
- **Парс с нуля не меняет мир**: E (полный json-парс, ноль BRP) == канон
  на всех общих с A/B тиках (64–3264).
- **Рестарт живьём реплеит прогон**: D-post (после RestartEvent на тике
  804) повторил канон бит-в-бит на тиках 64–1088 —
  `a_restart_replays_the_run` подтверждён вне тест-двора, вместе со
  сбросами WorldStarted реального приложения.
- **Неожиданная находка — дефект**: BRP-запрос (`res get SimTick`,
  безобидное чтение) в окне первых тиков (~0–64) уводит прогон на
  альтернативную траекторию — с тика 64 позиции всех пешек другие при
  идентичных агрегатах killed/escaped/moving на каждом семпле. Три
  ветки: канон `23d9fcca6672e097`, альтернатива-2 `dbe253af129ec7b7`
  (буты F и H — разные процессы, разные профили волн машины, gates
  1.76 s против 1.04 s — сошлись бит-в-бит: переключатель дискретный,
  не шум), альтернатива-1 `a712f5675a81f709` (D-pre). Окно закрыто
  с двух сторон: первый опрос на тике ≥ ~75 — канон (G); опросы,
  начатые после ready с тика ~5 — расхождение (H, значит фаза парса
  невиновна). Рестарт возвращает канон (D-post). Механизм не разрезан —
  отложено в docs/deepening-plan.md («Обзор №43») с рецептом: один
  запрос на фиксированном тике (5/30/60/80), варьировать ресурс и метод.
