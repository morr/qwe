# Запись 16 — конвейер заявок на шторме 30×: тихий стационар; выдача без снятия заявки, top-k на переполнении

Статус: диагностика + два фикса + env-тумблер. Файлы: `src/movement/pathfinding.rs` ·
`src/movement/components.rs` · `src/movement/tests.rs` · `src/diagnostics.rs` ·
`examples/bench/dispatch_bench.rs` · `src/dev.rs` · `src/main.rs` · `Cargo.toml`.
Коммиты: NOAPPNAP (07f3d23f), фиксы конвейера (1ec625ae).

**Кандидаты.** Записи 9 и 15 оставили на состояние «30× / шторм входа»: цикл спавна
тасков (0.4–1.3 мс/кадр при 712–1024 диспатчах), сорт кандидатов (~160 мкс при
переполнении) и волна переносов архетипов на пути заявки — выдача
`remove(Request)`+`insert(Task)`, приёмка `remove(Task)` — три переноса на поиск.

**Диагноз.** Живой Париж, 30×, шторм входа (свежий процесс, зум 0.4, ~17k в очереди):
**стационар конвейера тихий** — 2–17 диспатчей/кадр (диспетчер берёт только то, что
стоит в кадре; очередь вне кадра ждёт камеру по дизайну), пул не насыщен
(`sim/wait_ms` 0.0008), сорт не зажигается вовсе (кандидаты < бюджета 1024), тик
0.27–0.38 мс, тик-спайки единичны (все — флеш спавна 20k на входе в мир, `rest`
≈ весь спайк). Кандидаты записи 9 не горят и здесь — третий подтверждённый прогон
(после 1× из записи 15). Их состояние — **вспышка входа**: warmup/панорама камеры в
плотный район, где в кадре разом оказывается ≥ бюджета заявок. Разрез фаз
`dispatch_bench` (методика записи 9, насыщенный пул, 20k очереди): сам проход
диспетчера p50 0.99–1.13 мс, а **применение команд — 4.4–4.7 мс** на burst-кадр —
большая половина цены вспышки сидит в переносах архетипов, не в проходе. Замер
флеша добавлен в бенч колонкой `flush` (у пешек бенча архетип из 2–3 компонент —
у игровых пешек копировать при переносе в разы больше, абсолют ниже игрового,
сравнимы фазы).

**Фикс — выдача без снятия заявки.** Диспетчер ставит `PathfindingTask` **поверх
живой заявки** (один перенос вместо двух); приёмка снимает пару
`(PathfindingTask, PathfindingRequest)` одним пакетом (одна команда — один перенос).
Три переноса на поиск стали двумя. До приёмки выданные отфильтровываются
проверкой таска; «queued» в диагностике — заявка **без** таска; сетка очереди
держит запись до приёмки (её observers полноты событий не менялись — снятие
заявки теперь приходит с приёмки). Детерминированный диспетчер не тронут:
своя пара заявка/таск, там цену держит ожидание пула, а не команда.

**Фикс — top-k на переполнении.** Полный сорт очереди кандидатов заменён на
`select_nth_unstable_by` + `truncate(budget)`: дальше бюджета всё равно
обрезается, а ничья на (приоритет, дистанция) и раньше не была определена
(сорт был unstable).

**Батч-спавн тасков — заблокирован апстримом.** Одна разблокировка пула на пачку
недостижима через публичный API: `async-executor` 1.14 умеет `spawn_many` (один
лок на пачку), но `bevy_tasks::TaskPool` его не пробрасывает — только
поштучный `spawn`. Без апстримной правки bevy_tasks этот кандидат не берётся.

**QWE_PERF_NOAPPNAP=1** — активность `NSProcessInfo` класса `userInitiated`
(`src/dev.rs::no_app_nap`, objc2-foundation 0.3 — та же версия, что у winit,
отдельного дубликата не заводит; токен утекает до конца процесса). Запись 15:
App Nap плавает между прогонами (fps 113 ↔ 46, `ps -M` класс `…T`) и портит
сравнения. Заезд: **ни одного T-потока во всех прогонах** с флагом; warmup 2.92 с
против 10.1–16.1 с у апп-напнутых прогонов записи 15 — состояния машины
сравнялись, сравнение прогон с прогоном стало возможным. Без переменной ничего
не меняется.

**Метод.**

- Разрез фаз диспетчера — `cargo run --example dispatch_bench -- 20000 200 60`;
  A/B честный: `git stash push -- src/movement/pathfinding.rs` держит старый
  диспетчер при новом бенче (счётчик dispatched в бенче считает
  «заявка без таска» — семантика одинакова у обеих версий).
- Живые окна — по дельте `frame_count` за 15 с (`/tmp/qwe05/windows.py` жив);
  спайки — `tick spike`/`frame spike` при `QWE_PERF_FRAME_SPIKES=30`.
- Шторм входа — свежий процесс; перезапуск мира (R) не проходит через
  loader-warmup, строка `warmup:` бывает только на входе в город/приложение.
