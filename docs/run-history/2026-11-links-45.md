  лимитер кадра на городском зуме; wander-диспетчер уже камерный, сепарация

  люди — камерный LOD (Live-only, реплей — полный AI); цель 15–30×; трупы
  вечные, но запекаются чанками (форма предложена владельцем: свежие спрайтами
  → фон-пекарь дописывает квады в меш чанка сетки и деспавнит тройку);

  принято владельцем осознанно); запечённые трупы — «точечный материал» с
  полом HUMAN_MIN_PX (общий с дальним слоем); единый порог городского зума

## Замеры (live-app; детали — в «Известные измерения», блок «Фаза ×10 — 200k»)

Критерий готовности Ф1: 200k расселяется без рамки длиннее ~50 мс ✓ (бут-разгон,
порог детектора 50 — ни одной строки); прогрев сходится ✓ (Париж 3.95 с / Тула
2.74 с при таймауте 10); инвариант переписи зелёный на разгоне и после ✓ (ровно
200 000 на обоих городах, живьём и после рестарта); реплей-пины зелёные ✓ (1598
lib-тестов + набор tests/determinism.rs). Память живых 200k (открытый вопрос
плана): footprint 2.8G / пик 4.9–5.4G — база 2.2–2.3G, то есть ~+0.6G за население;
профиль/аллокатор не трогать. Тик 200k = 1.50–1.56 мс против 0.53 на 20k тем же
бинарем — affordable ≈ 3×: это «точка до» Ф2. Очередь ~198k заявок после Live —
штатно до Ф2, диспетчер не трогать (указание ревьюера ×10-плана).
