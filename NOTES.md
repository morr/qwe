## Уроки живых замеров

**worktree звена удалять только после того, как cwd сессии переведён из него
успешным `cd` в отдельном вызове** (№46): цепочка «cd главный && worktree
remove» падает на середине (remove отказал на нечистом worktree) — cd не
закрепился, сессия осталась стоять cwd в worktree, который следующим вызовом
удалили — и bash сессии умер до конца звена (`spawn /bin/zsh ENOENT` на любом
вызове). Спасение — воссоздать путь Write-тулом (он создаёт родительские
каталоги), затем успешный `cd` и чистка. Порядок работы: `cd` отдельным
вызовом → правки/замеры → удаление worktree последним вызовом, когда cwd уже
в главном чекауте.

**Фаза ×10 — 200k (№46, отсюда брать «до» для Ф2–Ф7):** расселение 200k партиями
по 2k — рамок ≥50 мс в разгоне нет вовсе (порог спайк-детектора; замер по партиям:
10k → рамки 100–130 мс, 4k → 50–64, 2k → чисто; почти вся цена рамки масштабируется

выжигается); перепись `alive+killed+escaped == 200000` точно на разгоне и после;

города на 200k — рамка 196–335 мс (база ~30 мс на 20k, линейно); entities
203–219k; **тик 200k = 1.50–1.56 мс (Тула, зум 0.4 и 0.05) против 0.53 мс на 20k
тем же бинарем** — affordable ≈ 3× при цели 15–30×; **память живых 200k:

B выглядела одной строкой из шести);
**RSS-сэмплирование — пауза сразу после warmup и фикс-стабилизация 5–6 c**:
первые секунды после Live догружают меши в GPU (+1.3–1.6G за секунды), без
паузы и стабилизации кривая шумит на ±1.4G (№23: «низкие» первые загрузки
оказались недосэмплированными, не эффектом зонда); реальная цена города —
dirty-footprint `vmmap --summary`, разрыв ps-RSS↔footprint — MADV_FREE'd
свободные страницы; `heap -addresses all` печатает строки `addr: тип (N
bytes)`, у Rust-аллокаций тип `non-object` — гистограммы только по размерам;
**статусы двух чекаутов — порознь**: склеенный вывод двух `git status` в одном
вызове читается как один (№23: Edit по пути главного чекаута прочитан как
worktree-правка, врезка в бинарь не попала — укус №5/№14 с изгибом);
**`res set City` тем же городом триггерит перезагрузку** (`retuned` = is_changed &&
!is_added) — серию загрузок одного города можно гнать без переключений на другой
город; **дрейф машины между сессиями больше разброса внутри сессии** — A/B сравнивай
только чередованием внутри одной сессии; временные таймерные врезки снимай ДО
коммита, и помни: повторные Edit с одним анкором дублируют блок (grep 'TEMP' перед
коммитом).

**счёт загрузок в пробе веди от строк лога после старта запуска** (№30): свой же
`res set City` — в том числе тем же городом — даёт загрузку, неотличимую в счёте
от «второй загрузки»; стартовый город после любого выхода приложения — город
последней загрузки, не тот, что в стандартном settings.toml, так что проба
«стартует Парижем, потом переключаю» может стартовать уже целевым городом и
сама съесть свой яд до всякого переключения; проверки файлов после `cd` в
worktree — только по абсолютным путям (греппы по относительному NOTES.md
читают копию ворктриа, №30).

**сэмплер CPU — pid фиксировать до серии, не резолвить в цикле** (№36):
`lsof -ti tcp:15703` каждые 0.5 с (сканирует все процессы) уронил живое
приложение в 3–7-секундные разрывы между кадрами на ВСЁ время серии; после
pkill сэмплера разрывы исчезли мгновенно. Порядок: `$b alive` → pid → цикл
только на `ps -o time=` + `ps -M` (как в первой серии звена — безопасно).

**бенч map_meshing между сессиями плавает сильнее живых окон** (№36):
fences 1752–2159 и road 1.52–1.96 против баз №35 (1083 / 1.09) при чистых
канарейках живого приложения того же кода; caffeinate бенчу не помогает —
сравнивать пары внутри сессии, между сессиями — только относительную
структуру слоёв.

**здоровье машины при живых замерах проверять ДО серии** (№31): `res get
SimSpeed` на Париже Astar несёт affordable 20+; обвал affordable (№31: 0.56 при
requested 1.0) — машина под внешней нагрузкой (в ps — ZCode GPU-процесс 43.7 %
+ opendirectoryd 36 %), рамочные замеры после такого момента — мусор (спайки
100–400 мс на паузе, кадр 4.1 с); доверять можно только учётке по таймстемпам
строк лога; ранние замеры той же сессии, сошедшиеся с известными базами
записей 61–63, остаются валидными. Деградация приходит волнами, привязанными
к активности собственной сессии (ZCode Helper 51 %; №33: из четырёх запусков
два деградировали ×25–100 разом при живом NOAPPNAP+caffeinate, два — чистые);
канарейки-шаги загрузки (снапшот-рид ~92 мс, fill ~137 мс) различают
мгновенно; **loadavg не показателен** — на 14-дневном аптайме читал 150–160
при 5 бегущих процессах и 85 % idle (№33); **деградация бывает внешней и
именованной: XProtectRemediatorPirrit (периодический скан macOS) жрал 72–93 %
CPU ~15 минут и вздул все шаги загрузки ×3–4** (№34, прогон выброшен
целиком) — перед серией и между прогонами проверять ps на не-своих
пожирателях и ждать их конца; бинарь напрямую не запускать
(«no LC_RPATH's found» — только через cargo run), якорь спавна — pgrep-поллер
с gdate (у BSD date нет %N).

**первый запуск свежего ворктриа — прогон целиком испорчен** (№35): холодный
кеш снапшота (рид 165 мс против 92) + сборка бинаря перед стартом + сидинг
настроек — выкидывать прогон, второй запуск ворктриа уже чистый; вид
владельца (Париж@0.4, Astar) ставится одним прогоном — старт Тулой →
`res set City . '"Paris"'` → ждать новую warmup-строку → quit
(`START_ZOOM` = 0.4, так что переключение города само даёт вид владельца).

**`res set` — всегда три аргумента: ресурс, путь, значение** (№42): дву-
аргументная запись `res set City '"Paris"'` скрипт молча отвергает
(«needs <Resource> <.path> <json-value>»), свит без ожидаемой warmup-строки
досиживает свой таймаут — потерянный прогон заметен только по числу
реальных переключений; скриптовые однострочники из старых секций Notes
с двуаргументной формой не копировать. Скриншот живьём — `shot` без
аргумента, файл переносить руками: приложение пишет в свой cwd
(`screenshot.png` + `.small.png`), кастомный путь скрипт ждёт зря
(30 с на попытку). Свит больше 4–5 городов — фоном сразу: цикл из
12 городов не влезает в foreground-таймаут 10 минут (№42).

**перед пробой перф-темы читать ЕЁ запись журнала, не только README-хвост** (№37,
дорогое переоткрытие): README до записи 67 — указатель, а вердикты по темам
лежат в самих записях; угол «предфильтр клипа находки лоскутов» был закрыт
записью 34 дословно («предфильтр обязан соглашаться со свипом i_overlay о
каждом волоске»), звено №37 потратило пол-звена на её переоткрытие с тем же
вердиктом. Порядок: grep по `docs/perf-journal/*.md` имени фазы/модуля —
потом врезка.

**soak на живой агентской машине contaminated по определению** (№40):
каждый сэмпл/вызов модели = 1–3 мин CPU собственной сессии = волна голода;
осмысленны инварианты/консервация/восстановление, НЕ абсолютные скорости и
спайки. Честный горизонт сим-времени — дельта SimClock между сэмплами, не
SimSpeed.actual. vmmap — только `grep 'Physical footprint'`; стоимость тика
— `res get SimLoad` (`texts tick` матчит не ту строку).

**смена `[profile.dev] opt-level` не инвалидирует cargo-кеш сама по себе**
(№41): `cargo run` после правки Cargo.toml отвечает «Finished in 0.59s» и
запускает старый бинарь; touch-пересборка (5–9 с инкрементально) может
поднять CGU из инкрементального кеша чужого профиля — числа такой серии
неподтверждаемы; гарантированная смена профиля — `cargo clean -p qwe`

запуска; сидинговая пересборка ворктриа (1m33s) тоже может уйти не с тем
профилем — серию с канарейками вне базы выкидывать и пересобирать чисто.

## Угол и что снято

Карта поверхности: события — `WorldStarted` (loading.rs:91; триггеры —
`announce_world_start` на входе в `Live` и `on_restart`; контракт «объявление до
первого тика» пинится тестом; слушатели — десять модулей, grep `On<WorldStarted>`
перечислен в доке у типа), `RestartEvent` (BRP; `run_if(Playing)` — комментарий у
регистрации объясняет, почему гейт обязан стоять на самом обсервере), три dev-события
BRP (скриншот/внеэкранный кадр/проба слоёв — безопасны в любом состоянии: скриншот
везде снимает окно, проба с пустым `InspectIndex` отвечает пустым отчётом),
`DemonCaughtHumanEvent` (тик погони → обсервер на синк-поинте цепи; цена убийства —
номер решения, пин `a_kill_spends_the_demons_next_decision_number`), `Scroll`
(EntityEvent с propagate — дельта гасится на первом уровне, который её потратил) и
`MovableReachedDestinationEvent` (EntityEvent; триггер — `Movable::to_idle` с
debug_assert-ом «живой путь = приход теряется»). Сущность-скриншот деспавнит сам
движок после снятия (bevy_render screenshot.rs:311) — накопления нет. Обсерверы
lifecycle: сетки `spatial` (Add/Remove покрывают смерть, побег, рестарт и смену
города одной парой), индексы заявок pathfinding/claims, инициализация `SimPosition`
по `Add<Movable>`, `FarTag`/`Silhouette` вставки, тинт паники. Писатели — все в
фиксед/апдейте с командами; массовых деспаунов из обсерверов нет (рестарт —
`PreUpdate`, урок оформлен комментарием в restart.rs).
