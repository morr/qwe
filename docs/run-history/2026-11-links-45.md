## Как шло

- Сурвей масштаба по скиллам и NOTES: тик Парижа 0.21 мс/20k (affordable 22×),
  бюджет 15/30× ⇒ tick ≤ 0.31/0.155 мс на 200k (0.75–1.5 нс/пешку); спрайты —
  лимитер кадра на городском зуме; wander-диспетчер уже камерный, сепарация
  экранная и off при зуме; трупы вечные; спавн 482 мс/20k одной рамкой.
- Восемь решений владельца (консультации в сессии): демоны «фон + орды»;
  люди — камерный LOD (Live-only, реплей — полный AI); цель 15–30×; трупы
  вечные, но запекаются чанками (форма предложена владельцем: свежие спрайтами
  → фон-пекарь дописывает квады в меш чанка сетки и деспавнит тройку);
  HUMAN_COUNT — новый дефолт 200 000; кап демонов — общий потолок живых
  (волна = min(wave_size, свободное место), вырождение ритма при полном капе
  принято владельцем осознанно); запечённые трупы — «точечный материал» с
  полом HUMAN_MIN_PX (общий с дальним слоем); единый порог городского зума
  0.75 для яруса/слоя/сепарации/wander-диспетчера.
- План писала спавненная fable-сессия (GLM-5.3, thought max; sess_966ffafb-…)
  по моему брифу с сурвеем; в ходе работы ей ушёл steer по трупам. План
  отревьюен против замеров и апстрима 0.20.1; планировщик поправил два
  утверждения брифа по коду (атлас не SDF — цвет вершины идёт через
  ColorMaterial/ATTRIBUTE_COLOR-путь; трупы и сегодня лежат на плоской
  Z_CORPSE 3.0 — «потеря y-сортировки» при запекании фиктивна). Дубль доставки
  steer-а прервал планировщика посреди записи — восстановлен ping-ом,
