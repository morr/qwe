# Запланировано 05 — подвисание при пересечении порога зум-LOD (Париж)

Приоритет: **1** (чувствуется в игре на каждом щелчке колеса).

## Проблема

В Париже пересечение порога зум-LOD (шаг деревьев, машины, трамвай,
roof clutter, дороги/рельсы) на каждое переключение даёт сильный кадровый
подвис. Отчёт автора, 2026-11-09: «когда во время зума происходит
переключение между уровнями LOD, игра очень сильно подвисает».

Механизм подозреваемых известен по коду и записям: пороговые слои, которые
**пересобираются** на пересечении (припаркованные машины, трамвай,
ближний шаг крон — запись 13 сделала его 0.2 м/px, на Париже это много
геометрии), плюс перевороты видимости у «держащих все шаги» слоёв. На
большом городе пересборка одного шага — десятки-сотни мс в кадре.
Детектор `QWE_PERF_FRAME_SPIKES` уже привязывает спайк к порогу, через
который прошло колесо в том же кадре (`frame spike: … (zoom …)`), — это
инструмент атрибуции, им и мерить.

## Направление решения (идея автора)

Переключение уровня — **не в основном потоке**: старый LOD остаётся на
экране, пока новый уровень не прогрузится; потом атомарная подмена.
Прецедент в репо — запись 12 (мешинг в поток загрузки) и `CrownStream`
(потоковая выдача крон).

## Шаги

1. Атрибутировать: какой слой доминирует на пересечении (по одному
   `frame spike` с зумом → `zoom::show_lod_layers`, `rebuild_cars`,
   `rebuild_tram`, ближний шаг крон; замерить каждый `Instant::now()` в
   отладочном прогоне).
2. По доминанте: перенести сборку мешей уровня в поток (rayon/bevy_tasks),
   выдать готовый меш в основной поток на подмену.
3. Слои-перевороты видимости (дороги, рельсы) не трогать — они дешёвые.
4. Инвариант живой правки: старый слой снимается только после появления
   нового; никакого кадра без LOD-слоя.

## Верификация

- Замер кадра при прокрутке зума через каждый порог до/после
  (`QWE_PERF_FRAME_SPIKES=30`, окна по `frame_count`).
- Скриншоты обоих шагов у порога — картинка не деградировала (переключение
  незаметно, кроме доли секунды старого LOD).
