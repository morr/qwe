# Запись 21 — шторм warmup: очередь не стена; первый выход без переспроса, пересборка inspect-индекса одна

Статус: разрез + два фикса заезда 11 (`planned/09-warmup-storm.md`). Файлы:
`src/human/systems.rs` · `src/navigation/backend.rs` · `src/navigation/mod.rs` ·
`src/map/inspect.rs`. Замеры: живой Париж, три базовых и три правочных прогона
(снапшот-хиты, одно состояние машины под `caffeinate -i`,
`QWE_PERF_NOAPPNAP=1`/`NOVSYNC`/`FRAME_SPIKES=30`); разрез — временные `info!`-фазы
в подаче, слотах, диспетчере, приёмке и `poll_warmup` (сняты до коммита).

**Было.** Warmup-холд на входе в мир (все 20k пешек подают заявки одним кадром)
плавал между прогонами и записями: 4.3–4.4 с (запись 14), 2.92 (16), 3.4 (18),
1.65–2.0 (20). Кандидаты заезда: разнести подачу по кадрам, приогреть диспетчер,
урезать множество входных заявок — решение по разрезу «спавн заявок / ожидание
диспетчера / прокладки».

**Разрез — три находки, все мимо кандидатов:**

1. **Очередь — не стена.** Первый кадр подачи стоит 4 мс на 14 189 заявок (слоты
   3.6 мс на 14 189 свежих, сетка очереди — обсерверы). Диспетчер выдаёт только
   пешек в кадре камеры: 176 на первом кадре, дальше хвост 43 → 20 → 9 → …;
   полианья отвечает 0.14–0.25 мс/путь, приёмка догоняет кадром позже, бюджет
   1024 не выбирается и вполовину — в кадре камеры на входе всего ~130–240 пешек.
   Ожидание диспетчера и сами прокладки — доли кадра.
2. **Подача размазана trickle'ом переспросов.** ~30% первых выходов
   (`HumanFirstWanderTag`) промахиваются целью в квартал: кольцо просеивания цели
   радиуса 1 (8 соседей тайла, `sift_target`) целиком стоит на доме — `None`,
   заявка уезжает на следующий кадр, пешка переспрашивает с новым броском. Хвост
   14 189 → 2 613 → 1 092 → 577 → … ~15 кадров; холд кончается на первом кадре с
   `waiting == 0`, то есть когда trickle заявок в кадре случайно паузнёт, —
   отсюда плавание 1.65–2.05 в одном состоянии машины.
3. **Стена окна — входные кадры, и в них main-поток платил за пересборку
   inspect-индекса трижды** (0.24–0.27 с каждая). Приборка триггеров показала:
   вторая и третья прошли при `is_changed() == false` у всех трёх ресурсов —
   `resource_changed` в run-condition видит записи параллельных систем кадра
   через своё окно change-detection раньше системы-исполнителя и зажигается
   вхолостую.

**Методическая находка — строка warmup меряет не main-поток.** С pipelined
рендером `Time<Real>` обновляется из канала render-мира
(`bevy_time::time_system`: инстанс приезжает по каналу bounded(2), при пустом —
`Instant::now`), поэтому «warmup: routed in X s» и `frame spike` отражают ритм
**рендера** — в окне сидит заливка мира (render-кадр спайком 1634–1657 мс,
диагностика fps 0.6). Wall окна (Playing → `warmup:` по таймстампам лога)
короче строки: 1.03–1.38 с у базы. Wall-замеры в этой записи — по таймстампам.

**Фикс — подача первого выхода без переспроса (живой режим).** Промах узкого
кольца на первом выходе досеивается широким — `Walkable::sift_target_far`
(радиус 4 тайла, тот же кольцевой поиск `nearest_passable_tile`, читатель
один). Заявка встаёт тем же кадром; бросков потока решений просеивание не
делает (геометрия), выбор цели не меняется — только её попадание в этот кадр.
Реплей не задет: детерминированная ветка подачи (свой `pick_wander_targets` в
`FixedUpdate`) гейтится `Determinism` и ведёт заявки по тикам как раньше.
Первый кадр подачи: 14 189 → **17 741** заявок, переспрос 29% → 11%.

**Фикс — пересборка inspect-индекса одна.** `resource_changed`-условие заменено
системной проверкой: система идёт каждый `Update` (гейт —
`resource_exists::<MapData>`) и перестраивает, только если сама видит смену
хоть одного из трёх входов (`MapData` / `RoadShapeOnMap` / `DrawnPieces`). На
входе в мир — ровно одна пересборка вместо двух-трёх; легитимные поводы
(оседание формы дорог, стиль деревьев, пересборка дорог) не задеты.

**Замеры** (Париж, снапшот-хиты, одно состояние машины; строка = значение
`warmup:`, wall = таймстампы `transition: Some(Loading)` → `warmup:`):

| | до (3 прогона) | после (3 прогона) |
|---|---|---|
| warmup, строка — свежий процесс | 2.05 с | **1.67 с** |
| warmup, строка — перезагрузка города | 1.67 / 1.65 с | 1.67 / 1.62 с |
| wall окна — свежий процесс | 1.38 с | **1.04 с** |
| wall окна — перезагрузка | 1.04 / 1.03 с | 1.03 / 1.01 с |
| пересборок inspect-индекса на вход | 2–3 × ~0.25 с | **1 × ~0.25 с** |

Свежий процесс по строке догнал перезагрузку (2.05 → 1.67, −19%): хвост
переспросов больше не растягивает холд. Перезагрузки по wall не сдвинулись —
фантомные пересборки и так сидели в тени рендер-заливки (исполнитель
параллелен тяжёлым кадрам): работа main-потока убрана, стену это не меняло.
Строковая метрика теперь упирается в рендер-сторону — заливку мира в render-мире
(~1.6 с render-clock спайком); после неё wall окна ~1.0 с держат спавн-флеш 20k
и первый extract. Контроли: `osm map:` бит-в-бит, `scene entities survived` — 0,
`panicked` — 0; карта целая (оффскрин центра Парижа, портал на месте); ярды и
`a_restart_replays_the_run` зелёные (`tools/check.sh`).

**Метод.**

- Прогон и состояния машины — как в записях 18/20; город перезагружался
  `brp res set City . '"Paris"'`.
- Разрез — временные `info!` в пяти системах, гейт `PlayPhase::Warmup` (чтобы
  после `Live` лог не засорялся), сняты до коммита.
- **Wall-замеры только по таймстампам лога** — `Time<Real>`-дельты
  (`warmup:`-строка, `frame spike`, диагностика fps) на входе в мир меряют
  рендер, не main-поток (см. выше); сравнивать их с wall нельзя.
- Порог видимости: `brp shot-at` с зумом крупнее 0.12 пешек уже не показывает —
  для проверки «пешки в кадре с путями» кадр брать крупнее (зум меньше).
