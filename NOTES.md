## Уроки живых замеров

**worktree звена удалять только после того, как cwd сессии переведён из него
успешным `cd` в отдельном вызове** (№46): цепочка «cd главный && worktree
remove» падает на середине (remove отказал на нечистом worktree) — cd не
закрепился, сессия осталась стоять cwd в worktree, который следующим вызовом
удалили — и bash сессии умер до конца звена (`spawn /bin/zsh ENOENT` на любом
вызове). Спасение — воссоздать путь Write-тулом (он создаёт родительские
каталоги), затем успешный `cd` и чистка. Порядок работы: `cd` отдельным
вызовом → правки/замеры → удаление worktree последним вызовом, когда cwd уже
в главном чекауте.

**Фаза ×10 — 200k (№46, отсюда брать «до» для Ф2–Ф7):** расселение 200k партиями
по 2k — рамок ≥50 мс в разгоне нет вовсе (порог спайк-детектора; замер по партиям:
10k → рамки 100–130 мс, 4k → 50–64, 2k → чисто; почти вся цена рамки масштабируется
от партии, ~7–8 мкс/пешку: выбор цели свежей партии, проводка трансформов, загрузка
спрайтов в GPU); прогрев сходится: Париж 3.95 с / Тула 2.74 с (таймаут 10 с не
выжигается); перепись `alive+killed+escaped == 200000` точно на разгоне и после;
вход мира без флеша населения: Париж 549 мс (база 660 — с флешем 20k); деспаун
города на 200k — рамка 196–335 мс (база ~30 мс на 20k, линейно); entities
203–219k; **тик 200k = 1.50–1.56 мс (Тула, зум 0.4 и 0.05) против 0.53 мс на 20k
тем же бинарем** — affordable ≈ 3× при цели 15–30×; **память живых 200k:
footprint 2.8G / пик 4.9–5.4G на обоих городах** (база 20k: 2.2–2.3G) — ~+0.6G
за население, открытый вопрос плана закрыт: профиль/аллокатор не трогать;

в Ф2+. A/B населения: `QWE_PERF_POP=<n>` в строке запуска, пересборки не требует;
криты тиков 20k↔200k сравнивать при одном городе и одном зуме (сепарация на

**отчёт слоя печатает Duration Debug-ом: под секундой — `966.271583ms`, над —
`1.072s`**, грепай `in [0-9.]+m?s`, а не `in [0-9.]+s` (№21: первая серия стороны

dirty-footprint `vmmap --summary`, разрыв ps-RSS↔footprint — MADV_FREE'd
свободные страницы; `heap -addresses all` печатает строки `addr: тип (N

**статусы двух чекаутов — порознь**: склеенный вывод двух `git status` в одном
вызове читается как один (№23: Edit по пути главного чекаута прочитан как

!is_added) — серию загрузок одного города можно гнать без переключений на другой
город; **дрейф машины между сессиями больше разброса внутри сессии** — A/B сравнивай

**счёт загрузок в пробе веди от строк лога после старта запуска** (№30): свой же

читают копию ворктриа, №30).

**смена `[profile.dev] opt-level` не инвалидирует cargo-кеш сама по себе**

**хук `guard-bash` режет чтение `sed -n` по путям с `.md`/`.rs`** (№69,
дважды): ложное срабатывание правила «не писать исходники из Bash» на честном

честный `awk '… $0 …' файл.md` — присваивание в скрипте хук читает как запись.

**`brp run` шагает минимум 1 с сим-времени** (№69): для долесекундного шага —
`brp speed 0.1`, затем `resume; sleep 1.5; pause` со сверкой `SimTick` до и

**`brp insert` принимает только полные зарегистрированные пути** (№69):
`{"qwe::movement::components::SimPosition":[x,y],…}`; короткое имя даёт

зарегистрирован — фильтром `--with` его не отфильтровать, срез ставь по имени.

**перед запуском `brp procs` смотри, кто держит порты** (№69): у владельца
экземпляр приложения держит 15702 и 15703 (последний — порт `.claude/live-app.json`)

**`Vec::with_capacity` не падает на больших числах** (№69): на этой машине
`1e12` успешен (ленивая память macOS, проверено отдельной программой), «capacity

висон под блокировкой и смерть по памяти. Вердикт «здесь упадёт» — только после
пробы.

**BRP-запись `u64` больше `i64::MAX` в поле `usize` любой группы настроек
роняла приложение при сохранении** (№69; закрыто №70 — `prefs::SavePrefs`
подрезает до `i64::MAX` с одной warn-строкой, живьём подтверждено): bevy-settings
сериализует в TOML через `unwrap()`, целое в TOML знаковое. Такая запись больше
не роняет, но `WorldSeed` по BRP по-прежнему не писать — рестарт мира.

**Обход групп настроек с правкой метит группу изменённой первым же `&mut`**
(№70): `ReflectComponent::reflect_mut` отдаёт `Mut`; сам вызов группу не метит,
а первый `DerefMut` — метит, и по метке переписывается файл и пересобираются
кроны, дороги и здания. Править без метки — через
`current.bypass_change_detection().as_partial_reflect_mut()`, а `set_changed()`
ставить вручную только там, где вправду поменял. Сверку с дефолтом (как у
`ResetSettings`) делать до взятия `Mut`.

**Отметка изменения видна только тиком строго новее опорного** (№70):
`Tick::is_newer_than` не видит правку, поставленную тем же тиком, что и
опорный `since`. В тесте граница `app.world_mut().increment_change_tick()` стоит
**между** опорным тиком и действием; граница, поставленная после действия, даёт
пустой список. Негативный пин («никто не отмечен») без контроля пуст по
определению: в его конец ставится отметка обходчиком теста, и та же проверка
обязана её увидеть.

**Юнит-двор с `SettingsPlugin` не пишет файл без границы тика** (№70): плагин
помнит тик своей сборки как последнюю запись, кадров во дворе нет — после
`add_plugins(SettingsPlugin::new(..))` нужен
`app.world_mut().increment_change_tick()`, иначе `IfChanged` молчит и проба
ложно зелёная (до фикса зондом снята паника библиотеки, после — файл).

**Замыкание, возвращающее `&mut` из захваченного состояния, не пишется как
`impl FnMut(usize) -> Option<&mut dyn PartialReflect>`** (№70): E0106, затем
E0582; рабочая форма — контейнер аргументом: `P: ?Sized` и
`impl FnMut(&mut P, usize) -> Option<&mut dyn PartialReflect>`. Рядом:
имена полей читаются до мутабельного заёма поля (`name_at(i)` при живом
`field_at_mut` — E0502); `ReflectMut::Function` есть только с фичей `functions`;
`World::change_tick()` берёт `&mut self` и отдаёт `Mut<Tick>`, держа заём мира,
— опорный тик читается через `World::read_change_tick()`; `Tick` живёт в
`bevy::ecs::change_detection`, не в `ecs::component`.

**`cargo test prefs` не запускает `tests/prefs.rs`** (№70): фильтр матчит имена
тестов, а не файлы — «running 0 tests … 4 filtered out» с exit 0.
Интеграционный файл гоняется явно, `cargo test --test prefs`, и в выводе
читаются строки `running` и `test result`: exit 0 сам по себе не доказывает,
что тесты шли.

**`TempDir::new` строит путь из pid и тега** (№70): два параллельных теста с
одним тегом делят каталог, падение одного удаляет файл соседа («файл не найден»
в зелёном по значениям тесте) — каждому двору свой тег.

**Сидирование настроек ворктри сохраняет mtime файла владельца** (№70):
после старта `.settings/settings.toml` носит время OS-файла — старый mtime не
значит, что приложение не пишет. «Пишет ли в покое» проверяется по mtime после
первой записи, не после старта.

**Пекарь трупов читает глобальный трансформ в кадр смерти** (№71):
`bake_queued_corpses` (`Update`) на городском зуме берёт тело тем же кадром —
`spread_blood` ставит его в очередь первым кадром, а пересчёт
`GlobalTransform` из `Transform` живёт в `PostUpdate`. Писатель `Transform`
трупа обязан писать и глобальный (`lay_down` с №71 пишет оба). Юнит-двор без
`TransformPlugin` propagation не имеет вовсе: тест пекаря с *согласованной*
парой трансформов дефект не увидит — пин ставит пару *устаревшую*.

**Клетка 500 м маскирует смещение в живой пробе** (№71): сверка «клетки
трупов против клеток демонов» не отличила сдвиг в сотни метров — клетка
`CorpseField` 500 м, жертвы молодого мира гибнут в сотнях метров от спавна и
попадают в те же клетки. Различил только TEMP-зонд в пекаре с расстоянием по
каждому трупу (всего / дальше 1 м / дальше 100 м / дальше 300 м / максимум):
до фикса 97.7 % / 61 % / 7 %, максимум 723.5 м; после — нули на 19 300 трупах.

**Сетка людей сажает по `Transform` при добавлении** (№71):
`spatial.rs::on_human_added` читает `Transform`, а не `SimPosition`; дальше
её ведут писатели `SimPosition` через `SpatialGrid::moved`. Перенос пешки по
BRP одной записью `SimPosition` сетку не двигает — пешка остаётся в старой
клетке, пока сама не перейдёт границу. Живая проба с переносом сущности
по этой причине отвергнута.
