## Уроки живых замеров

**`QWE_PERF_NOAPPNAP=1` обязателен в строке запуска** (№19: без него процесс
деградировал в App Nap посреди серии — все потоки T в ps -M, загрузки в 2.4–2.7×
медленнее с третьей-четвёртой; диагностика — резкий скачок ВСЕХ шагов загрузки между
соседними загрузками; четыре замера выброшены); **`pwd &&` — в самой команде запуска
приложения** (№19: cd ворктриа в фоновом build-задании не персистентен — «сторона A»
снята с чужого бинарника; числа переклеены, но урок дорогой); `$b ready <log>` после
первой загрузки всегда «готов» — для серий переключений ждать НОВУЮ строку warmup
(grep-счёт до/после), иначе `res set City` гейтится в Loading и переключение теряется
молча; **.settings перезаписывается на выходе приложения — город последней загрузки
становится стартовым, первая строка «navmesh filled in» серии бывает Парижем, а не
Тула-выбросом** (№19); после тёплой сборки ready может вернуть «готов» мгновенно, а
первая загрузка — уехать до вызова: окно по таймстемпам считай только между
строками, которые точно после старта запуска; никаких параллельных компиляций при
живых замерах (check.sh рядом замедлял загрузки 10×); `algorithm=Hpa` в сохранённых
настройках запускает сборку northstar (22–28 с) после каждого входа в Live — для серий
переключений ставить `res set PathfindingAlgorithm . '"Astar"'` сразу после первого
ready (для одиночных стартовых загрузок не нужно); после warmup/pause `res get
SimSpeed` читается в переходном состоянии — бери steady-state из строки `brp run`
(actual Nx) и счётчик `frame spike`; pgrep по полному пути ворктриа не находит процесс
(argv[0] относительный), pid брать у `$b alive`; check.sh не принимает Cargo.toml и
.md (rustfmt падает E0758); окно snapshot→warmup шумнее отдельного шага: −111 мс шага
дали −0.07 с окна, −29 мс шага не видны вовсе — меряй целевой шаг по его строке
лога, окно — как вторичный признак; вид владельца (Париж, zoom 0.4, Astar)
настраивается одним прогоном базы: системный settings.toml перезаписывается на
выходе, worktree при первом запуске сеется из него
(`prefs.rs::seed_worktree_settings`) — у сторон A/B файлы идентичны без ручной
возни (№21);
**отчёт слоя печатает Duration Debug-ом: под секундой — `966.271583ms`, над —
`1.072s`**, грепай `in [0-9.]+m?s`, а не `in [0-9.]+s` (№21: первая серия стороны
B выглядела одной строкой из шести);
**`res set City` тем же городом триггерит перезагрузку** (`retuned` = is_changed &&
!is_added) — серию загрузок одного города можно гнать без переключений на другой
город; **дрейф машины между сессиями больше разброса внутри сессии** — A/B сравнивай
только чередованием внутри одной сессии; временные таймерные врезки снимай ДО
коммита, и помни: повторные Edit с одним анкором дублируют блок (grep 'TEMP' перед
коммитом).

## Главное: пункт (б) не влит, отложен с числами

- **«Малой правки» не существует.** Простой `#[global_allocator]`
  (mimalloc 0.1.52, default-features off) падает SIGABRT под
  `bevy/dynamic_linking` ещё до первого окна: bevy-дайлибы несут свой
  System-аллокатор, атрибут бинаря на них не распространяется, и
  `Box<dyn System>`, созданный в бинаре (`prefs::track_pref`) и
  освобождённый в bevy_ecs-дайлибе, убивает процесс —
  `BUG_IN_CLIENT_OF_LIBMALLOC_POINTER_BEING_FREED_WAS_NOT_ALLOCATED`
  (crash-report в ~/Library/Logs/DiagnosticReports/qwe-2026-11-19-233412.ips).
  Статическая сборка mimalloc не исправит дайлибы (two-level namespace);
  рабочая форма — interposing malloc всего процесса.
- **Interpose работает и стабилен.** Собран shared mimalloc v3 (из
  libmimalloc-sys 0.1.49/c_src; cmake сломан в пакете — JoinPaths.cmake и
  mimalloc-config-version.cmake вырезаны cargo-пакетом, inline-стабы;
  `MI_BUILD_SHARED=ON` даёт секцию `__interpose` — 49 пар, MADV_FREE_REUSABLE
  на macOS — немедленный rss-учёт декоммита, purge_delay 1000 мс):
  `cmake -S /tmp/qwe-mimalloc/src -B /tmp/qwe-mimalloc/build -DMI_BUILD_SHARED=ON -DMI_BUILD_STATIC=OFF -DMI_BUILD_TESTS=OFF -DMI_BUILD_OBJ=OFF -DCMAKE_BUILD_TYPE=Release && cmake --build /tmp/qwe-mimalloc/build`
  Запуск: `DYLD_INSERT_LIBRARIES=/tmp/qwe-mimalloc/build/libmimalloc.SOVERSION.dylib cargo run`.
  Три полные серии (по 7 загрузок) + тиковые шторма — ноль паников.
- **Числа (чистая пара, Astar, чередование, по 3 прогона на сторону).**
  RSS (footprint vmmap / ps rss): вставка платит в покое — S0 Париж
  fp 2.1–2.3G против 1.8–1.9G (ps 3.26–3.28G против 2.64–2.65G), но выход
  на плато немедленный (Париж 2.3G, Тула 1.7G — без роста по серии),
  базовый рост монотонный и сам замедляется (Тула 2.66→3.15→3.48 ps).
  К концу серии итоги сопоставимы. Тик/кадр/джерки: регрессии и выигрыша
  не видно (±5 %): throughput 6.1–6.6x против 5.8–6.5x, спайки 327–440
  против 372–469; загрузки не изменились (Париж тёплый 4.48–4.75 с,
  Тула 1.19–1.27 с). check.sh (build + 1587 тестов + clippy + fmt) под
  атрибутом зелёный. Чистый выигрыш — ≈0–0.4 ГБ за час переключений,
  на короткой сессии — минус. Вердикт: риск/сложность interpose-формы
  неокупаются измеренным выигрышем — разбор и триггер в плане
  («Обзор №15»), патч на ветке `perf15` (worktree `.worktrees/perf15`,
  коммит 1f252f74), worktree `perf15-base` рядом.
- Побочная находка: при `PathfindingAlgorithm=Astar` тёплый вход Парижа
  изредка ловит `warmup timed out with 9 pawns` (дизайн-фоллбек WARMUP_TIMEOUT,
  мир продолжает); дефолт Hpa не затронут.

## Уроки замера (следующим звеньям)

- `$b ready <log>` ищет маркер по всему логу — после первой загрузки он
  всегда «готов» мгновенно. Для серий переключений ждать НОВУЮ строку
  warmup (grep-счёт до/после), иначе `res set City` прилетает в Loading,
  гейтится и переключение теряется молча (серия №2 этого звена прошла
  3–4 загрузки вместо 7 и была невалидна целиком).
- Никакой параллельной компиляции при живых замерах: check.sh, шедуленный
  рядом с серией, замедлял загрузки в 10× (Париж 4.7 → 52 с) и тики.
  Сначала check.sh, потом замеры.
- В сохранённых настройках `algorithm=Hpa`: после каждого входа в Live
  стартует сборка northstar (22–28 с, все ядра) и заражает следующие 2–3
  загрузки серии; для серий переключений — `res set PathfindingAlgorithm . '"Astar"'`
  сразу после первого ready.
- After warmup/pause `res get SimSpeed` читается в переходном состоянии —
  бери steady-state числа из строки `brp run` (actual Nx) и счётчик
  `frame spike`, не пост-паузовые effective/pipeline.
- `pgrep -f '<worktree>/target/debug/qwe'` не находит процесс — argv[0]
  относительный (`target/debug/qwe`); pid брать у `$b alive`.
- check.sh не принимает Cargo.toml и .md — rustfmt падает E0758 (fmt-шаг
  гоняет rustfmt по всем переданным файлам).
