# Запланировано 12 — мешинг-стена тёплого старта: дорожная ступень обочин 0 (Париж)

Приоритет: **1** — после записи 22 стена whole set — дорожная дорожка, ступень 0.
Заезд 14.

## Проблема

Тёплый старт Парижа (снапшот-хит) — 7.18/7.00 с (запись 22). Стену whole set
(`build_world_meshes`) держит дорожная дорожка — **3.7–3.8 с за ближнюю
ступень обочин** (дальняя 2.6–2.8, обе в своих потоках с записи 20). Рядом
заборы 3.1, полимеш 2.6–3.0, здания 2.4–2.5 — после ступени 0 стеной станет
заборы; гейты 1.44 с и полимеш в заезд не входят.

Разрез фаз `build_roads` записи 20 (бенч, ближняя ступень, Париж — 3129 мс)
плоский — ни одной «арки» записи 19; кандидаты заезда, по нему же:

| фаза | мс | кандидат |
|---|---|---|
| станции краски + `kerb_returns` | 531 | **kerb_returns поузлово** — запись 14 отложила («~400 строк самого волосатого кода», приз ~300 мс; тогда не стена) |
| `lay_green_scraps` | 650 | по лоскуту; `find`/`find_green` уже в `in_parallel` — сверлить, где серийное |
| ленты → обочины | 478 | `push_verges`, независимые по улице |
| сплиттеры + устья | 398 | (резерв разреза) |
| краска узлов | 329 | (резерв разреза) |
| `medians::draw` | 269 | (резерв разреза) |

Сумма кандидатов ~1.4 с из 3.7; при 5–6 ядрах реалистичный приз ступени
0.8–1.1 с — тёплый старт ~7.0 → ~6.2–6.4, и стена переходит к заборам (3.1).

## Направление решения

Первый шаг — **разрез ступени 0** (офлайн бенч `map_meshing paris`, временные
`eprintln`, снять до коммита), три сверления:

1. **`kerb_returns`** (`roads/corners/gather.rs`) — две фазы, разделить:
   сбор лучей по дорогам (первый цикл, `HashMap` узлов) и поузловой расчёт
   (второй цикл, `arms.into_values()` — fillet/bend/nose/outer, ~300 мс
   по записи 14). Если поузловая часть доминирует —
2. **kerb_returns поузлово**: `in_parallel` по узлам. Порядок узлов —
   порядок итерации `HashMap` (`into_iter` в `Vec`, не пересортировка);
   частичные накопители сливаются по порядку — выход бит-в-бит с базой.
   Записи `butt`/`setback` в пер-дорожные массивы — по списку `(road, end)`
   в порядке узлов (узел пишет только в торцы своих лучей, конфликтов нет).
   Сбор лучей по дорогам — тем же `in_parallel` по индексам дорог, слияние
   в `HashMap` в порядке дорог (тот же порядок вставок — тот же порядок
   итерации).
3. **Обочины в лентах** (`push_verges`): вход улицы — только чтение
   (`prepared`, `meadows`, `butt`, `bites`, лента по `order`); выход — три
   билдера, `Scraps` (lawns + paving-контуры; сетки строятся лениво позже),
   `pieces`. Варианты: пре-вычисление по улице в `in_parallel` над порядком
   заливки + серийная раскладка в цикле, либо локальные билдеры +
   `MeshBuilder::append` и `Scraps`-слияние по порядку заливки. Выбор —
   по разрезу (доля компьюта `densify`/`verge_at`/`verge_runs`/`miter_offsets`
   против earcut-раскладки).
4. **`lay_green_scraps`**: по разрезу — серийные части (`push_green`-фильтр
   над карманами и газонами, `bitten`, earcut-раскладка лоскутов) —
   `in_parallel` по карманам/лоскутам с сохранением порядка; если 650 мс
   уже почти целиком в параллельных `find`/`find_green` — алгоритмическая
   экономия по форме результата (без размазывания фокуса).

Каждый шаг — отдельный коммит с бенчем до/после; откат мелкий.

## Инварианты (не трогать)

- **Геометрия — функция входа, не потоков.** Цель — вершины ступени 0
  бит-в-бит с бенчем базы (слияние в порядке входа); если какой-то порядок
  меняется по строению правки — дрейф класса «перестановка вершин»
  (прецеденты записей 19/22) фиксируется в записи честно.
- **Порядок `DrawnPieces` / списков `Scraps`** — контракт семантического
  индекса (`map/inspect.rs`) и оверлеев; лоскуты и находка едут в порядке
  газонов, находка улицы — в порядке заливки.
- **Порядок заливки** — «узкие первыми, ведущие последними» (`fill_order`);
  вход параллельного прохода = порядок заливки, не индекс дорог.
- **Зерно от точки** (`map/seed.rs`): ничего в дорожной сборке не сеется
  от индекса улицы или узла.
- **Пересборка стилем/солнцем/формой остаётся одной сборкой `build_roads`**
  — выигрывает от тех же правок; регресса живой пересборке не давать.
- Ступень 1 идёт тем же кодом — её бенч-время сверять контрольной строкой.
- Инструменты по цветам слоёв и `references/roads-*.md` (скил osm-map) —
  инварианты обочин/кербов; правки сверять с ними.

## Шаги

1. Спека (этот файл).
2. База: 2–3 живых тёплых старта (снапшот-хиты, `caffeinate -i`,
   `QWE_PERF_NOAPPNAP=1`/`NOVSYNC`/`FRAME_SPIKES=30`) + офлайн бенч
   `cargo run --example map_meshing -- paris` в одном состоянии машины.
3. Разрез ступени 0 (временные `eprintln`, до коммита) — сначала офлайн
   бенчем, подтверждение живым лейном `map meshes: roads (verge step 0)`.
4. Фиксы по результатам разреза (мелкими коммитами, каждый с бенчем).
5. Верификация (ниже), запись 24, артефакт.

## Верификация

- Бенч `map_meshing`: дорожные слои и `RoadReport` — счётчики бит-в-бит
  до/после (или честно зафиксированный дрейф класса перестановки);
  ступень 0 → целевая цифра по разрезу.
- Живой тёплый старт: 2 базы + 2 правочных прогона, строки
  `map meshes: roads (verge step 0)` и `whole set in …`; warmup в шуме
  (записи 15/19); строки `osm map:` бит-в-бит.
- Картинка: оффскрин-кадр плотного центра Парижа до/после (обочины, кербы,
  лоскуты, краска — та же геометрия).
- `world reload: N scene entities survived` — 0; `panicked`/`ERROR` — 0.
- `tools/check.sh` по изменённым файлам (ярды реплеев,
  `a_restart_replays_the_run` зелёные).
