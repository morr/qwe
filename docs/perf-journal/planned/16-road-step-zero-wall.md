# Запланировано 16 — стена whole set: дорожный лейн, ступень обочин 0 (второй заход)

Приоритет: **1** — `planned/15-startup-discovery.md` в очереди не появился
(в `planned/` лежат 01–14), итогов startup-разбора нет. Стена whole set
после записей 24/25/26 — **`roads (verge step 0)`**, 4.5–4.9 живьём в
спокойной машине. Заезд 17.

## Проблема

Тёплый старт Парижа (снапшот-хит, спокойная машина, вечер 2026-11-11):
8.36–8.77 с; лейны prepare-потока — roads step 0 **4.5–4.9** (стена,
whole set 4.4–4.8), polymesh 3.8–4.7, buildings 3.6–3.8, мелочь 1.8–2.0,
заборы 1.0–1.3, warmup ~2.0.

Два вопроса, которые записи 24/25/26 оставили:

1. **Остаток бенча не атрибутирован.** Разрез записи 24 разобрал 1395 из
   3009 мс бенча ступени 0 (kerb_returns 253, ленты 596, лоскуты 546,
   станции 0); правки срезали эти фазы до ~250 мс, но бенч ступени упал
   только до 2558 — **~2.3 с остатка фазами не разбирались**: нарисованная
   сеть (`Drawn`), узлы и скругления, краска, мосты, сборка слоёв с earcut
   на ~6 млн вершин ступени.
2. **Живой лейн выше бенча на ~1.5–2 с** (бенч 2558 против 4.1–4.3 живьём
   в записи 24 — разрыв остался прежним и после правок). Дележ ядер между
   лейнами объяснён частью (0.2–0.4, запись 24); остальное — не объяснено.
   Кандидат: одновременные штормы `in_parallel` всех лейнов (каждый вызов
   сеет `workers()` потоков — 2 ступени дорог + здания + заборы + полимеш
   + мелочь на одной машине). Проверить разрезом пофазно: wall фазы живьём
   против wall той же фазы в бенче.

## Направление решения

Первый шаг — **разрез фаз `build_roads` ступени 0 в двух осях** (временные
`eprintln` DRILL, снятые до коммита; CPU-суммы параллельных проходов
отличать от wall — метод записи 24):

1. бенч (`map_meshing paris`, ступень 0) — фазы в одиночном прогоне: куда
   ушли ~2.3 с остатка;
2. живой тёплый старт — те же фазы внутри лейна `roads (verge step 0)`
   prepare-потока: разрыв живой/бенч пофазно — дележ ядер против лишней
   работы. Контроль — строки `map meshes:` всех лейнов того же прогона.

Фиксы по разрезу (приоритет задают цифры, не список):

1. **Префильтр по рамкам** (прецеденты записей 22/25) — где фаза платит
   за пары, которых не может быть;
2. **`in_parallel` по независимым единицам, порядок входа сохранён**
   (прецеденты записей 19/22/24/26);
3. **Сетка/кеш вместо линейных сканов** (арки записи 19, `FenceIndex`
   записи 26);
4. Если доминанта — **дележ ядер** между лейнами (wall фазы живьём ≫ wall
   в бенче на тех же входах): кап параллелизма поверх `in_parallel` или
   перекладка групп `build_world_meshes` — форма по разрезу; порядок
   результатов (сортировка по индексу входа) не меняется ни в какой форме.

## Верификация

- **Бенч** `caffeinate -i cargo run --example map_meshing -- paris`:
  строка `roads` (ступень 0) до/после в одном состоянии машины; соседние
  строки (buildings, fences) — контроль состояния машины.
- **Живая пара** база/правка в одном состоянии машины (stash-пара в
  worktree или пара HEAD/HEAD~N); шум межпрогонный ±8–15 %, брать медианы
  снапшот-хитов; ступень входа заборов — по строке отчёта.
- `osm map:` бит-в-бит; `road meshing:` — вершины бит-в-бит или класс
  перестановки вслух; `polymesh stitched` бит-в-бит.
- Оффскрин-кадр плотного центра до/после (mean разности — метод записи 25).
- `world reload: N scene entities survived` — 0; `panicked`/`ERROR` — 0.
- `tools/check.sh <файлы>` — зелёные, включая швы бит-в-бит, парити-тесты
  заливки, ярды реплеев и `a_restart_replays_the_run`.
