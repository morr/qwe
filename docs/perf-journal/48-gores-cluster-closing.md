**Компаньон network-уровня** — `g_closed_outline` **59.2 serial**
(запись 47): два outline-прохода по результату union
(`outline(+GORE_CLOSING)`, затем `outline(-GORE_CLOSING)`). Прямой
чанкинг float-вызовов по фигурам union **не бит-в-бит**: адаптер
квантования float→int строится по габаритам источника
(`OutlineSolver::prepare` — rect точек, раздутый на
(|внешний|+|внутренний|)·фактор скругления, масштаб целочисленной сетки
из радиуса) — у куска габариты свои, и координаты гуляют на ~4e-5 м;
контракт-тест поймал расхождение на первом прогоне. Лечение — пайплайн
на **int-уровне с общим адаптером**:

1. **группировка кусков** (`closing_clusters`): фигуры union в пределах
   2×`GORE_CLOSING` (24 м) — в один кусок, транзитивно, консервативно
   по габаритам фигур, раздутым на 24 м (пересечение раздутых габаритов
   — достаточное условие объединения). Основание: close фигуры ⊆ её
   раздувание (6 м за край), раздувание раскладывается по объединению,
   бридж эрозии возможен только между фигурами ближе 24 м — закрытие
   куска равно серийному закрытию его фигур, конкатенация кусков —
   серийному результату;
2. **проход 1 (раздувание)** по кускам `in_parallel` с адаптером A1
   всего набора (тот же расчёт `prepare`: габариты фигур +
   (6+6)·1.1 — фактор скругления Round = 1.1, `padding_factor` у
   i_overlay `pub(super)`, Round — единственный join сборки); каждый
   кусок: `to_int(A1)` → `IntOutlineOffset::outline` → `to_float(A1)` →
   `SimplifyContour(A1)` — та же чистка, что у float-двери;
3. **проход 2 (эрозия)** по кускам с адаптером A2 — по габаритам
   **раздутого набора целиком**: серийный второй проход строит адаптер
   по своему входу, а он известен только после первого (два раунда
   параллели);
4. **порядок легален**: outline i_overlay инвариантен к порядку входа
   (проверено контрактом), клинья считаются per-figure независимо, и
   итоговый union клиньев (`wedges.simplify_shape`) нормализует порядок
   входа (тоже проверено) — конкатенация кусков в порядке фигур
   восстанавливает серийный результат без ручного порядка.

**Метод** (новое к методу записей 36–47):

- **квантование i_overlay зависит от габаритов источника**:
  `OutlineSolver::prepare` строит адаптер float→int из габаритов набора
  (rect + (|внешний|+|внутренний|)·`padding_factor`, масштаб — из
  радиуса), поэтому у куска свой масштаб целочисленной сетки, и прямой
  чанкинг float-outline расходится с серийным на ~4e-5 м — контентные
  счётчики этого не видят, ловит только сравнение байт-в-байт
  (контракт-тест). Лечение — int-уровень (`IntOutlineOffset`) с
  адаптером всего набора; проход, чей вход — результат предыдущего,
  требует второго адаптера от габаритов раздутого набора (два раунда
  параллели);
- **порядок входа не мешает чанкингу булевых проходов**: outline
  i_overlay инвариантен к порядку входа, а итоговый union конвейера
  (`wedges.simplify_shape`) нормализует порядок — конкатенация кусков
  в порядке фигур union легальна без восстановления серийного порядка
  фигур; оба свойства закреплены контракт-тестом;
- внешний пул финалов ≈ max персональной стены + 12 (spawn/join) —
  в отличие от вложенного конвейера записи 47, одноуровневый пул
  не прячет работу.
