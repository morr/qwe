# Запланировано 09 — шторм warmup: 20k заявок в первом кадре, тёплый старт платит 1.65–4.4 с

Приоритет: **1** — заезд 11. После заезда 10 (запись 20) это последняя крупная
последовательная часть тёплого старта вне мешинга; стеной мешинга стал полимеш
(4.6–4.7 с, навигационная работа, в заезд не входит).

## Проблема

Warmup-холд на входе в мир (Париж, тёплый старт) плавает между прогонами и
состояниями машины: 1.65–2.0 с (запись 20, свежие прогоны), 3.4 с (запись 18),
4.3–4.4 с (запись 14), 2.92 с после правки конвейера (запись 16). Плавание —
методическая мина записи 15: сравнивать прогон с прогоном только в одном
состоянии машины (`caffeinate -i`, `QWE_PERF_NOAPPNAP=1`).

Тёплый старт Парижа после заезда 10 — 8.2–8.5 с: мешинг ~4.7 (стена полимеш) +
гейты 1.44 + спавн + warmup 1.7–2.0. Warmup здесь — треть остатка, который
мешинг не объясняет.

## Механика (из кода, ноябрь 2026)

- 20 000 пешек спавнятся в `OnEnter(Playing)` с **нулевой** `WanderPause`
  (`human/systems.rs`: «без стартовой паузы: все идут с первого кадра») и
  `HumanFirstWanderTag` — стартовая паза когда-то была и убрана сознательно,
  потому что заставляла пешек в кадре стоять первые секунды.
- `pick_wander_targets` (`Update`, живая ветка) в первом же кадре подаёт
  командами ~20k `PathfindingRequest`; в том же кадре (явный
  `.after(pick_wander_targets)`) `assign_destination_slots` видит их все по
  `Added<PathfindingRequest>` и разводит слоты, а обсерверы сетки очереди
  принимают 20k записей. Одна волна переносов архетипов из 20k — механизм
  записи 15.
- Диспетчер (`dispatch_pathfinding_requests`, `Update`, `SimPipeline::Live`)
  **работает на паузе прогрева** — `live_dispatch_runs` делает для неё
  исключение; бюджет `MAX_PATHFINDING_IN_FLIGHT` = 1024, выдача только пешкам
  в кадре+запас (`queue_key` → `None` вне кадра), внутри приоритета — ближние
  к центру. Приёмка (`listen_for_pathfinding_tasks`) снимает пару
  `(PathfindingTask, PathfindingRequest)` одним пакетом (запись 16) и ставит
  `MovingTag` — по переносу архетипа на каждый поиск.
- Прогрев (`loading.rs::poll_warmup`) ждёт нуля пешек с заявкой/таском в
  **точном кадре** камеры (запас не добавляется), таймер — `Time<Real>`:
  каждый тяжёлый кадр шторма входит в цифру целиком. `WARMUP_TIMEOUT` 10 с,
  `WARMUP_GRACE` 0.5 с.
- Бэкенд на входе — полимеш (строится в лоад-потоке, `PolyNavmesh::set_ready`
  в `Done`); northstar в живом режиме на входе не строится (его
  `OnEnter(Warmup)`-постройка сидит в `SimPipeline::Deterministic`, отключённом
  в живом режиме) — его и не ждём, меш перекрывает.
- Демонов на прогреве нет — спавнер гейтится `Live`. Шторм — чисто мирные.

Кандидаты цены: (a) **кадры подачи** — 20k вставок заявок + 20k слотов + 20k
записей сетки одной волной в первом-втором кадре; (b) **ожидание диспетчера** —
цикл приёмка/выдача один на кадр при бюджете 1024: в кадре видно ~1200–2000
пешек (зум 0.4, портал в центре плотности), это 1–2 цикла, но каждый цикл —
кадр, а кадры шторма тяжёлые; (c) **сами прокладки** на пуле (полианья, длительность
уже в `PATHFINDING_DURATION_MS`); (d) **хвост** — последние пешки с долгими
путями держат холд после опустошения очереди.

## Направление решения — решение по разрезу

1. **Разрез фаз шторма** — временные `eprintln` до коммита (прецеденты: разрез
   `build_roads` заезда 10, union/lay записи 19; снятие — `git restore`, пока
   дифф состоит только из замеров):
   - `pick_wander_targets`: сколько заявок подано в кадре, длительность прохода;
   - `assign_destination_slots`: сколько свежих в кадре, длительность;
   - `dispatch_pathfinding_requests`: сколько выдано, бюджет на входе;
   - `listen_for_pathfinding_tasks`: сколько снято;
   - `poll_warmup`: `waiting`/`elapsed` по кадрам (или реже — по дельтам).
   По строкам лога с таймстампами ищем, где время: **спавн заявок / ожидание
   диспетчера / сами прокладки**.
2. По вердикту разреза — один из кандидатов (не все сразу):
   a. **Разнести очередь входа по кадрам** (растянутая подача заявок) — если
      доминанта кадры подачи. Зерно решений от `(PawnId, номер решения)`
      (`WanderIndex`) защищает от порядка обхода — растяжение по кадрам не
      меняет выбор целей; сверить ярды.
   b. **Приогреть диспетчер до Live** — если доминанта ожидание циклов:
      диспетчер уже работает на паузе прогрева, так что смысл кандидата —
      убрать пустые кадры до первой выдачи, поднять частоту цикла
      (не раз в кадр) или бюджет на прогреве. Правки живой ветки;
      детерминированный диспетчер не трогается вовсе.
   c. **Урезать само множество входных заявок** — дальние пешки вне камеры
      получают заявки позже, — если доминанта подача/слоты/сетка, а не
      прокладки. Прецедент обратной правки: стартовая паза убрана (см.
      `human/systems.rs`), потому что заставляла пешек в кадре стоять —
      вернуть «стоять» нельзя, но «стоять» и «стоять без заявки» разные вещи:
      пешка вне кадра без заявки выбирает цель, когда камера приехала.

## Инварианты (не трогать)

- **Смысл warmup-холда**: пешки в кадре стоят готовыми (с путями), когда
  лоадер уходит. Любой кандидат проверяется скрином сразу после `Live`.
- **Каунт прогрева считает ровно то, что диспетчер обслужит** (прецедент
  записи 18: «считает только то…») — `wanderers_dispatched_at_zoom` +
  `UrgentPath`, точный кадр без запаса.
- **Детерминизм**: retire tick / dispatch rate / FIFO key детерминированного
  диспетчера не трогать. Подача — `WanderIndex::next` от `(PawnId, номер
  решения)`: порядок обхода на выбор цели не влияет по построению, но правки
  кандидата (c) сверять с ярдами реплеев обязательно.
- **Переносы между архетипами**: выдача без снятия заявки (запись 16) уже
  сократила цену до двух переносов на поиск; новых осей в пространство
  архетипов не добавлять (потолок переписи, запись 15).
- Новых спавн-сайтов правка не заводит; если заводит — `DespawnOnExit` и
  ноль в счётчике `world reload: N scene entities survived`.

## Шаги

1. Спека (этот файл).
2. База: 3 живых прогона тёплого старта Парижа до правок — снапшот-хиты,
   `caffeinate -i`, `QWE_PERF_NOAPPNAP=1`/`NOVSYNC`/`FRAME_SPIKES=30`, фоном;
   warmup по времени между строками лога (снапшот-хит → `warmup:`), шторм —
   строки `warmup:` и pathfinding в логе.
3. Разрез фаз (временные `eprintln`, до коммита) на живом прогоне; вердикт,
   где время; дельта базы с разрезом против базы без (замеры не должны
   плавать от самой инструментировки).
4. Фикс по вердикту (мелкими коммитами, стиль git-скилла) → `tools/check.sh`
   по изменённым файлам.
5. Живые замеры после: 2+ прогона в том же состоянии машины; контроли ниже.
6. Запись 21 в `docs/perf-journal/` (стиль записей 16–20), строки в артефакте
   (get_artifact → правка → update_artifact с expectedRev), коммиты.

## Верификация

- Warmup: база 3 прогона → после 2+; дельта против межпрогонного шума
  (±8–15 %, запись 15); сравнение только в одном состоянии машины.
- Контроли: `osm map:` бит-в-бит между прогонами; `scene entities survived` —
  0; `panicked`/`ERROR` — 0; спайки кадров (`FRAME_SPIKES=30`) — волна подачи
  не должна переехать в `Live` видимым всплеском.
- Картинка/поведение: оффскрин-кадр центра Парижа сразу после `Live` — пешки
  в кадре с путями (стоят или идут, но не «стоят без путей»); дельта
  killed/escaped за окно 30 с — как раньше.
- Ярды и `a_restart_replays_the_run` зелёные (`tools/check.sh`).
