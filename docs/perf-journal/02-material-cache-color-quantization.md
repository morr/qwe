# Запись 2 — Кеш материалов рендера масштабируется с населением → квантование цвета одежды

Статус: фикс. Файлы: `src/human/look.rs` · `roll_attire`, `spread_blood`.

**Гипотеза.** Холостой кадр (пауза, zoom 0.4) занят на ~60 % процессорного
времени `bevy_sprite_render::sprite_mesh` — `evict_unused_materials`
и `add_material`. Кеш материалов keyed по *точным битам* цвета
`Sprite`; у каждой пешки цвет одежды — три непрерывных броска f32
(hue 170–290°, sat 0.15–0.5, light 0.3–0.55) → ~20 000 уникальных бакетов, и eviction
ходит по ним каждый кадр независимо от изменений (~0.5 мс/кадр, линейно с населением).

**Проверка.** Профили `sample` на паузе: 20k популяция —
~4 900 сэмплов sprite-механики на 3 потоках; перезапуск с
`QWE_PERF_POP=64` — ~100 сэмплов. Зависимость от населения подтверждена.

**Фикс.** Квантование после броска: hue → 3°, sat/light → 0.05
(≤ ~1 900 бакетов; на приглушённой палитре шаг глазом не виден). Число и порядок
бросков потока решений не меняются — детерминизм цел. Бонус: `spread_blood`
больше не пишет `Silhouette`-«no-op» на паузе (запись того же значения
гонит лужу через перепись спрайта и переключение материала каждый кадр).
