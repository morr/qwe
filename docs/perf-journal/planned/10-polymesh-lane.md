# Запланировано 10 — полимеш-дорожка мешинга: стена whole set 4.6–4.7 с на Париже

Приоритет: **1** — заезд 12. После заезда 10 (запись 20) стеной мешинга стал
полимеш: последняя дорожка-одиночка, не разобранная прецедентами 19/20.
07 занята разведкой крови — не трогать.

## Проблема

Тёплый старт Парижа после заездов 10/11 — 8.2–8.5 с, стена whole set
(`build_world_meshes`) — **полимеш 4.6–4.7 с** (запись 20 «Что дальше», строка
`map meshes: polymesh in …`). Рядом в тени: заборы 2.6–2.9, здания 2.3–2.4,
мелочь 1.3, дороги 3.7+2.6. Вне мешинга последовательно: гейты 1.44 с,
warmup ~1.0–1.3 s wall после записи 21.

Панель Navmesh включена по умолчанию (`PolymeshDebug::enabled`, радиус —
`POLYMESH_AGENT_RADIUS_MIN` = 0.2, чанки по умолчанию), так что 4.7 с — стена
дефолтной конфигурации, не артефакт настроек сессии.

## Механика (из кода, ноябрь 2026)

- Полимеш строится **в лоад-потоке** дорожкой `build_world_meshes`
  (`map/prepare.rs`) → `build_polymesh_for` → `build_polymesh`
  (`navigation/polymesh/build.rs`) от финальной `MapData` под
  `StyleSnapshot`; отмена в лейне не передаётся (`None`) — `Arc<AtomicBool>`
  живёт только в асинхронном панельном пути (`sync_polymesh_build`).
- Фазы `build_polymesh` (строки лога уже дают хвост): контуры
  (`CurbCoverage::build`, блокирующие `blocker_contours` — здания/вода с
  дырами, русла, стены, заборы минус проёмы, бордюры мостов; режущие
  `carve_contours` — настилы, примыкающие, арки) → **большой boolean**
  `blockers.overlay(carves, Difference)` → клип прямоугольником карты →
  **раздувание радиуса** (`inflate_ring` по внешним контурам + union раздутых)
  → `chunk_layers` (глобальные `seam_points` раз, затем **последовательный**
  цикл по чанкам: клип контуров прямоугольником чанка + CDT
  `polyanya::Triangulation` + `merge_polygons`) → `components_of` по слою →
  `mesh.bake()` → `stitch_chunks` → `set_search_delta/steps`.
- Существующие строки лога: `polymesh chunked into … in …` (весь цикл чанков),
  `polymesh baked in …`, `polymesh stitched: … in …`; начало конвейера
  (контуры + большой boolean + клип + раздувание) в строку чанка не попадает —
  разрез добирает её временными `eprintln`.
- Дорожка сшита с миром через `WorldMeshes.polymesh` → `PolyNavmesh::set_ready`
  в `Done`: асинхронный панельный билд на входе не стартует, диспетчер сразу
  роутит через полианью (warmup-пути — полимешные).

## Направление решения — решение по разрезу

1. **Разрез фаз** — временные `eprintln` до коммита (прецеденты: разрез
   `build_roads` заезда 10, union/lay записи 19; снятие — `git restore`, пока
   дифф состоит только из замеров): `CurbCoverage`+контуры, большой boolean,
   клип карты, раздувание (сам `inflate_ring` против его union), цикл чанков
   (клип против CDT внутри `chunk_layer` при надобности), components, bake,
   stitch. База строк лога уже лежит в прогоне — разрез только добирает
   начало. Офлайн-кросс-чек — `examples/bench/polymesh_bench` (Тула,
   детерминированный, печатает время постройки).
2. По вердикту разреза — один кандидат, не все сразу:
   a. **Чанки по прецеденту записи 19** (`map/parallel.rs::in_parallel` с
      порядком входа): чанки независимы — входы (`contours`, `seams`,
      прямоугольник) только читаются, у каждого слоя свой выход, порядок
      результатов = порядок индексов чанков. Проверка отмены — внутри
      обработки чанка (та же гранулярность, что у последовательного цикла).
   b. **Раздувание/его union по прецеденту тайлового union** (`push_union`
      записи 19: клетки 256 м, `in_parallel`, финальный union) — если
      доминанта раздувание.
   c. **Вынос за стену whole set** (мир стартует без меша, меш доезжает
      панельным асинхронным путём) — если разрез покажет, что дешёвого
      среза до заборов (2.6–2.9 с) нет: цена — warmup и первые пути на
      входе роутит сетка, поведение входа меняется; решение только по цифрам.

## Инварианты (не трогать)

- **Порядок чанков, швов и стичей — контракт** (`navigation-deep
  references/polymesh.md`): слои в меше идут в порядке индексов чанков
  (8-битный индекс слоя полианьи, граф компонентов, коридор); `seam_points`
  считаются раз на всю карту, оба соседа получают один список; точки швов —
  функция индекса узла и шага, не lerp. `in_parallel` обязан сохранять
  порядок входа.
- **Постройка идёт в лоад-потоке под `StyleSnapshot`** — входы не читаются
  из живых ресурсов; правки лейна не должны заводить ECS-чтений.
- **Пересборка живым солнцем/панелью остаётся дешёвой**: путь
  `sync_polymesh_build` (таск, отмена `Arc<AtomicBool>`, supersede при смене
  радиуса) не деградирует — проверка отмены сохраняет гранулярность «до
  чанка/до стадии»; `set_agent_radius` в конвейере не появляется (радиус
  вшит в контуры, раздутых кольца объединяются).
- **`rescue_trapped_entities` на completed build — слот не трогать**
  (`polymesh_rebuilt` по `PolyNavmesh::generation`).
- **Детерминизм**: раздутые контуры и точки швов — функции входа, не порядка
  обхода потоков; `in_parallel` сортирует по индексу. Геометрия результата —
  контракт картинки и поиска (пороги швов, `SIMPLIFY_EPSILON`,
  `DEGENERATE_SPAN` не менять).
- Счётчик `world reload: N scene entities survived` — 0; новых спавн-сайтов
  правка не заводит.
- Ярды реплеев и `a_restart_replays_the_run` зелёные (`tools/check.sh`).

- Лейн: база 2–3 прогона → после 2+; дельта против межпрогонного шума
  (±8–15 %); сравнение только в одном состоянии машины. Тёплый старт — тем
  же способом по хиту снапшота.
- Контроли: `osm map:` бит-в-бит между прогонами; строки `polymesh chunked
  … polygons` / `layers fully blocked` / `stitched: N seam vertices, N
  component nodes` — те же числа между прогонами до и после (порядок и
  геометрия не поехали); `scene entities survived` — 0; `panicked`/`ERROR`
  — 0.
- Картинка/поведение: оффскрин-кадр центра Парижа после `Live`; полимешный
  оверлей (Show на панели Navmesh) по желанию — контуры препятствий на месте.
- Тесты полимеша (`navigation/polymesh/tests.rs`, парити-тесты, швы
  бит-в-бит) и `polymesh_bench` без регресса поиска (mean/worst query time).
