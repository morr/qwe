# Запланировано 19 — inspect-индекс в лоад-поток: база параллельно лейнам, куски — догонкой на входе

Приоритет: **1** — остаток пункта 2 списка `15-startup-discovery` («окно
входа в мир»), рычаг ~0.3 с из warmup-окна: его update-сегмент 341–352 мс —
`rebuild_index` (разведка 15, подтверждена записью 23). Заезд 20.

## Разведка заезда — вердикт по исходной формулировке

Исходный план («индекс строится в prepare-поток до спавна, целиком») не
даёт выигрыша даже без запрета записи 28:

- индекс — четыре прохода (площади, линии, точки, деревья) + карманы у
  бордюра + пятый проход по отрисованным кускам (`DrawnPieces`);
- четыре с карманами читают только `MapData` + `RoadShape` — оба готовы
  до лейнов (`kerb_pocket_outlines(map, shape)` — чистая функция, без
  глобалей и статиков);
- пятый проход читает `pieces` — выход дорожного финала, а дорожный
  финал ступени входа — сама стена whole set (3.4–3.5 с, записи 28/29).
  Любое место после финала — хвост лейна или после join'а — серийная
  надбавка к стене: −0.3 с из warmup, +0.3 с к whole set, ноль итого.

Так что решение **не требует правок `map/prepare.rs` и `map/roads/*`
вообще** (запрет записи 28 не всплывает): индекс делится — дорогое в
лоад-поток параллельно лейнам, куски — догонкой при входе в мир.

## Текущее состояние

`rebuild_index` (`map/inspect.rs`) — Update-система: судит смену
`MapData` + `RoadShapeOnMap` + `DrawnPieces` сама (`a4a42ede`, запись 23)
и строит индекс целиком (`InspectIndex::rebuild`). На входе в мир все три
ресурса свежи (карта вставлена `poll_job`-ом, куски — `spawn_map`-ом),
пересборка попадает в первый Update warmup-холда — 341–352 мс. Дорогой
проход — карманы (`kerb_pocket_outlines`, подъём каркаса дорог); его доля
замеряется базой (строка `inspect index: … kerb pockets in …`).

`DrawnPieces` читает только `rebuild_index`; пишут `spawn_map` (вход) и
`rebuild_roads` (пересборка). Куски в лоад-потоке уже есть: `RoadBuild`
несёт их с записи 28 (`prepare.rs` → `WorldMeshes.roads`).

## Направление решения

1. **Деление индекса** (`map/inspect.rs`): `InspectIndex::prebuild(map,
   shape)` — проходы 1–4 + карманы, `pieces` пуст, флаг «ждёт куски»
   хранит форму, под которую собран. `apply_pieces(&mut self, pieces)` —
   пятый проход (габарит + вставка в сетку + копия вектора — дешёвый,
   меряется). Полный `rebuild` остаётся как был (галерея, дрейф формы,
   смена стиля при игре).
2. **Лоад-поток** (`map/osm/download.rs::finish_world` — файл не
   заморожен): состав деревьев поднимается до клона (та же
   проверка-и-сбор, что внутри `build_world_meshes` — её проверка увидит
   состав готовым и не повторит; карта после гейтов и прунинга финальна),
   глобаль ширины полосы ставится та же, что `prepare.rs` ставит лейнам
   (карманы отвечают той же осью, что рисунок), клон `MapData` уходит в
   поток `std::thread::scope` параллельно `build_world_meshes`; по join'у
   предсборка кладётся в `LoadedWorld`. Клон — серийная цена перекрытия
   (меряется; ожидание — десятки мс против 0.3 с выигрыша).
3. **Вход в мир**: `poll_job` вставляет предсборку как `InspectIndex`
   (Done-ветка, рядом с `MapData`). `rebuild_index` первым кадром мира
   видит «ждёт куски» под текущей формой → `apply_pieces` (+ строка
   лога) — вместо полной пересборки. Дрейф формы (ручка ехала при
   загрузке) — полная пересборка, как сегодня. Порядок кадра гарантирует
   свежесть кусков: вставки `poll_job` применяются в конце кадра Done,
   спавн-цепочка (`StateTransition`) кладёт новые `DrawnPieces` до
   первого Update следующего кадра — между ними Update-система не
   запустится, устаревшие куски догнать нельзя.
4. Смена стиля при игре (`rebuild_roads` → новые куски) — как сегодня:
   полная пересборка (предсборка уже съедена; переиспользование базы по
   тикам — не в этом заезде).

## Инварианты (не трогать)

- **Ответ пробы бит-в-бит**: находки `prebuild`+`apply_pieces` на сетке
  точек равны находкам полного `rebuild` (тест).
- **`map/prepare.rs` и `map/roads/*` не правятся** (запись 28). Правятся:
  `map/osm/download.rs`, `src/loading.rs`, `map/inspect.rs` (+ тесты).
- Строки `osm map:` / `road meshing:` / `polymesh stitched` бит-в-бит;
  `map meshes: whole set` — с учтённой серийной надбавкой клона.
- Состав деревьев собирается ровно один раз за загрузку (по строкам
  лога), состав `composed_for` — как был.
- Ярды реплеев и `a_restart_replays_the_run` — зелёные; `world reload:
  N scene entities survived` — 0.
- Не трогать: `planned/07` (кровь — чужая разведка);
  `navigation/navmesh/{gates,reach,fill}.rs` и `map/footprint.rs`
  (запись 26); vendor-патчи полимеша (запись 29); незакоммиченную
  инструментировку параллельных сессий.
- Порты пары 15704/15706; 15702 — пользователь, 15703 может быть занят
  чужой сессией. Чужие процессы не убивать.

## Шаги

1. Спека (этот файл).
2. **Worktree-пара** (прецеденты записей 27–29): `.worktrees/perf20-base`
   (master) и `.worktrees/perf20` (ветка фикса); кеш `assets/osm/`
   скопировать с mtime в оба; `tools/seed-worktree-target.sh`.
3. **База**: 3 живых тёплых старта на сторону (запуск фоном
   `BRP_PORT=… QWE_PERF_NOAPPNAP=1 QWE_PERF_NOVSYNC=1
   QWE_PERF_FRAME_SPIKES=30 caffeinate -i cargo run`; свежий процесс —
   холодный, в медианы не берётся; перезагрузки
   `brp res set City . '"Paris"'`; сосед на `brp pause` во время
   перезагрузок измеряемой стороны). В базе — доли проходов индекса
   (строки `inspect index:`); разрез клона — временный `eprintln`,
   снятый до коммита.
4. Фикс — мелкими коммитами: деление индекса → лоад-поток → вход.
5. `tools/check.sh` всех изменённых файлов.
6. Живая пара до/после в одном состоянии машины, запись 30, артефакт,
   коммиты, заезд 21.

## Верификация

- Живая пара: тёплый старт (снапшот-хит → `warmup:`) — медианы 3+3;
  warmup-строка; whole set (надбавка клона видна и учтена); строки
  `inspect index:` — готовка в лоад-потоке и догонка кусками вместо
  rebuild.
- Проба в живом приложении: `brp probe` плотной точки — куски и карманы
  в ответе, как до правки; подсветка выбранной находки рисуется.
- `inspect index: rebuilt` в тёплом старте быть не должно (только на
  дрейфе формы и смене стиля).
- `tools/check.sh` — зелёный: тесты inspect-индекса (равенство
  prebuild+apply и полного rebuild), ярды реплеев,
  `a_restart_replays_the_run`, clippy, fmt.
