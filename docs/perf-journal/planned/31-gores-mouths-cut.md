Приоритет: **1** — заезд 33, разрез-заезд по рейтингу записи 42. Дорожная лайна
тёплого старта Парижа — критический путь whole set (3.5 у фикса записи 42
против 3.6 у базы). Рейтинг серийных кусков после ленты (запись 42):
**gores ≈273 / mouths ≈265** (union-куски — записи 27/34), **`Drawn::new`
нижняя ≈347** (серийные сетки стежков — порядок вставки пинит выбор стыка на

## Проблема

Разрез записи 40 снял лайну по верхнему уровню и под contention живой пары;
внутри трёх крупнейших серийных кусков свежего разреза нет:

- **`Gores::of`** (`map/roads/gores.rs`): замыкание сети — **один**
  `simplify_shape` + `outline(+GORE_CLOSING)` + `outline(−GORE_CLOSING)` по
  всему городу (сеть из штрихов подходов и колец) — не тайловано, в отличие от
  union лент устьев (запись 27). Дальше — разность по фигурам (каждая фигура
  фильтрует **все** `solid` по рамке — `clip_near`), веера подходов попарно
  (`fans`), повторный simplify клиньев, фильтр тел по касанию двух подходов,
  `settle` (outline на каждое тело: асфальт +0.5, штриховка ±0.3 + `is_wide`).
  Замыкание — морфологическое (расширение+сжатие), **не дистрибутивно по
  union**: тайловать по клеткам «по первой точке», как устья, нельзя — мост
  через границу клеток (зазор ≤ 2·[`GORE_CLOSING`]) будет потерян.
- **`mouths`** (`junctions.rs::mouths` → `gores/mouths.rs::mouths`): отбор
  проезжих частей и сборка `taken` (все дома/вода/зелень/стоянки + дорожные
  площади + острова), постройка лент — simplify+stroke по каждой проезжей
  части серийно; union лент **уже тайлован** (запись 27), но итоговый union
  выходов клеток серийный; размыкание дыр — `outline(−0.75)+outline(+0.75)`
  по **всем** дырам города; проверки (вершины дорожек, `taken`,
  `paved_share`) — по сетке.
- **`Drawn::new`** (`map/roads/drawn.rs`): сетка звеньев стежков —
  `insert_segment` по каждому звену (`network/mod.rs::stitches`) и
  `Obstacles::new` (здания+вода в сетку) — серийные; порядок вставки задаёт
  порядок `near_each` и выбор стыка на ничьих (запись 39) — сетка звеньев
  **не параллелится**; у `Obstacles::new` запрос — `at().any`, порядок
  результата не важен. nodal ≈154 уже параллелен внутри (пробы пар,
  перепонки, поиск стежков — запись 39); его серийные стены (RoadNodes,
  `pairs.align`, сглаживание+пути) — единицы–десятки мс.

Что из этого держит числа — не измерено: у gores и mouths разреза внутри не
было (устья — только union в записи 27), `Drawn::new` разрезан записью 39 до
фиксов 39/40/41/42 — контеншн лайны с тех пор сменился трижды.

## Направление — разрез трёх кусков, фикс крупнейшего ≥150

**Разрез** (временные `eprintln`, патч в `/tmp` **до** любого отката и до
коммитов — держать, пока правка не закоммичена, урок записи 42; соло-бенч
`map_meshing paris` ×3, свои живые процессы заглушены — два qwe на симуляции
дают +300–400 мс, урок записи 42):

- `Drawn::new`: nodal / стежки (сетки: звенья + `Obstacles::new` / параллельный
  поиск) / `across_median` / `merges` / сборка `stitched`;
- `Gores::of`: узлы колец + подходы / `fan_head`+штрихи сети / solid (кольца,
  острова, близкие улицы) / замыкание (simplify / outline(+6) / outline(−6)) /
  разность по фигурам / веера / повторный simplify+фильтр тел / `settle`;
- `mouths`: отбор+сборка (`junctions::mouths` до чистой функции) / ленты
  (simplify+stroke) / union (клетки / итог) / размыкание дыр / проверки;
- верхний уровень блока (gore_roads+`Gores::of`+adds / `mouths`+
  `clear_crossings`+`add_mouths`) — сверка с рейтингом записи 42.

**Фикс** — крупнейшая под-фаза ≥150 мс, по шаблону:

- union-кусок → тайлы, как `union_ribbons`/тени: клетка объединяет своё
  (`in_parallel`), выходы клеток объединяются разом; порядок клеток
  детерминирован — сортировка по ключу; малый вход — прежний однопроходный
  путь. Для замыкания gores тайлы обязаны быть **мостобезопасны**: контур
  кладётся в каждую клетку, которой касается его рамка, раздутая на
  2·[`GORE_CLOSING`] — пара контуров с зазором ≤ 2·[`GORE_CLOSING`] тогда
  сходится в общей клетке, мост не теряется; расширение дистрибутивно по
  union, сжатие — нет, поэтому итог клеток обязан собраться **одним**
  объединением. Геометрия — то же множество; порядок вершин — класс
  перестановки тайловых путей (прецеденты 19/22/25/27).
- по-кандидатная работа (ленты устьев, штрихи подходов) → чанки
  `in_parallel` + частичный аккумулятор + раскладка в исходном порядке
  (прецеденты: разделительные 27, краска узлов 40, кластеры/зебры 41, лента
  42). **ЧАНКИ, не по-штучные аккумуляторы** — по-уличный аккумулятор на
  десятках тысяч улиц дал +140 мс (урок записи 42).
- сетка звеньев стежков — порядок вставки пинит `near_each` — не трогать;
  `Obstacles::new` (`at().any` — порядок не важен) — кандидат, только если
  разрез скажет ≥150.

Выходы обязаны остаться бит-в-бит: счётчики ОБЕИХ строк `road meshing:` —
контроль (тайловые union — класс перестановки, `+N` vertices, как записи
19/22/25/27 — не молчаливая смена). Лента не пишет в `MapData` —
`SNAPSHOT_VERSION` не трогается.

**Правило выхода** (заезды 29–32): если рычаг в замороженных файлах, или
крупнейшая под-фаза <150 мс, или цена меньше планки — следующая по рейтингу
фаза записи 42 (обочины раскладки ленты 31–32 — частичные `Scraps` с ленивой
сеткой), и это отмечается в этой спеке и записи 43.

## Ожидание и риски

- Цель: разрез закрывает три куска под-фазами со свежим рейтингом; фикс
  снимает ≥150 мс серийной работы лайны (`map meshes: roads in`, whole set
  медианой живой пары, обе строки `road meshing:`). Обещать больше без
  разреза нельзя: числа записи 40 — под contention живой пары, соло
  существенно меньше.
- Эквивалентность: счётчики обеих строк `road meshing:` бит-в-бит (кроме
  заявленного класса перестановки тайлов); gores/mouths не пишут в `MapData`
  — `SNAPSHOT_VERSION` не трогается.
- Риски: тайловое замыкание gores обязано держать мосты через границы клеток
  (см. выше) — тест-контроль: счёт gores в строке `road meshing:` не меняется
  ни на один, кадр кольца с островками сравнивается с базой; `fans` попарно
  — O(n²) по подходам, чанки по подходам меняют порядок вееров в `wedges`
  перед simplify — порядок клиньев обязан остаться исходным (раскладка по
  индексам внешнего цикла); `settle_hatched` гоняет outline по каждому телу —
  тела независимы, кандидат по-тельного прохода; сборка `taken` — тысячи
  слайсов, если разрез скажет, что она горяча — параллель не нужна, она
  серийная по спискам.
- Витрины и бенчи (`build_roads_from`, `map_meshing`) идут через ту же
  сборку — их отчёты остаются контролем; малый вход (тесты) — однопроходный
  путь, тот же байт в байт.
