# Запланировано 20 — зданиевый лейн: разрез по фазам, тени и порядок

Приоритет: **1** — следующая стена после дорог (записи 28–30: roads step 0
3.4–3.5 живьём, buildings 2.8–3.0 — второй лейн стены; polymesh 1.2–1.3,
мелочь 1.6–1.9, заборы 0.75–1.1). Пункт 2 очереди записи 30
(переиспользование базы inspect-индекса на смене стиля) и остатки записи 29
(fence_gaps 122, union 307) — вне этого заезда: первый узкий только при
смене стиля, второй требует запрещённых файлов. Заезд 21.

## Проблема

Зданиевый лейн живьём 2.8–3.0 с (`map meshes: buildings`, записи 28–30).
Лейн — тот же чистый `mesh_buildings`, что мерит оффлайн-бенч, так что
бенч — якорь лейна: разница живого и бенча — дележ ядер с дорогами под
стеной (у обоих `in_parallel`), не лишняя работа.

Бенч (Париж, `ExtrusionShadowsTint` — игровой дефолт, clutter true,
`2.5D+shadows+tint` ≈ **1.98 с**) уже даёт пофазную разбивку:

| фаза | мс |
|---|---|
| наземные тени (`shadows` — union + кайма + заливка) | **1096** |
| порядок отрисовки (`order` — пары домов) | 291 |
| тени на кровлях (`roof shadows`) | 296 |
| экструзия (`extruded`, уже параллельна по домам) | 234 |
| развёртки (`sweeps`, параллельны) | 54 |
| арки | 6 |

То есть ~55 % лейна — **наземный union** (`shadow::push_union` →
`union_of`): свипы всех 56 тыс. домов группируются по клеткам 256 м,
клетки объединяются по потокам, результаты клеток — один финальный union
(серийный хвост). Двухуровневое слияние клеток уже замерялось против этого
и выигрыша не показало (док `union_of`) — но как делится 1.1 с между
группировкой, клетками, финалом и раскладкой в меш, не мерил никто.

`draw_order` — однопоточный: проверка пар домов (`upper`, до 16 проб на
пару) идёт серийным циклом, хотя пары независимы; результат пары пишется
по её номеру — конфликтов записи нет.

## Направление решения

1. **Разрез-отпечаток** (временные `eprintln` с меткой заезда, снятые до
   коммита; бенч — якорь, 3+ прогона в одном состоянии машины): внутри
   `union_of` — группировка с клонами, клеточный wall (по счётчикам клеток
   и контуров), финальный union; в `push_union` после union — раскладка
   (полигоны + каймы); в `roof_shadow_builder` — сетка/рамки, параллельный
   wall, заливка; в `draw_order` — `Drawn::of`, `candidate_pairs`, цикл
   пар, сортировка+топология.
2. **Кандидаты по разрезу** (каждый — отдельный коммит с замером):
   - `draw_order`: параллельный цикл пар — результаты в `Vec` по номеру
     пары (пишет одна нить), слияние в `covered` серийное; scratch —
     на нить.
   - наземный union — по цифрам разреза: плотные клетки (дробить ячейку
     группировки нельзя — граница клеток и так не влияет на геометрию,
     только на цену), финальный хвост, кайма/заливка.
   - кровельные тени — по цифрам разреза.
3. Прочее не трогать: экструзия и развёртки уже параллельны, их wall —
   дележ с дорогами, не своя цена.

## Инварианты (не трогать)

- **Геометрия — функция входа**: вершины и счётчики отчёта
  `building meshing:` бит-в-бит до/после; `road meshing:`, `osm map:`,
  `polymesh stitched` бит-в-бит (соседние лейны не тронуты — контроль).
- Детерминизм: параллельные секции сохраняют порядок входа
  (`in_parallel`), порядок вершин меша не меняется; ярды реплеев и
  `a_restart_replays_the_run` зелёные.
- Оффскрин-кадр плотного центра (4245, 2956, зум 0.4) до/после — mean
  разности (метод записи 25).
- `world reload: N scene entities survived` — 0; `panicked`/`ERROR` — 0.
- **Не трогать**: `planned/07` (кровь — чужая разведка); `map/footprint.rs`
  и `navigation/navmesh/{gates,reach,fill}.rs` (запись 26); `map/prepare.rs`
  и `map/roads/*` (запись 28); vendor-патчи полимеша (запись 29);
  `map/inspect.rs`, `map/osm/download.rs`, `src/loading.rs`,
  `map/osm/model.rs`, `map/osm/model/trees.rs` (запись 30).
- Чужие процессы не убивать: 15702 — пользователь, 15703 может быть занят
  чужой сессией; своя пара — 15704/15706.

## Шаги

1. Спека (этот файл).
2. **Worktree-пара** (прецедент записей 26–30): `.worktrees/perf21` —
   правка, базовая сторона — второй worktree на master; кеш `assets/osm/`
   **скопировать с mtime** в оба (снапшот-хиты той же выгрузки);
   `tools/seed-worktree-target.sh`.
3. **База**: бенч ×3 на сторону в одном состоянии машины; живая пара —
   3+3 тёплых старта вперемежку (`BRP_PORT=15704`/`15706`,
   `QWE_PERF_NOAPPNAP=1 QWE_PERF_NOVSYNC=1 QWE_PERF_FRAME_SPIKES=30
   caffeinate -i cargo run`, фоном; свежий процесс каждой стороны —
   холодный, в медианы не брать; сосед на `brp pause` во время
   перезагрузок измеряемой стороны), лейны — строки `map meshes:`,
   тёплый старт — снапшот-хит → `warmup:`.
4. **Разрез-отпечаток** (п. 1), снят до коммита.
5. **Фиксы** по разрезу — мелкими коммитами, каждый с замером бенча.
6. Верификация (ниже), запись 31, строки в артефакт, коммиты, заезд 22.

## Верификация

- **Бенч** `map_meshing paris` до/после в одном состоянии машины: строка
  `2.5D+shadows+tint` — целевая; соседние строки (Shadows, 2.5D, fences) —
  контроль состояния машины.
- **Живая пара** (worktree-пара одного состояния машины, 3+3 вперемежку):
  лейн `buildings`, whole set, тёплый старт.
- Отчёт `building meshing:` (вершины, счётчики) бит-в-бит во всех прогонах
  обеих сторон; `road meshing:` / `osm map:` / `polymesh stitched` — тоже.
- Оффскрин-кадр плотного центра до/после — mean разности.
- `tools/check.sh <файлы>` — зелёные: зданиевые тесты, ярды реплеев,
  `a_restart_replays_the_run`, clippy, fmt.
