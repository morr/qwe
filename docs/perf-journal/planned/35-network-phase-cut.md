## Проблема

Окно `network_time` (`src/map/roads.rs::RoadCommon::new`, от `started`
до bed caps) — серийные фазы между пулом скруглений и первой лентой:

- **init** — painter, `RutLines`, четыре `MeshBuilder`, `Bridges::new`,
  `lots::Grounds::of`, `Meadows::of` (сетка записи 45);
- **corners** — `in_parallel(steps)`: `kerb_returns` + `lay` каждой
  ступени (известно ≈245 live; бенч одной ступени 105–108 + 26–29);
- **merge_edges** — `merges::lay_merge_edges` (кромки слияний к кромке
  продолжения);
- **kerb_pockets** — `pockets::lay_kerb_pockets` (карманы у бордюра);
- **turning_circles** — `junctions::lay_turning_circles`;
- **osи и порядок** — `axes(Ribbon)` (срез Cow), ширины, `fill_order`,
  `leading`;
- **gores/rings** — `GoreRoad::new` по порядку заливки, газон и трава
  колец, `Gores::of` + splitters + forks;
- **mouths** — `mouths(...)` + `clear_crossings` (известный union ≈47,
  записи 43/44);
- **ramps** — `merges::ramps` (каркасы половин у слияний);
- **medians** — `medians::draw` + `paint_median` по нарисованным;
- **merge paint** — `nose_fill` + `merge_axis` по чистым слияниям +
  bed caps.

Сразу за окном (после `network_time`, тоже до лент): `islands::lay_areas`
(площади и островки), `lay_ring_island_bands`, `approach_flags`,
`seam_dash_gaps` — таймер даётся им отдельной группой, в сумму network не
входит.

**Не рычаги** (отмечено записями 34/39/43/44/45/46, не пытаться):

- сведение corners в один пул — отвергнуто цифрами (запись 46);
- mesh обочин 351–363 CPU — насыщенный параллель (earcut плотных лент,
  записи 45/46);
- `find`/`find_green` лоскутов 424 — насыщенный параллель (записи 34/44);
- сетки звеньев/препятствий стежков 21+16 (записи 39/44);
- итоговый union устьев 47 — однопроходный якорь дыр (записи 43/44);
- сетка `Meadows` стоит (запись 45);
- verges pool уже чанками (запись 46, live 70–95).

## Направление — разрез по фазам, фикс крупнейшего ≥150

**Разрез** (временные `eprintln`; таймеры вносятся руками — патч разреза
35 на изменённый код не накатывается, урок 44; свой патч в
`/tmp/perf37-drill.patch`, держать, пока правка не закоммичена, урок 42):

- `Instant` на каждую фазу окна выше, `eprintln` одной строкой на фазу
  (мс, wall); в конце — wall всего окна (`network_time`) и **сумма фаз
  против wall** — зазор показывает не тированную сантехнику;
- corners — одной фазой (весь пул скруглений) для якоря ≈245;
- группа «после окна, до лент» (`islands::lay_areas`,
  `lay_ring_island_bands`) — отдельно, вне суммы;
- соло-бенч `map_meshing paris` ×3 (свои живые процессы заглушены — урок
  записи 42), живой прогон — под contention фоновых лайн (как живьём
  фазы проседают в разы между прогонами — записи 42/46).

**Фикс** — крупнейший кусок ≥150 мс wall; кандидат-шаблон по прецедентам
краски 40 / ленты 42 / зелени 44 / обочин 46: если кусок — проход по
улицам/узлам с по-штучными аккумуляторами, **чанки
(`ribbon_lane::chunks` или свой разрез) + частичный вклад куска + одним
пулом `in_parallel` + раскладка аппендами в исходном порядке**; **чанки,
не по-штучные аккумуляторы** — урок записи 42. Серийные фазы-проходы по
всей сети без пер-уличной структуры — по данным разреза: сеточный
индекс, перенос под соседний параллель или отметка «не рычаг». Выходы
обязаны остаться бит-в-бит: счётчики **обеих** строк `road meshing:` —
контроль (заявленный класс перестановки тайлов — `+N` vertices, не
молчаливая смена); строка `roads` бенча бит-в-бит (различается только
build-время). Лента не пишет в `MapData` — `SNAPSHOT_VERSION` не
трогается.

**Правило выхода** (заезды 29–36): рычаг в замороженных файлах
(`map/inspect.rs`, `map/osm/download.rs`, `src/loading.rs`,
`map/osm/model.rs`, `map/osm/model/trees.rs` — запись 30), или крупнейший
кусок <150 мс wall, или цена меньше планки — плато-отметка в этой спеке
и записи 47, следующий уровень по свежему рейтингу.

## Ожидание и риски

- Цель разреза: распределить ≈535 остатка по фазам, найти крупнейший
  кусок и объяснить зазор суммы против wall; фикс снимает его
  (`map meshes: roads in`, whole set медианой живой пары, обе строки
  `road meshing:`, поле `network`).
- Ожидание: если остаток держат 1–2 фазы по >150 — кандидаты по
  прецедентам чанков; если размазан по 8+ фазам по 40–70 — плато
  (структуру окна не ломать ради ≤100 суммарно), отметка в спеке и
  записи.
- Риски: фазы окна делят уже построенные пулы потоков? Нет — окно
  серийное, кроме corners; параллелить серийную фазу безопасно, только
  если её вход — только чтение, а выход раскладывается в исходном
  порядке. Малый вход (тесты, витрины) — прежний путь: `in_parallel`
  сводит к одному потоку, чанки вырождаются в один.
