## Найдено и влито (ветка perf26, 1 коммит e849e1db → ff master; check: OK,
## cargo check --lib главного чекаута после ff — OK)

- **Единственная находка** — `ui/stats.rs::apply_seed_on_enter`: гейт ввода
  ранним return-ом (`if !keys.just_pressed(Enter) { return }`) при регистрации
  без run_if — прямо запрещённый CLAUDE.md паттерн. Переведён на
  `.run_if(input_just_pressed(KeyCode::Enter))`, параметр клавиш и ранний
  return сняты. Единственный такой сайт: остальные клавишные системы (sim_time,
  restart, quit, ui/debug, movement, shell) уже стоят на run_if, у инспектора —
  предикаты-условия.
- **Перф-вердикт**: run_if строго не дороже раннего return-а — условие с одним
  параметром против входа в систему с валидацией четырёх параметров каждый
  кадр; горячего пути не трогали, поведение не менялось. Замер и живой A/B не
  требуются.
- **Доки-двойка не нужны**: механизм UI-ввода не менялся — одна система
  приведена к канонической форме регистрации.

## Чистые зоны свипа (негативы с основаниями)

- **Time-типы — чисто.** Все 11 сайтов алиаса `Res<Time>` — симуляционные
  системы в FixedUpdate (movement: `move_moving_entities`/`separate_pawns`;
  demon: спавнер/блуждание/погоня; human: выбор целей, паника/бегство/побег,
  души). Исключения документированы в комментариях у каждого сайта:
  косметика крови — Update с виртуальным временем, камера/панель скорости/dev —
  `Time<Real>` с обоснованием на паузе. Двойная регистрация
  `pick_wander_targets` (тик + кадр) — задокументированное сознательное
  решение с обоснованием в комментарии. `Time<Virtual>`-дельт в FixedUpdate
  нет; observers время не читают.
- **UI-ввод — чисто.** Единственный читатель сырых кнопок мыши — camera.rs:
  `drag_pan` держит решение о драге в `Local` (канон «решить раз при нажатии»),
  `zoom_to_cursor` под `run_if(not(hovering_ui))`, гейт общий с витринами
  через публичный `hovering_ui`. Панельные строки читают `Pointer<Click>` —
  гейта не требуют.
- **Деспаун-сайты — чисто.** Пешки деспаунятся только в FixedUpdate (побег,
  души) и PreUpdate (рестарт по R). Деспауны в Update (кроны деревьев,
  перестройки слоёв карты, оверлеи, UI-строки) деспаунят собственные
  сущности — их id не naming-цели ничьих пешечных буферов, а спавн и деспаун
  идут из одной системы. Держать правило в голове при появлении новых
  пешечных систем.
