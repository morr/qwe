# Запланировано 25 — деревья парса: разрез 0.62 с посадки и фикс

Приоритет: **1** — запись 36: деревья парса — **0.624 с из 3.69 с parse-стены
Парижа (17 %)**, крупнейшая помеченная фаза парса после карманов (взятых
заездом 26). Заезд 27. Платится на первом прогоне города и после бампа
`QUERY_VERSION` (парс при промахе кеша; снапшот `s2` после парса
переписывается).

## Проблема

Parse-стена Парижа — 3.69 с после заезда 26; из них **посадка деревьев —
0.624 с**. Остальные помеченные фазы — сотни миллисекунд и меньше (corners
внутри карманов 0.417 — машина `kerb_returns` с пином нарисованных вееров,
дома-с-тротуаров 0.229, блоки-к-дорогам 0.192, footway-стороны 0.191, скверы
0.136, входы 0.134, парковки 0.134); на непомеченное — ≈1 с.

Проход один — `map/osm/planting.rs::plant_trees` (посадка; **не**
`map/osm/model/trees.rs` — тот заморожен записью 30), тайминг снимается одной
строкой на весь проход. Внутри:

1. `Obstacles::build` (`planting/index.rs`) — пять индексов близости на сетке
   32 м: здания (AABB с паддингом кроны), дороги — **по отрезкам**, каждый с
   паддингом `width/2 + TREE_MAX_RADIUS + TREE_KERB_CLEARANCE` (≈8–13 м),
   вода, русла, голые полигоны (grass + sand). Дороги — десятки тысяч
   отрезков, каждый кладётся во все ячейки раздутого AABB.
2. `plant_standalone` — одиночные ноды: точка в лесах и у аллей через сетки,
   `solid` + `on_road` + `crowded`.
3. `plant_woods` — rejection-sampling: `count = площадь·6.35/410` деревьев на
   лес, до `count·60` попыток; каждая — `point_in_area` по контуру леса
   (контур большого леса — тысячи вершин) + `blocked` (дома —
   `distance_to_outline` по всему контуру, дороги — `distance_to_segment`,
   голые полигоны — `point_in_area`).
4. `plant_rows` ×4 раскладки (`TreeRowLayout::ALL`, свой `occupied.clone()` на
   каждую): слоты по `scattered_ranks`, позиция — `point_at_arc_length`
   (линейный проход с начала ломаной на каждый слот), `free_spot` с полной
   проверкой на `Slide`.

## Направление — сначала разрез, фиксы по факту

Разрез (временные `eprintln`, снятые до коммитов, патч в `/tmp`): таймеры
`Obstacles::build` (по каждому индексу) и трёх посадок; в лесу — попытки/
отказы/принятые и число вершин контура (контур-монстр виден сразу); в рядах —
слоты и вставшие. Кандидаты фикса — по убыванию ожидания, уточняются
разрезом:

- **`plant_woods`** — попытки × `point_in_area` по большим контурам лесов:
  индекс рёбер леса по y-полосам (пересечение горизонтали — точный и дешёвый
  запрос вместо полного прохода по контуру на каждую попытку).
- **`Obstacles::build`** — road_index: клонирование отрезков по ячейкам
  раздутого AABB, паддинг.
- **`blocked`/`solid` на попытку** — `distance_to_outline` по всему контуру
  дома: выборка рёбер через ту же сетку, что и у леса.
- **`plant_rows`** — `point_at_arc_length` с начала ломаной: префиксные
  накопленные длины.

## Ожидание и риски

- Цель: посадка 0.624 → ≤0.4 с медианой живой пары, parse-стена 3.69 → ≈3.5.
  Обещать больше без разреза нельзя.
- **Правило выхода** (заезд 27): если разрез покажет, что рычаг в замороженных
  файлах (см. запреты ниже) или вся фаза стоит меньше 150 мс — направление
  закрывается, берётся следующая по рейтингу фаза (непомеченное ≈1 с — разрез
  всего парса), и это фиксируется в этой спеке и записи 37.
- Риски: наборы деревьев (лес, одиночные, аллеи под каждой раскладкой)
  обязаны остаться теми же — индексы близости внутренние, менять можно;
  предикаты (`solid`/`blocked`/`on_road`/`crowded`) обязаны отвечать то же
  самое на то же место. Порядок попыток посадки не менять — он и есть
  детерминизм набора.
