# 60. Floods шага калиток — в два потока

Дата: 2026-11-20 (Обзор №17). Хвост записи 59: floods 78 мс — два полных
обхода сетки (достижимое и достижимое без оград), которые ничего не делят.

## Что было

Голова `open_sealed_fences` (`gates.rs`) до раундов:

1. `flood(&self.passable, reachable, [start])` — достижимое с оградами;
2. `reachable_bare = reachable.clone()`;
3. полный проход по сетке за seed-ами: тайлы, закрытые только оградой
   (`fenced`) и касающиеся `reachable`;
4. `flood(&bare.passable, reachable_bare, seeds)` — достижимое без оград.

Шаги 2–3 существовали ради зависимости: второй обход стартовал из
ограждённой компоненты. Но та же достижимость без оград — это просто
**bare-компонента портала**: `bare.passable ⊇ passable`, поэтому ограждённая
компонента лежит в ней целиком, а тайл bare-компоненты вне её примыкает к ней
через тайл, закрытый только оградой, — ровно то множество, которое собирал
скан seed-ов (путь по bare-проходимым тайлам до первого тайла вне
ограждённой компоненты — это seed; хвост пути лежит в его bare-компоненте).
Значит оба обхода можно стартовать от портала — и они становятся независимы.

## Что стало

Оба `flood` идут параллельно в `thread::scope`, каждый пишет свой буфер —
результат не зависит от планирования. Скан seed-ов (полный проход по сетке с
проверкой соседей у каждого оградного тайла) и клон `reachable` (мегабайты)
ушли вместе с зависимостью. Вырожденный случай — непроходимый стартовый тайл
(снап вернул сырую подсказку) — сохранён гардом: тогда оба набора пусты, как
и раньше (seed не проходит проверку `passable`).

снапшот-хит, сохранённый вид владельца zoom 0.4, `QWE_PERF_NOAPPNAP=1`,
порт 15703; база — perf16 (master a38c3d35), код — perf17. Мерялась строка
шага `navmesh: opened … fence gates in …`.

- база (8 значений): 257.0–271.3, среднее **262.4** мс;
- новый (8 значений): 228.5–243.7, среднее **233.7** мс;
- **−28.7 мс (−11 %)**, разделение полное (минимум базы 257.0 выше максимума
  нового 243.7).

Тула тем же протоколом (по 3 загрузки на сторону): 158.2–161.1 →
139.3–143.1, **−18.8 мс (−12 %)** — эффект не парижская специфика.

Окно snapshot→warmup (Париж, по таймстемпам): база 4.48–4.55 с, новый
4.46–4.57 с — в шуме; окно доминируют лейны мешинга (урок №16: −111 мс шага
дали −0.07 с окна), −29 мс в нём не видны. Признак «регрессии нет».

Меньше теоретической половины (78/2 ≈ 39 мс + скан с клоном) потому, что

пропускную способность, ускорение заметно меньше 2×; скан seed-ов и клон
добавили несколько мс сверху.
