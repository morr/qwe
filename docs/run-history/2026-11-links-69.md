## Угол и что снято

- Домен читался целиком, по инвариантам, а не по файлам. **Захват целей**:
  `acquire_pass` — общий проход для детерминированного `acquire_targets` и живых
  четвертей `acquire_slice::<S>` (`DemonSlice<S>`, `PawnId % 4`, период
  `ACQUIRE_SLICE_TICKS`); заявки `ChaseTarget`, места `ChaseClaims` — не больше
  двух преследователей на жертву, место освобождает только `GaveUp`, смена
  жертвы — переносом. **Лестница погони** (`decide.rs`): чистая функция над
  `ChaseSense`, ответом прямой видимости и «есть ли жертва лучше» — `LostTarget`,
  `GaveUp`, `Kill`, `Lunge`, `WaitForPath`, `Hold`, `Repath`, `Switch`; троттл
  `ChaseRepath` (`DEMON_CHASE_REPATH` = 0.4 с), заморозка таймера после броска.
  **Спавнер и орда**: общий кап `DemonStyle::cap()`, очередь обязательств,
  волны из чистого потока `stream(seed, Demon, HORDE_WAVE_KEY + wave_index)`,
  усечение волны до свободного места после розыгрыша.
- **Швы с движением**: `MovableState::needs_path()` = только
  `Idle | PathfindingError`; идущий (`Moving`) не даёт ни `repath_due`, ни
  `needs_path`; спасение `rescue_from_impassable` / `rescue_trapped_entities`;
  обсёрверы сеток (`spatial.rs`) читают `Transform`; пульс и сброс масштаба
  пожирания против `resize_silhouettes_on_zoom` (пишет `Sprite`, не
  `Transform.scale`); портал — `DespawnOnExit` на месте.
- Что держится (негативы с причиной): инварианты заявок — место освобождается
  только сдачей, выход из погони снимает набор `ChaseComponents` целиком;
  спавнер и орда считают под одним капом, волна режется до свободного места
  после розыгрыша; демоны попадают в сетку демонов на тике рождения;
  `WaitForPath` охраняется кулдауном; масштаб пожирания не воюет с зумом
  (писатели разные); портал уходит со сценой. Спасение застрявших для демона
  безвредно: после `to_idle` погоня перепрокладывается через первый путь.

## Находки и фиксы

- **Демон, взявший жертву на ходу, до целого троттла шёл прочь от неё**
  (`76145796`): захват ставил свежий `ChaseRepath`, а идущему (`Moving`)
  лестница отвечает `Hold` — у него нет ни `repath_due`, ни `needs_path`.
  Первый путь к жертве выходил через `DEMON_CHASE_REPATH` = 0.4 с (≈ 5.6 м при
  14.04 м/с) по старому блуждающему отрезку. Человеческая сторона чинила то же
  в `ed7a81ad` (`panic` ставит `FleeRepath` почти истёкшим через
  `almost_finish`) — теперь `acquire_pass` так же ставит `ChaseRepath`:
  **первый путь погони уходит в тик захвата**. Демон, ждавший своей очереди
  поиска в `Pathfinding`, отвечает `WaitForPath`, а путь к жертве уходит первым
  же тиком после блуждающего ответа. Два пина в `behavior.rs` (двор
  `acquire_app`, помощники `spawn_walker` / `tick_by`):
  `a_demon_taking_aggro_on_the_move_turns_toward_its_victim_at_once` (до фикса
  красный — конец пути `IVec2(-100, 5)` прочь вместо `IVec2(20, 5)` к жертве)
  и `a_demon_that_waited_for_its_search_turns_the_tick_that_search_lands`.
  Док-твины той же правкой: CONTEXT.md (запись демона) и species-behavior
  (абзац о первом пути погони, список полей с клампом на чтении, абзац о
  троттле). `decisions.md` не трогал — механика одного модуля.
  **Влияние на баланс: погони сходятся до 0.4 с раньше** — доложено владельцу
  здесь, отдельного решения не заводил.
- **Размер волны орды читался без клампа** (`44c4ee3b`): `plan_wave` заказывал
  `Vec::with_capacity(wave_size)` и крутил разброс до усечения по капу —
  значение за пределами шкалы слайдера (BRP-запись; из файла приходит не больше
  `i64::MAX`) планировало миллиарды точек выпуска под блокировкой навмеша.
  Падение тут не гарантировано: на этой машине `Vec::with_capacity(1e12)`
  успешен (ленивая память macOS, проверено отдельной программой), «capacity
  overflow» даёт только значение за пределами `isize`; средние — не паника, а
  висон под блокировкой и смерть по памяти. Фикс: акцессор
  `HordeStyle::wave_size()` с клампом к `WAVE_SIZE_MAX` (2000), по образцу
  `DemonStyle::cap()` и `HordeStyle::wave_every()`; ноль по-прежнему значит
  «волн нет» (`play_waves` сразу отпускает расписание). Пины:
  `wave_size_clamps_garbage_to_the_slider_scale` (components.rs),
  `a_garbage_wave_size_releases_only_the_free_room` (horde.rs: `usize::MAX`
  при капе `DEMON_INITIAL_BURST + 4` выпускает ровно по капу). Живьём с
  клампом: `wave_size=1e12` по BRP — волна 2000 (демонов 190 → 2303), паник 0.
- **Найдено и отложено — запись настроек падает на беззнаковом 64-битном
  поле**: `brp res set HordeStyle .wave_size 18446744073709551615` роняет
  приложение не в потребителе, а при сохранении — `prefs.rs::save_prefs`
  ставит команду библиотеки `SaveSettingsSync::IfChanged`, внутри неё
  `toml::Value::try_from(serializer).unwrap()` (bevy-settings 0.20.1, lib.rs:464)
  паникует «u64 value was too large», exit 101. Класс общий для любого поля
  `usize`/`u64` любой группы настроек, вход только через BRP. Рецепт и триггер —
  в deepening-plan («Обзор №69»): рефлексивный санитайзер в `prefs.rs` с ребром
  `.before(save_prefs)`, нужен скилл `ui-panels`.
- **Отложено — погоня за недостижимой жертвой идёт без троттла** (статикой):
  `decide` считает `PathfindingError` за «пути нет» и отвечает `Repath` мимо
  таймера (пин `a_lost_path_repaths_without_waiting_for_the_timer` держит это
  как норму), так что демон у границы компонент меша (разрез №65) делает по
  неудачному поиску на каждый оборот ответа, пока жертва в кольце 67.5 м.
  Лечение — поведение (сдача при ошибке поиска либо ошибка под тем же
  троттлом), меняет баланс живого мира — решение владельца. Цена петли не
  снята: один сэмпл живьём в молодом мире — 0 из 408 преследующих стоят в
  `PathfindingError`; под штормом и в старом мире не мерилось.
- **Устаревший указатель в плане**: рецепт «Разреза №44б» ссылался на ворктри
  perf43 с полным прибором — тот удалён ещё до №49; помечен в deepening-plan,
  прибор для разреза собирается заново.
