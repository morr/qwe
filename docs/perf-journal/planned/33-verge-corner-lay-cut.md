# Запланировано 33 — цена самих фаз стен дорожной лайны: разрез `street_verge_geometry` и `lay`, фикс крупнейшего ≥150

Приоритет: **1** — заезд 35, разрез-заезд по рейтингу записи 44. После
фикса префикса финала (запись 44: finish0 677 → 604, бенч −66, whole set
2.8 → 2.7) в дорожной лайне остались стены, у которых разреза внутри нет:
**verges_prep** (`street_verge_geometry` 107–114 на ступень; live 177 —
два серийных прохода по ступеням) и **corners** (≈199 на ступень; live
corners0 381.9 — вложенный параллель двух ступеней, два × 10 потоков на
10 ядрах). Рядом — layout ленты 46 и nodal-стены `Drawn::new` ≈100.

## Проблема

Стены без свежего разреза внутри (бенч `map_meshing paris` записи 44,
числа под contention живой пары):

- **verges_prep 107–114 на ступень** — обочины по улицам в потоках на
  каждую ступень (`map/roads.rs` ~1097–1115 → `verges::
  street_verge_geometry` через `in_parallel(&order)`); внешние проходы по
  ступеням серийные (live: ступень 0 116.1 + ступень 1 61.3). Внутри
  по-уличного прохода разреза нет — не измерено, что держит число:
  запросы (`rings().of`, `verges_drawn`, `road_bites.on_points`,
  `bridges::seam_ends`, `Meadows::beside`), профиль (`densify`,
  `arclengths`, `verge_at`, `verge_runs`, `miter_offsets`), меш
  (`push_polygon`/`push_ribbon_trimmed` — earcutr по плотным лентам),
  лоскуты (`push_paving_band`/`push_lawn_band`), куски.
- **corners ≈199 на ступень** — скругления ступеней
  (`map/roads.rs::RoadCommon::new` ~837–870, по ядру на ступень через
  `in_parallel(steps)`): `kerb_returns` (вклады/частичные — `in_parallel`,
  разрезаны записью 44) + **`KerbReturns::lay` 81–83 серийная укладка**.
  Укладка — веера в свои слои (`push_convex`), группы в лоскуты
  (`scraps.push_lawn` — клон контура), `meadows.under` для газонов углов,
  носы/дуги триангуляцией целиком (`push_polygon` — earcutr), `pieces`.
- Вложенный параллель ступеней: `in_parallel(steps, …)` с двумя ступенями
  — два потока, каждый разводит свой `in_parallel` на ~10 потоков → два ×
  10 на 10 ядрах; сведение в один пул оценивается в ~−80 wall (запись 44).
- layout ленты 46 (appends 18 / verges_apply 24 / bridges 1.9 — запись 42)
  и nodal-стены `Drawn::new` ≈100 (RoadNodes 28–30, paths+pairs ~40, align
  11–22, tail 20–36 live — записи 39/44): разрезы есть, куски < планки.

**Не рычаги** (отмечено записями 34/39/43/44, не пытаться):

- `find`/`find_green` лоскутов 424 — насыщенный параллель (CPU ≈ 4300 /
  10 ядер), батчинг опровергнут цифрами (записи 34/44), геометрия не
  держит бит-в-бит;
- сетки звеньев/препятствий стежков 21+16 — порядок вставки пинит
  `near_each` и выбор стыка на ничьих (записи 39/44);
- итоговый union устьев 47 — однопроходный якорь дыр (записи 43/44);
- клоны финала — сняты записью 44 (`in_parallel_owned`, уклады уходят
  `mem::take`-ом).

## Направление — разрез фаз, фикс крупнейшего ≥150

**Разрез** (временные `eprintln`, патч в `/tmp` **до** любого отката и до
коммитов — держать, пока правка не закоммичена, урок записи 42;
re-drill на изменённый код патчем не накатывается — таймеры «кусков
после» вносятся руками, урок записи 44):

- `street_verge_geometry` — фазы по-уличного прохода: запросы (rings,
  `verges_drawn`, bites, seam, `meadows.beside`) / профиль (densify,
  arclengths, `verge_at`, `verge_runs`, miter) / меш (push_polygon,
  `push_ribbon_trimmed`) / лоскуты (bands) / куски. Сумма CPU по улицам —
  аккумуляторы (соль или возвращаемое), wall прохода — снаружи; соло-бенч
  ×3, живой прогон — под contention;
- `KerbReturns::lay` — фазы укладки: push_lawn (лоскуты) / push_convex по
  группам (roads/unpaved/sidewalks/overlaps/verges/verge_lawns) /
  `meadows.under` / носы и дуги (`push_polygon`) / pieces;
- внешние стены под нынешним контеншном: corners (вложенный параллель),
  verges_prep (два прохода), layout ленты — свежие live-числа.

**Фикс** — крупнейший кусок ≥150 мс, по шаблону `in_parallel`/
`in_parallel_owned` (`map/parallel.rs`): чанки + частичный аккумулятор +
раскладка в исходном порядке (прецеденты: краска узлов 40, лента 42).
**ЧАНКИ, не по-штучные аккумуляторы** — урок записи 42. Кандидаты по
текущим знаниям:

- **lay чанками**: частичные сборщики слоёв + `Scraps` + pieces по чанку
  контуров, аппенды в исходном порядке (порядок укладки — инвариант
  `corners::lay` — сохраняется чанками); `meadows.under` — `&self`, в
  потоках безопасно;
- **`Meadows::covers` — линейный проход по всем `parks`+`grass`** на
  каждый вопрос (`beside` — до 6 `covers`, `under` — по всем вершинам
  угла): сетка по габаритам (`Grid`), как `Scraps::near_lawn` — ответ
  bool, порядок обхода не важен, бит-в-бит безопасно;
- сведение вложенного параллеля ступеней в один пул (~−80 wall по оценке
  записи 44) — ниже планки отдельно, кандидат в паре с lay.

Выходы обязаны остаться бит-в-бит: счётчики **обеих** строк
`road meshing:` — контроль (заявленный класс перестановки тайлов — `+N`
vertices, не молчаливая смена). Лента не пишет в `MapData` —
`SNAPSHOT_VERSION` не трогается.

**Правило выхода** (заезды 29–34): рычаг в замороженных файлах
(`map/inspect.rs`, `map/osm/download.rs`, `src/loading.rs`,
`map/osm/model.rs`, `map/osm/model/trees.rs` — запись 30), или крупнейшая
фаза <150 мс, или цена меньше планки — следующая по рейтингу фаза записи
44 (nodal-стены RoadNodes / paths+pairs; layout ленты appends 18 /
verges_apply 24) и отметка в этой спеке и записи 45.

## Ожидание и риски

**Итог разреза (заезд 35, соло-бенч ×3, разброс 1–4 %)** — серийного
куска ≥150 нет: lay 84 (из них `meadows.under` 52.5), verges prep 114
(meadows CPU 176 — второй кусок после меша), mesh 366 CPU — насыщенный
параллель по улицам (earcut плотных лент, как `find` записи 34 — не
рычаг), seam 24 CPU, layout 48, returns 116–123. Крупнейший снимаемый
кусок — **линейные проходы `Meadows::covers` ≈230** (52.5 серийно в
`lay` ×2 ступени + 176 CPU в `beside` на ступень): фикс — сетка по
габаритам, ответ bool порядок не читает. Wall-выигрыш по бенчу −66
(roads-строка 1524.7 → 1458.8) — ниже планки ≥150 по wall, но это
крупнейший кусок свежего рейтинга и он взят: альтернативы — nodal-стены
(куски 30–65, структурно серийные) и сведение вложенного параллеля
(~−80 wall), оба меньше. Отметка правила выхода здесь и в записи 45.

- Цель: разрез закрывает `street_verge_geometry` и `lay` фазами со
  свежим рейтингом; фикс снимает крупнейший кусок
  (`map meshes: roads in`, whole set медианой живой пары, обе строки
  `road meshing:`). Числа стен — под contention; соло существенно
  меньше, обещать больше разреза нельзя.
- Эквивалентность: счётчики обеих строк `road meshing:` бит-в-бит во
  всех прогонах обеих сторон; строка `roads` бенча бит-в-бит (различается
  только build-время); `SNAPSHOT_VERSION` не трогается.
- Риски: если разрез покажет, что стены держит earcut плотных лент
  (`push_polygon`) — насыщенный параллель по улицам уже есть, рычага нет
  (как `find` записи 34) и фикс уйдёт к следующей фазе по правилу выхода;
  сетка `Meadows` меняет порядок `covers` — bool-ответ порядок не
  читает, но счётчики контролируют; порядок укладки `corners::lay` —
  инвариант модуля, чанки сохраняют его внутри каждой группы.
- Витрины и бенчи (`build_roads_from`, `map_meshing`) идут через ту же
  сборку — их отчёты остаются контролем; малый вход (тесты) — прежний
  путь, тот же байт в байт.
