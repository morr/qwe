## Уроки живых замеров

**`QWE_PERF_NOAPPNAP=1` обязателен в строке запуска** (№19: без него процесс
деградировал в App Nap посреди серии — все потоки T в ps -M, загрузки в 2.4–2.7×
медленнее с третьей-четвёртой; диагностика — резкий скачок ВСЕХ шагов загрузки между
соседними загрузками; четыре замера выброшены); **`pwd &&` — в самой команде запуска
приложения** (№19: cd ворктриа в фоновом build-задании не персистентен — «сторона A»
снята с чужого бинарника; числа переклеены, но урок дорогой); `$b ready <log>` после
первой загрузки всегда «готов» — для серий переключений ждать НОВУЮ строку warmup
(grep-счёт до/после), иначе `res set City` гейтится в Loading и переключение теряется
молча; **.settings перезаписывается на выходе приложения — город последней загрузки
становится стартовым, первая строка «navmesh filled in» серии бывает Парижем, а не
Тула-выбросом** (№19); после тёплой сборки ready может вернуть «готов» мгновенно, а
первая загрузка — уехать до вызова: окно по таймстемпам считай только между
строками, которые точно после старта запуска; никаких параллельных компиляций при
живых замерах (check.sh рядом замедлял загрузки 10×); `algorithm=Hpa` в сохранённых
настройках запускает сборку northstar (22–28 с) после каждого входа в Live — для серий
переключений ставить `res set PathfindingAlgorithm . '"Astar"'` сразу после первого
ready (для одиночных стартовых загрузок не нужно); после warmup/pause `res get
SimSpeed` читается в переходном состоянии — бери steady-state из строки `brp run`
(actual Nx) и счётчик `frame spike`; pgrep по полному пути ворктриа не находит процесс
(argv[0] относительный), pid брать у `$b alive`; check.sh не принимает Cargo.toml и
.md (rustfmt падает E0758); окно snapshot→warmup шумнее отдельного шага: −111 мс шага
дали −0.07 с окна, −29 мс шага не видны вовсе — меряй целевой шаг по его строке
лога, окно — как вторичный признак; вид владельца (Париж, zoom 0.4, Astar)
настраивается одним прогоном базы: системный settings.toml перезаписывается на
выходе, worktree при первом запуске сеется из него
(`prefs.rs::seed_worktree_settings`) — у сторон A/B файлы идентичны без ручной
возни (№21);
**отчёт слоя печатает Duration Debug-ом: под секундой — `966.271583ms`, над —
`1.072s`**, грепай `in [0-9.]+m?s`, а не `in [0-9.]+s` (№21: первая серия стороны
B выглядела одной строкой из шести);
**RSS-сэмплирование — пауза сразу после warmup и фикс-стабилизация 5–6 c**:
первые секунды после Live догружают меши в GPU (+1.3–1.6G за секунды), без
паузы и стабилизации кривая шумит на ±1.4G (№23: «низкие» первые загрузки
оказались недосэмплированными, не эффектом зонда); реальная цена города —
dirty-footprint `vmmap --summary`, разрыв ps-RSS↔footprint — MADV_FREE'd
свободные страницы; `heap -addresses all` печатает строки `addr: тип (N
bytes)`, у Rust-аллокаций тип `non-object` — гистограммы только по размерам;
**статусы двух чекаутов — порознь**: склеенный вывод двух `git status` в одном
вызове читается как один (№23: Edit по пути главного чекаута прочитан как
worktree-правка, врезка в бинарь не попала — укус №5/№14 с изгибом);
**`res set City` тем же городом триггерит перезагрузку** (`retuned` = is_changed &&
!is_added) — серию загрузок одного города можно гнать без переключений на другой
город; **дрейф машины между сессиями больше разброса внутри сессии** — A/B сравнивай
только чередованием внутри одной сессии; временные таймерные врезки снимай ДО
коммита, и помни: повторные Edit с одним анкором дублируют блок (grep 'TEMP' перед
коммитом).

**счёт загрузок в пробе веди от строк лога после старта запуска** (№30): свой же
`res set City` — в том числе тем же городом — даёт загрузку, неотличимую в счёте
от «второй загрузки»; стартовый город после любого выхода приложения — город
последней загрузки, не тот, что в стандартном settings.toml, так что проба
«стартует Парижем, потом переключаю» может стартовать уже целевым городом и
сама съесть свой яд до всякого переключения; проверки файлов после `cd` в
worktree — только по абсолютным путям (греппы по относительному NOTES.md
читают копию ворктриа, №30).

**сэмплер CPU — pid фиксировать до серии, не резолвить в цикле** (№36):
`lsof -ti tcp:15703` каждые 0.5 с (сканирует все процессы) уронил живое
приложение в 3–7-секундные разрывы между кадрами на ВСЁ время серии; после
pkill сэмплера разрывы исчезли мгновенно. Порядок: `$b alive` → pid → цикл
только на `ps -o time=` + `ps -M` (как в первой серии звена — безопасно).

**бенч map_meshing между сессиями плавает сильнее живых окон** (№36):
fences 1752–2159 и road 1.52–1.96 против баз №35 (1083 / 1.09) при чистых
канарейках живого приложения того же кода; caffeinate бенчу не помогает —
сравнивать пары внутри сессии, между сессиями — только относительную
структуру слоёв.

**здоровье машины при живых замерах проверять ДО серии** (№31): `res get
SimSpeed` на Париже Astar несёт affordable 20+; обвал affordable (№31: 0.56 при
requested 1.0) — машина под внешней нагрузкой (в ps — ZCode GPU-процесс 43.7 %
+ opendirectoryd 36 %), рамочные замеры после такого момента — мусор (спайки
100–400 мс на паузе, кадр 4.1 с); доверять можно только учётке по таймстемпам
строк лога; ранние замеры той же сессии, сошедшиеся с известными базами
записей 61–63, остаются валидными. Деградация приходит волнами, привязанными
к активности собственной сессии (ZCode Helper 51 %; №33: из четырёх запусков
два деградировали ×25–100 разом при живом NOAPPNAP+caffeinate, два — чистые);
канарейки-шаги загрузки (снапшот-рид ~92 мс, fill ~137 мс) различают
мгновенно; **loadavg не показателен** — на 14-дневном аптайме читал 150–160
при 5 бегущих процессах и 85 % idle (№33); **деградация бывает внешней и
именованной: XProtectRemediatorPirrit (периодический скан macOS) жрал 72–93 %
CPU ~15 минут и вздул все шаги загрузки ×3–4** (№34, прогон выброшен
целиком) — перед серией и между прогонами проверять ps на не-своих
пожирателях и ждать их конца; бинарь напрямую не запускать
(«no LC_RPATH's found» — только через cargo run), якорь спавна — pgrep-поллер
с gdate (у BSD date нет %N).

**первый запуск свежего ворктриа — прогон целиком испорчен** (№35): холодный
кеш снапшота (рид 165 мс против 92) + сборка бинаря перед стартом + сидинг
настроек — выкидывать прогон, второй запуск ворктриа уже чистый; вид

(`START_ZOOM` = 0.4, так что переключение города само даёт вид владельца).

**перед пробой перф-темы читать ЕЁ запись журнала, не только README-хвост** (№37,
дорогое переоткрытие): README до записи 67 — указатель, а вердикты по темам
лежат в самих записях; угол «предфильтр клипа находки лоскутов» был закрыт

**soak на живой агентской машине contaminated по определению** (№40):

**смена `[profile.dev] opt-level` не инвалидирует cargo-кеш сама по себе**
