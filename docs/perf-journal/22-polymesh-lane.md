# Запись 22 — полимеш-дорожка: бордюры мостов по рамкам, чанки по потокам — 4.6 → 2.6 с, тёплый старт 8.1 → 7.0 с

Статус: фикс заезда 12 (`planned/10-polymesh-lane.md`) · замеры живого Парижа
(три базовых и два чистых правочных прогона, снапшот-хиты, одно состояние
машины под `caffeinate -i`, `QWE_PERF_NOAPPNAP=1`/`NOVSYNC`), офлайн-бенч

CDT ~1.2, merge ~1.6 мс — ровно, без доминанты.

**Правки — две:**

1. **Бордюры мостов — разность по рамкам.** Вычитать стоит только ленты,
   чья рамка задевает бордюры моста: разность с непересекающейся лентой —
   тождество. Отбор — рамки колец с запасом `JOIN_EPSILON` (тот же, которым
   `CurbCoverage` судит соседство ways одного физического моста; способы
   одного composite-моста рамками перекрываются всегда). Нет пересекающихся
   — бордюры идут в блокирующие без оверлея. Заодно список лент выровнен по
   мостам (`Option` на мост вместо `filter_map`-сборки): старый код
   исключал «себя» по индексу `bridges` в списке, собранном `filter_map`-ом,
   — при упавшей `ribbon_outline` индексы разъезжались и вычиталась чужая
   полоса. 1213 → **22 мс**.
2. **Чанки — `map::parallel::in_parallel`** (прецедент записи 19): входы
   чанка — только чтение (`contours`, `seams`, прямоугольник), порядок
   результатов — порядок индексов чанков (слои в меше идут в порядке
   индексов: 8-битный индекс слоя полианьи, граф компонентов, коридор).
   Отмена — проверка перед чанком, как у последовательного цикла (работник
   видит флаг, взяв следующий чанк; асинхронный панельный путь сохраняет
   supersede-семантику). 947 → **378 мс**.

**Цена и отвергнутое:**

- **Тайловое разложение большого boolean (0.8–1.05), клипа карты (0.4–0.6)
  и разности заборов (0.35–0.42)** по прецеденту `push_union` — не взято:
  после двух правок полимеш (2.6–3.0) ниже новой стены whole set (дороги,
  3.7–3.8), выигрыш тёплому старту не достаётся, а цена — дрейф вершин у
  границ клеток: результат едет в CDT и в раздувание, где сшивка и швы
  чувствительны к геометрии тоньше, чем в теневом union. Пунктир — если
  когда-нибудь станет узко живое пересборка радиусом (`sync_polymesh_build`,
  ~5–20 с на Туле): там эти фазы те же.
- **Пофильтрованная разность заборов по одному забору** не пробовалась:
  7080 мелких `i_overlay`-вызовов вместо одного — накладные расходы вызова
  съедают выигрыш; проём одного забора может задевать полосу соседнего
  (глобальная маска), пер-заборная семантика не эквивалентна.

**Метод.**

- Прогон: `BRP_PORT=15703 QWE_PERF_NOAPPNAP=1 QWE_PERF_NOVSYNC=1
  QWE_PERF_FRAME_SPIKES=30 caffeinate -i cargo run`, фоном; тёплый старт —
  по таймстампам строк лога (снапшот-хит → `warmup:`), лейн — строка
  `map meshes: polymesh in …`, фазы — строки `polymesh chunked / baked /
  stitched` плюс временные `eprintln` (`polymesh PHASE …`, второй раунд —
  `polymesh DRILL …`), снятые `git`-диффом до коммита. Перезагрузка города —
  `brp res set City . '"Paris"'`.
- Офлайн-якорь — `caffeinate -i cargo run --example polymesh_bench -- 500
  0.2`: время постройки и разбор запросов без окна (Тула), тем же
  состоянием машины, что и живые прогоны.
- Верификация геометрии без скриншот-пар: семантические счётчики меша
  (`seam vertices` / `component nodes` / `edges`, бит-в-бит) и счётчик
  полигонов (микродрейф — вслух).
