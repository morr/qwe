**Было.** Запись 50 закрыла рантайм на планке 150 плато и оставила два

**Вердикт по post: это движковая цена кадра bevy 0.20** — новая
архитектура экстракции (`bevy_extract`, скретч-мир) гоняет экстракцию
рендера и синхронизацию миров на воркерах, главная нить ждёт; стены
probe-ов при этом **врут** — exclusive-probe ждёт всего concurrently
исполняющегося, и слабый порядок `chain_weak` UI-сетов даёт системам
идти вперемешку с экстракцией, размазывая её по всем стенам (в том
числе по «UI-кускам»). Рычага на app-уровне нет: масштабирует счёт
извлекаемых сущностей, а 20k пешек — сама игра. Запись 50 атрибуировала
этот кусок как «движковый PostUpdate» без разреза — теперь он разрезан.

**Метод** (новое к методу записей 36–50):

- **probe-скобки обязаны гейтиться** (`QWE_PERF_CUT_PROBES`): 19
  exclusive sync-точек на кадр сами стоят стену — разрез без проверки
  «а что без проб» нельзя верить (пара no-UI с пробами и без дала
  одинаковый post 2.04);
- **стена probe'а врут при конкурентных системах**: exclusive-probe ждёт
  дренажа всего executor'а; точная скобка вокруг системы меряет её плюс
  конкурентный хвост — для атрибуции сравнивать «с системой» против
  «без» (деспавн/гейт плагина), не скобки между собой;
- **macOS `sample <pid> 4 -file …`** — дешёвый профайлер без правок кода:
  назвал парк главной нити в executor'е и extract на воркерах за один
  прогон;
- **TEMP-патч записи 50 в `/tmp/perf40-cut.patch` — битый вариант**:
  делит каждую запись `TickSegments` на тики (занижение ×16 при 16
  тиках/кадр); правильный — сумма записей по имени, делённая на тики
  (`/tmp/perf41-temp.patch`); урок записи 50 про «делить нельзя» был
  про это же;
- **счётчики команд** (`cmd cut`) — дешёвый объёмный разрез GAP: статики
  Relaxed на местах команд + печать дельт раз в секунду; против BRP-
  дельт — перекрёстная проверка без правок;
- `brp` принимает только числовые id — `593v0` это просто `593`; вид
  `Entity 4294966702v0` в ошибке = id был выдуман (один деспавн
  ресурсной сущности уронил приложение — проверять `brp get <id>` до
  деспавна);
- `brp quit` — с проверкой `pgrep`; после каждого гашения пусто
  (урок записи 49 без новых инцидентов).
