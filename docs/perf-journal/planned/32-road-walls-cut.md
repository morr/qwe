# Запланировано 32 — стены уже-параллельных кусков дорожной лайны: разрез `finish_split` / `corners_steps` / `verges_prep` и фаз, фикс крупнейшего ≥150

Приоритет: **1** — заезд 34, разрез-заезд по рейтингу записи 43. Дорожная
лайна тёплого старта Парижа остаётся критическим путём whole set (2.8 у фикса
записи 43 против 3.0 у базы; скелет «перед лентами» 736 против 946; mesh-строки
2.219/1.693 против 2.380/1.830). Крупнейшие серийные куски разрезаны и
параллелены записями 39–43; следующий уровень — **стены уже-параллельных
кусков**: у каждого свои внутренние фазы, разреза внутри них нет.

## Проблема

Стены (intraprocess-стенд записи 40, под contention живой пары — соло меньше;
свежих разрезов внутри нет ни у одной):

- **`finish_split` 806–1000** — финал ступени сплит-двери
  (`map/roads.rs::build_roads_steps` → `finish_step_split`, по ядру на ступень
  через `in_parallel`): клоны уклада ступени (`verges`/`verge_lawns`/
  `verge_yards`/`pieces`/`scraps` — `Scraps` клонирует списки lawns+green+
  contours, сетки ленивые), `pave_scraps` (`near_lawn` по сетке газонов +
  полосы по всем улицам), `lay_green_scraps` (`push_green` карманы и газоны,
  `find_green`+`find` — клип-оверлеи по газонам, внутри `in_parallel` и
  насыщен — запись 34: батчинг опровергнут, CPU оверлеев не снижается;
  раскладка фигур `push_shape` серийная), сборка слоёв и отчёт.
- **`corners_steps` 417–421** — скругления ступеней (`RoadCommon::new`,
  по ядру на ступень): `corners::kerb_returns` (сбор вкладов по дорогам и
  частичные по узлам — оба `in_parallel`, `corners/gather.rs`) +
  `KerbReturns::lay` (серийная укладка в сборщики ступени + `pieces`).
- **`verges_prep` 294–332** — обочины по улицам в потоках на каждую ступень
  (`verges::street_verge_geometry` через `in_parallel`); стены — внутри
  по-уличного прохода.
- **layout ленты 51** — раскладка вкладов кусков (запись 42): аппенды,
  серийные мосты, обочины `apply` 31–32 (частичные `Scraps` с ленивой сеткой —
  в записи 42 не окупились).
- **nodal-стены ≈115 внутри `Drawn::new`** (записи 39/43): RoadNodes 31–33,
  `pairs.align` 19–40, сглаживание+пути ≈30.

Что из этого держит числа — не измерено: у всех четырёх разреза внутри нет
(лента разрезана записью 42 только на верхнем уровне, `Drawn::new` — записью
39, но nodal-стены там названы без разреза).

**Не рычаги** (отмечено в записях 43/39, не пытаться):

- итоговый union устьев 47 — **однопроходный якорь дыр**: двухступенчатое
  слияние перевернуло 4 пограничные дыры из 261 — класс перестановки тайловых
  путей не покрывает пороги по площади (урок записи 43);
- сетки звеньев/препятствий стежков 21+16 — порядок вставки пинит `near_each`
  и выбор стыка на ничьих (запись 39) — не параллелятся.

**Опция ревью-сессии заезда 33**: `sidewalk_states` мёртв — состояние на
начале каждого куска всегда `None` (проводку починил `149280c4`); удалить
механизм вместе с абзацем записи 42 (препас `ribbon_lane.rs`, вызов и
передача в `chunk`).

## Направление — разрез стен на фазы, фикс крупнейшего ≥150

**Разрез** (временные `eprintln`, патчи в `/tmp` **до** любого отката и до
коммитов — держать, пока правка не закоммичена, урок записи 42; соло-бенч
`map_meshing paris` ×3, свои живые процессы заглушены — два qwe на симуляции
дают +300–400 мс, урок записи 42; eprintln фаз одного процесса проседают в
разы между прогонами — медианы набора, меньшая сторона как нижняя граница):

- `finish_step_split`: клоны / `pave_scraps` (near_lawn+банды) /
  `lay_green_scraps` (push_green / `find_green` / `find` / раскладка фигур) /
  слои+отчёт — по каждой ступени;
- `corners_steps`: `kerb_returns` (вклады / частичные узлов / слияние) / `lay`;
- `verges_prep`: стена по ступеням; при живом куске — внутри
  `street_verge_geometry` (запросы сеток / штрихи);
- layout ленты: аппенды вкладов / серийные мосты / обочины `apply`;
- nodal-стены `Drawn::new`: RoadNodes / `pairs.align` / сглаживание+пути —
  свежие числа под нынешним контеншном.

**Фикс** — крупнейшая под-фаза ≥150 мс, по шаблону `in_parallel`
(`map/parallel.rs`): чанки + частичный аккумулятор + раскладка в исходном
порядке (прецеденты: пробы пар/перепонки/стежки 39, краска узлов 40,
кластеры/зебры 41, лента 42, gores/ленты устьев 43). **ЧАНКИ, не по-штучные
аккумуляторы** — по-уличный аккумулятор на десятках тысяч улиц дал +140 мс
(урок записи 42). Если рычаг — клоны финала ступени: передача владения
(`mem::take` укладов до финала, финал от собственного `StepLay`) — раскладка
аппендами не нужна, тот же байт в байт; расширение `map/parallel.rs`
допустимо. Тайловые union — только там, где после нет порогов по площади
(урок записи 43).

Выходы обязаны остаться бит-в-бит: счётчики **обеих** строк `road meshing:` —
контроль (заявленный класс перестановки тайлов — `+N` vertices, не молчаливая
смена). Лента не пишет в `MapData` — `SNAPSHOT_VERSION` не трогается.

**Правило выхода** (заезды 29–33): рычаг в замороженных файлах, или
крупнейшая под-фаза <150 мс, или цена меньше планки — следующая по рейтингу
фаза записи 43 (nodal-стены RoadNodes / `pairs.align`; обочины раскладки
ленты 31–32), и это отмечается в этой спеке и записи 44.

## Ожидание и риски

- Цель: разрез закрывает четыре стены под-фазами со свежим рейтингом; фикс
  снимает ≥150 мс серийной работы лайны (`map meshes: roads in`, whole set
  медианой живой пары, обе строки `road meshing:`). Числа стен — под
  contention записи 40; соло существенно меньше, обещать больше разреза
  нельзя.
- Эквивалентность: счётчики обеих строк `road meshing:` бит-в-бит; `map
  meshes: roads in` — та же сумма вершин у ступеней; `SNAPSHOT_VERSION` не
  трогается.
- Риски: `find`/`find_green` насыщены параллелем (запись 34) — их стену
  снимает только снижение CPU оверлеев, которого нет (батчинг опроверг
  цифрами); финал ступени дважды клипает одни и те же газоны (ступени
  отличаются мощением) — разделение требует готовых оверлеев и бит-в-бит не
  держит; клоны `Scraps`/`pieces`/сборщиков — чистая цена передачи владения,
  кандидат без геометрических рисков; раскладка фигур `lay_green_scraps`
  серийна и по-фигурна — кандидат чанков с аппендами (прецеденты краски 40,
  ленты 42).
- Витрины и бенчи (`build_roads_from`, `map_meshing`) идут через ту же
  сборку — их отчёты остаются контролем; малый вход (тесты) — прежний путь,
  тот же байт в байт.
