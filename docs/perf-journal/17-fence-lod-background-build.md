# Запись 17 — подвисание на пороге зум-LOD: доминанта — заборы; сборка шага в фоновом таске, атомарная подмена

Статус: фикс заезда 07 (`planned/05-lod-switch-hitches.md`). Файлы: `src/map/fences.rs` ·
`src/map/mod.rs` · `src/map/zoom.rs` · `examples/bench/map_meshing.rs`. Замеры: живой
Париж (пауза, свежие процессы, `QWE_PERF_NOAPPNAP=1`, `QWE_PERF_FRAME_SPIKES=30`,
зум колесом через BRP), оффлайн-бенч.

**Атрибуция.** Прокрутка зума через каждый порог по одному (`cross`: одно колесо =
один порог, спайк читается из лога с зумом кадра). Подозреваемые плана (машины,
трамвай, ближний шаг крон) не подтвердились как доминанта: машины на пересечении
платят 3–7 мс CPU (меш кузовов по кешу расстановки, `CarPlacement`) + один кадр
подмены меша ~66 мс; трамвай по умолчанию снят (`TramStyle::visible` = false) и не
мерялся вовсе; кроны после записи 13 стримятся пачками и стоят 30–40 мс на кадр
пачки. Доминанта — **заборы**: пересечение 0.12 (ступень 0.50 м) — спайк
**1182.5 мс**, пересечение 0.35 (ступень 1.30 м) — **2275.5 мс**; оба кадра —
целиком сборка `mesh_fences` (репорт слоя печатается за ~20 мс до конца спайка).
Снятие слоя на 0.9 — деспавн, бесплатный и до правки. Заборы числились «дешёвой
лестницей» (1–15 мс) по Туле с её сотнями оград; Париж несёт **7080 линий →
10 144 куска**, и цена сборки шага — секунды.

**Что внутри секунды.** Новые строки бенча (`measure_fences`, Париж): свип и
объединение теней — **93%** сборки (стадия shadows — 2245 мс из 2410 на ступени 1.30 м):
каждое звено каждого куска даёт прямоугольник свипа и восьмиугольник узла —
порядка 400k выпуклых контуров через `i_overlay`. Проёмы (`fence_gaps`) — 146 мс,
настилы мостов — 0, куски — 4, ленты линий — 14 мс. Ступени целиком: 0.25 м —
826 мс/595k вершин, 0.50 м — 1198 мс/651k, 1.30 м — 2410 мс/688k.

**Правка.** Пересечение порога (и осевшее солнце) больше не собирает слой в кадре:
`fences::queue_fence_rebuild` ставит задачу в `AsyncComputeTaskPool` — чистая
`mesh_fences` зовётся в таске с **клонированными** оградами и дорогами (Париж —
десятки МБ, миллисекунды в кадре; ресурс карты с потоком не разделяется). Старый
слой остаётся на экране, пока сборка идёт; `fences::apply_fence_rebuild` (каждый
кадр, `check_ready`) подменяет атомарно — спавн нового и деспавн старого в одной
командной очереди, один синх-пойнт: **ни кадра без LOD-слоя, ни кадра с двумя**.
`generation` отбрасывает устаревший результат: пока сборка идёт, порог могли
пересечь ещё раз (быстрый свип зума) или осело солнце. Дальняя ступень (0.9) —
как и раньше, деспавн сразу: строить там нечего. Вход в мир — прежний путь
(`rebuild_fences` в кадре, под экраном загрузки), он же сбрасывает `FenceBuild`
при смене города. Солнце таск читает уже осевшее: `settle_sun`/`apply_sun` идут в
`PreUpdate`, пересборка — в `Update`.

**Замеры** (живой Париж, пауза, свежие процессы под NOAPPNAP; «до» — прогон
старого бинарника, «после» — новый, тот же протокол и та же машина):

| пересечение (сборка ступени) | до | после |
|---|---|---|
| 0.12 наружу (0.50 м) | 1182.5 мс | 30.2 мс (шумовой пол) |
| 0.35 наружу (1.30 м) | 2275.5 мс | спайков нет |
| 0.9 внутрь (1.30 м) | — | спайков нет |
| 0.35 внутрь (0.50 м) | — | спайков нет |
| 0.12 внутрь (0.25 м) | — | 33.6 мс (шумовой пол) |

Контроли: машины 0.4 (66.6 мс до — подмена меша, CPU 3 мс) — 30–40 мс после,
слилась с шумовым полом; кроны 0.2 (стрим) — 39.7 до / 36.6 после; снятие слоя
(0.9 наружу, 0.8, вагоны 2.0) — без спайков в обоих прогонах. Шумовой пол прогона
— спайки 30–40 мс на ровном месте (рендер-сторона полного кадра на этих зумах),
есть и в «до». Сборки доходят до подмены: репорты на живом — 1.30 м за 2.37 с,
0.50 м за 1.21 с, 0.25 м за 0.85 с после запроса. Гвард поколения проверен живым:
0.12 вниз и сразу вверх — отчёта ступени 0.25 в логе нет (результат выброшен),
применилась ступень 0.50; паник нет.

**Цена.** Подмена платит загрузку нового меша в рендер — один кадр ~30–60 мс
(на этих зумах сливается с шумовым полом). Отброшенная задача дожигает ядро до
конца сборки (`Task` при дропе отвязывается) — заметно только при свипе через
несколько заборных порогов подряд. Пока сборка идёт (до ~2.4 с), экран несёт
ступень прежней ширины — заявленный автором компромисс. Вход в мир по-прежнему
собирает заборы в кадре (под лоадером; общий стартовый мешинг — отдельный пункт
очереди).

**Что дальше.** Очередь прежняя: 4b — бинарный снапшот `MapData` (planned/04),
kerb_returns поузлово (запись 14, ~300 мс), мешинг-стена старта (здания ~8 с,
тени 3.0 с из них — запись 14 «Что дальше»; вход в мир теперь ещё и заборы 2.4 с
в кадре под лоадером — кандидат на тот же перенос в поток), рендер-сторона шторма
(запись 15 «Отвергнутое»). Из этого заезда: подменный кадр слоя-с-блендингом
(машины 2M вершин на ближней ступени) — если когда-нибудь станет заметен, резать
загрузку меша, а не сборку.

**Метод.**

- Атрибуция — `cross()`-прокрутка: `hover 640 360`, одно `MouseWheel` с
  `y = ln(из/в)/ln(1.12)` на порог, спайки читаются дельтой `grep -c 'frame spike'`
  вокруг каждого пересечения; зум в строке спайка — зум кадра, порог
  восстанавливается парой «спайк + репорт слоя» в одном кадре (репорт печатается
  перед концом спайка — сборка и есть спайк).
- Плотное место для скриншотов — по кешу, не по живому перебору: барная сетка
  выгрузки (`barrier=fence|wall`) проецируется в метры карты тем же расчётом, что
  в `tools/osm_near`, плотная ячейка 400 м — кандидат в точки (`brp cam`, `shot-at`).
  Ограда-решётка (`Railing`) тени не имеет и разницы ширины почти не показывает —
  для визуальной пары искать `fence`/`wall`.
- Оффскрин-скриншот с чужим `zoom` двигает зум живой камеры на кадр съёмки и
  может сам пересечь порог: между «во время сборки» и «после подмены» камера
  обязана уже стоять на целевом зуме.
