# Запланировано 01 — чанкование merged-мешей карты (frustum culling)

Приоритет: **1**, самый большой выигрыш. Средний заезд (несколько слоёв, замеры,
скриншоты). Контекст: записи 10 и 5 журнала (`docs/perf-journal/`).

## Зачем

- Париж: fps 27–35 на **всех** зумах 0.118–1.142 при `sim/tick` 1.7–2.3 мс;
  hide-тест (пауза, окна по 10 с): без `building_extruded` 27→45 fps,
  без дорог →51. Тула на тех же условиях 58 fps и на скрытие не реагирует.
- Механика: каждый merged-слой карты — одна сущность через всю карту;
  `calculate_bounds_2d` (bevy_sprite) ставит ей Aabb всей карты, frustum culling
  не отбрасывает её никогда → ~20M вершин (Париж) уходит в GPU каждый кадр.
- Берлин (запись 5) — та же находка; Париж лишь довёл её до доминанты кадра.

## Дизайн

- Сетка кусков карты — как у крон: `trees.rs::sorted_chunks` + `CROWN_CHUNK = 1000.0`
  (клетка `IVec2`, порядок кусков по клеткам (y, x) — детерминизм картинки).
  Для карты — константа `MAP_CHUNK` рядом с владельцем; начать с 1000 м
  (8×6 клеток), пересмотреть по замерам.
- Чанковать непрозрачные доминанты: buildings (facades/roofs/extrusion), семейство
  дорог, ground/surface-слои. **Строительные тени не чанкуются**: они через
  `i_overlay`-union (`shadow::push_union`), пересечение границы чанка дало бы
  двойное затемнение прозрачного слоя. Тени деревьев уже чанки (CROWN_CHUNK).
- `mesh_<layer>(data, style) -> Vec<LayerMesh>` уже возвращает список —
  чанкование лишь добавляет записей: каждая со своим `MeshBuilder`, общим `name`
  и одним z. `spawn_layers` не меняется. `brp hide/probe` по имени продолжают
  работать (чанки одного слоя делят имя).
- LodStep-слои (рельсы, два шага обочин): каждый чанк наследует `LodStep(index)` —
  `show_lod_layers` управляет видимостью по тегу, чанки не ломают его.
- Прозрачные paint-слои — во вторую очередь, после непрозрачных.

## Шаги

1. Хелпер чанкования в `map/meshing.rs`: сборка сразу в per-cell builders
   (или разрез собранного слоя — выбрать по коду; сборка в builders чище).
2. Переводить по одному слою с замером после каждого: buildings → roads → surface.
3. Верификация после каждого слоя: `tools/check.sh`; zoom-развёртка на Париже
   и Туле (пауза, окна по 10 с по дельте `frame_count`: 0.118 / 0.23 / 0.5 / 1.0);
   скриншоты на границах клеток (швы), в том числе у ленточных дорожных слоёв.

## Риски

- Швы на границах клеток у штрихованных и ленточных слоёв — ловить скриншотами
  на границе; geometry у слоя общая, разрез только по принадлежности клетки.
- Рост draw calls на широком зуме: 48 клеток × ~20 слоёв — сотни вместо ~30;
  замерить fps на зуме 4.5 до/после (там выигрыша от чанков нет, важно не проиграть).

## Ожидаемый эффект

Кадр зума 0.23 — 450×250 м из 7600×5700 (~0.3% площади): culling отбрасывает
~97–99% геометрии → 27 fps → ожидаемо 50–60 на ближних/средних зумах.
На самом широком зуме — без изменений.
