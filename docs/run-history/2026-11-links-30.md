## Найдено (ветка perf30 — БЕЗ КОММИТОВ, правки кода угол не потребовал)

- **Статический разрез кандидата f32.** Условие перезагрузки — три
  триггера: `retuned::<City>`, `retuned::<NavtileBase>`,
  `parse_knobs_diverged` (city.rs:244–248); единственный путь из
  `Playing` в `Loading` в src — `reload_world`. Ручки согласованы
  конструкцией: файл настроек накладывается в `SettingsPlugin::build` —
  **до любого расписания** (сверено по исходнику bevy-settings 0.20.1:
  apply в `Plugin::build`, синхронно), парс читает ползунок `RoadShape`
  (восстановлен тем же накладом), сравнение — осевшую копию
  `RoadShapeOnMap`, которую `seed_road_shape` в `Startup` копирует с
  того же ползунка; все три места несут одно значение, f32 3.3 ↔
  «3.299999952316284» в toml — точный round-trip (shortest repr).
  `settle_road_shape` подливает копию за ползунком, не наоборот.
  Дивергенции на чистом переключении взяться неоткуда.
- **Живые пробы (master-бинарь из worktree perf30).** Три чистых
  переключения (стартовый Париж → Тула → Париж) — **ровно одна загрузка
  на переключение** (`world reload:` одна, warmup +1, без хвоста).
  Затем на долгоживущем приложении — яд: TEMP-тест писал снапшот Тулы
  без улиц с настоящим штампом (`snapshot::write` с
  `MapData::default()`), переключение Тулой исцелилось
  («snapshot rejected (corrupt: decoded map holds no roads)» → json →
  снапшот перезаписан → мир здоров) — и **90 с тишины**, второй
  загрузки нет.
- **Точная реплика пробы №29 (свежий запуск + яд + res set) —
  воспроизвела «две загрузки» и раскрыла механизм.** Приложение
  стартовало НЕ Парижем, а **Тулой** — настройки перезаписаны на выходе
  предыдущего приложения (урок №19: город последней загрузки становится
  стартовым). Стартовая загрузка сама съела яд: reject → исцеление →
  warmup 20:53:20.9. Моя же скриптовая команда `res set City '"Tula"'
  через 8.25 с после Live дала вторую загрузку («world reload: city
  Tula» → чистый snapshot hit → warmup): **повторная установка того же
  города перезагружает мир** — `retuned` семантикой изменения, не
  равенства; урок про это был в NOTES, свою же команду в пробе №30
  я сначала принял за «вторую загрузку». Лог №29 читается тем же
  разбором: их проба B — старт на Туле (после пробы A, завершившейся
  Тулой) с отравленным снапшотом = исцелившая загрузка №1, затем их
  собственный `res set City Tula` = загрузка №2; «Paris ready» было
  неверным допущением. «Два snapshot hit» — из проб «до» фикса, где
  яд переживал загрузку и попадался каждым заходом.

## Вердикт

в `parse_knobs_diverged` закрыт статикой и живьём. TEMP-врезка снята,

гонялся. Перф-вердикт: код не менялся — цены нет, угол диагностический.
