# Запись 69 — камерный LOD людей на 200k: очередь диспетчера опустела, анатомия тика, sync-пойнты цепочки поведения ≈ 1 мс

Статус: Фаза 2 плана ×10 (`docs/population-x10-plan.md`), звено №47
(`pop47`, master на старте `cb7a2091`). Правки кода: `src/human/lod.rs`
(ярусы Near/Far, срезы `FarSlice<0..7>` по `PawnId % 8`, швы promote/demote),
сегмент `sim/far_ms`. Диспетчер не тронут (вне Ф2). Замеры — Тула 200k,
стартовый вид, A*; тик Ф1 1.50–1.56 мс не является базой сравнения: там мир
стоял (очередь ~198k заявок не двигалась), здесь — весь живёт.

**Критерий фазы выполнен**: очередь заявок диспетчера 197 698 → **0–6**
(зум 0.4), 0 на городском зуме; 99.6% пешек в дальнем ярусе
(FarTag 198 255 из 199 066 живых).

**Вердикты.**

- **Sync-пойнты — реальный класс затрат на 200k.** Цепочка HumanBehavior
  (`panic → flee → escape → far_onset → 8×far_slice → rise_souls` внутри
  одного `.chain()`) ставила auto-sync-пойнт между каждой упорядоченной
  парой — до девяти применений командных буферов за тик. Вынос восьмёрки
  срезов в отдельный `add_systems` с `chain_ignore_deferred` (порядок тот же,
  пойнтов нет — команды восьмёрки применяются одним хвостовым пойнтом;
  единственный сохранённый sync — после `far_onset`, ради видимости
  `FleeRepath`; порядок против ближней цепочки — дешёвым `.after(escape)`)
  снял 0.5–1.0 мс: тик 4.26–4.31 → 3.2–3.7 по двум запускам. Разброс — шум
  машины и возраст мира (far сам растёт 1.6 → 1.8+ с ходом шторма), до/после
  в одном запуске не чередовалось.
- **Возраст мира меняет far_ms сильнее зума.** Один и тот же размер среза
  (~24.7k пешек/тик): тик 3.34 на молодом мире против 4.37 (far 2.3) через
  три сим-минуты шторма — демоны разошлись, дальнее бегство подорожало.
  Замеры фаз сравнивать только на одном возрасте мира.
- **Городской зум (≥ 0.75) опустошает Near мгновенно** — 127 ближних из
  197 601, и все 127 — беглецы (`UrgentPath` остаётся ближним по плану:
  срочные заявки диспетчатся на любом зуме). Мирных — ноль.
- **Инвариант переписи держится под LOD**: после 106 с шторма
  alive 196 326 + killed 3 674 + escaped 0 = 200 000; promote/demote посреди
  бегства (возврат `UrgentPath` + rescue) счёт не рвёт.
- **Остаток rest ≈ 1.0–1.5 мс против 15×-бюджета 0.31 мс — разрез следующему
  звену.** Кандидаты: применение команд `to_moving`/`to_idle` на каждом
  выборе цели (archetype-волны), диспетчерский скан очереди, pump. Sync-пойнты
  главной цепочки (`panic → flee → escape → rise_souls`) тоже остались — их
  разбор требует того же метода (TEMP-врезка по `Instant`).
