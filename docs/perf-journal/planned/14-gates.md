# Запланировано 14 — гейты navmesh: 1.44 с серийной части лоад-потока (Париж)

Приоритет: **1** — после записи 25 стена whole set — дороги (ступень 0,
4.5–4.9 живьём в спокойной машине), заборы из стены ушли; из очереди
«Что дальше» недобит **гейты** — 1.44 с (записи 19/20/22/24/25). Заезд 16.

## Проблема

`Navmesh::open_gates_and_prune(map, portal, stage)` лоад-потока
(`download.rs::build_navmesh`) стоит **после** navmesh fill (~0.26 с) и
снапа портала, **до** мешинга — серийный кусок потока, и его секунды
тёплый старт видит целиком (тёплый старт Парижа, снапшот-хит, спокойная
машина: 9.4–10.1 с). Из 1.44 с в логе уже отведены две строки: гейты
(`navmesh: opened N fence gates in …`, ready-маркер) и прунинг
(`navmesh: pruned N unreachable tiles in …`).

## Направление решения

Первый шаг — **разрез фаз** (временные `eprintln`, снять до коммита,
подтверждение офлайн-якорем `fence_prune_audit` и живым прогоном):
внутри `open_sealed_fences` — `fill_base` (повторная растеризация
воды/зданий/стен поверх клона сетки), `door_groups`, два стартовых
обхода (flood достижимого и «голого»), скан карманов по 5 млн тайлов,
`nearest_fence_point` (линейный перебор всех оград на каждый тайл
калитки), `StreetEdges::build`, и **по-раундовая перекладка**:
`fence_gaps` пересобирает сетку всех дорог + `RoadNodes` и
перерастеризовывает все ограды в **каждом** раунде (париж: ~86k дорог,
~7080 оград), `extend_reachable`. Раунды посчитать. Прунинг — своей
строкой, при нужде сверлить вторым раундом (flood против финального
скана).

Решение — по разрезу (приоритет задают цифры, не список):

1. **Инвариантная часть `fence_gaps` — один раз** (прецедент разреза
   записи 24): сетка отрезков дорог, `RoadNodes` и висячие торцы от
   раунда к раунду не меняются — строятся до цикла раундов, по раунду
   детекция проёмов идёт по готовому индексу (порядок `push_gap` —
   калитки первыми в списке ограды — сохранён дословно).
2. **Растеризация оград — один раз, по раунду вычитание** (прецедент
   префильтра по рамкам записей 22/24): тайлы ленты каждой ограды
   собираются в свой список; калитки только открывают (правило кода:
   «заливка оград поверх той же основы даёт сетку, где проходимого
   стало больше»), поэтому по раунду из списка своей ограды вычитаются
   тайлы в круге обновлённых проёмов (круг с **слитым** reach —
   `push_gap` мог поднять его у совпавшего проёма), сетке отдаются
   только изменившиеся тайлы. Точность — та же дизъюнкция кругов, что у
   перепроверки `in_gap`; расхождение порядка слияния (калитка после
   дорожных проёмов против калитки первой) — щель на `JOIN_EPSILON`
   (0.5 м) при совпадении калитки с проёмом дороги, ловится счётчиками
   и аудитом карманов, при расхождении — откат к форме 1.
3. **`fill_base` без повторной растеризации**: `fill_from_mapdata` —
   единственный вход заливки — отдаёт основу сразу после неё
   (скретч-поле навмеша, следующий fill перезаписывает); пара
   «калитки, затем прунинг» берёт готовую, ручные сборки (аудиты,
   парити-тесты) — прежний путь, если скретча нет.
4. **`nearest_fence_point` по сетке** (прецедент арок записи 19):
   линейный перебор всех оград на каждый тайл калитки — отрезки оград в
   `Grid` (та же арифметика, что `StreetEdges`/`BridgeBands` рядом).

## Инварианты (не трогать)

- **Порядок «гейты до prune» и запись гейтов в `MapData` до prune** —
  правило world-lifecycle; `stage`-колбэк между шагами и формат обеих
  лог-строк (ready-маркеры) не меняются.
- **Открытые гейты — часть проходимости**: смены результата гейтов для
  пешек быть не должно — счётчики навмеша (`polymesh stitched`),
  число калиток в отчёте аудита и запросы (`count`, парити-тесты) —
  контроль; дрейф — только честно зафиксированный класс перестановки
  тайловых путей, не смена множества открытых калиток.
- Картинка не меняется: оффскрин-кадры до/после.
- Новых спавн-сайтов не заводить (`DespawnOnExit`, `survived` — 0);
  ярды реплеев и `a_restart_replays_the_run` в check.sh — зелёные.
- Не цель: полимеш-дорожка, ступень обочин 0; `planned/07` (кровь) —
  занята разведкой другой сессии, не трогать; чужое приложение на
  BRP_PORT=15703 не убивать — свой запуск на 15704.

## Шаги

1. Спека (этот файл).
2. База: 3 живых тёплых старта (`BRP_PORT=15704 QWE_PERF_NOAPPNAP=1
   QWE_PERF_NOVSYNC=1 QWE_PERF_FRAME_SPIKES=30 caffeinate -i cargo run`,
   фоном, снапшот-хиты; свежий процесс + перезагрузки
   `brp res set City . '"Paris"'`) — гейты по таймстампам строк лога
   между navmesh fill и мешингом.
3. Разрез фаз (временные `eprintln`, два раунда; офлайн-якорь —
   `caffeinate -i cargo run --example fence_prune_audit -- paris`).
4. Фиксы по результатам разреза (мелкими коммитами, каждый с замером).
5. Верификация (ниже), запись 26, артефакт, коммиты.

## Верификация

- Живой тёплый старт: база и правка stash-парой в одном состоянии
  машины (прогон не параллельно cargo-сборке; шум межпрогонный
  ±8–15 %); гейты по таймстампам между fill и мешингом; строка
  `osm map:` бит-в-бит; `polymesh stitched` — бит-в-бит или честный
  дрейф; тёплое `warmup:` — контроль (гейты пешек не касаются).
- Аудит `fence_prune_audit` (Париж): число калиток, прунинг, карманы —
  до/после.
- Оффскрин-кадр плотного центра (4245, 2956, зум 0.4) до/после.
- `world reload: N scene entities survived` — 0; `panicked`/`ERROR` — 0.
- `tools/check.sh` по изменённым файлам: тесты гейтов/парити, ярды
  реплеев, `a_restart_replays_the_run` — зелёные.
