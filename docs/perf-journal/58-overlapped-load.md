# Запись 58 — перекрытие navmesh-префикса с лейнами на скрытом бакете заборов (вариант-б)

Статус: фикса влита (Обзор №14, ветка `perf14` → ff master). Первая попытка
(вариант-а: вся дорожка fill+gates+prune рядом с лейнами, заборы/полимеш
стартуют по join навмеша) была отката в `perf12` — отрицательный результат с
двумя уроками: дизайн обязан гейтиться на бакет входного зума, а при ближнем
бакете лейн заборов дорог сам по себе (2.3–2.8 с Парижа) и его старт не должен
сдвигаться гонкой дорожек за ядра. Эта запись — второй дизайн из меню perf12:
разорвать пару fill→gates→prune и выпускать калитки до прунинга.

**Дизайн** (`prepare.rs::build_overlapped_world`): гейт —
`fences::entry_step_hidden(styles.fence_zoom)` (скрытая ступень лестницы
заборов: width ≤ 0, `entry_layers` выходит рано, до чтения проёмов). На
видимой ступени — серийный путь без изменений (`download.rs::build_navmesh`):
вид владельца (Save, zoom 0.4) не тронут. На скрытой — перекрытая загрузка:
состав деревьев серийно, затем scope с двумя волнами. Первая — лейны, не
читающие калиток (buildings ∥ roads ∥ small ∥ fences-пустой ∥ inspect, всё
по карте напрямую, без клона) рядом с навмеш-дорожкой (клон карты: fill →
снап → `open_sealed_fences`). Вторая волна — после присоединения дорожки
калиток: прунинг (`prune_unreachable` + `drop_gate_scratch` — порядок
«калитки до прунинга» держится) ∥ полимеш по клону с открытыми калитками.
Калитки сливаются в карту мира после всех дорожек (единственная мутация
клона — `fences[..].gates`). Тела лейнов и голова «fill + снап» общие у обоих
путей; лог-строки сохранены дословно.

**Замер** (Париж, тёплый снапшот-хит, сохранённый вид с зумом 1.2 — скрытый
бакет; чередование A/B по уроку №13; `QWE_PERF_NOAPPNAP=1`, порт 15703; окно
«snapshot hit → warmup routed» по таймстемпам строк лога):

- база (master, серийный): **4.542 / 4.441 / 4.459** — 4.48 ± 0.06 с;
- перекрытая (perf14): **3.875 / 3.784 / 3.804** — 3.82 ± 0.05 с.

Дельта **−0.65 с (−14 %)**, стабильна через чередование; дрейф машины в
пределах ±90 мс на вторых прогонах обеих сторон. Бит-в-бит между сторонами и
прогонами: калитки **1288**, прунинг **772 506** тайлов.

**Разбивка**: у серийного пути префикс (рид 0.09 + fill 0.26 + gates 0.37 +
prune 0.08) стоит перед лейнами целиком. У перекрытого fill/gates уходят под
стену лейнов (fill 0.42–0.45 под contention против 0.26 серийного, gates
0.41–0.52 против 0.37), прунинг — вторая волна (0.087–0.097), полимеш
получает клон с калитками сразу после шага калиток — его 1.3–1.4 с
перекрываются, а не добавляются. Хвост — roads (2.5–2.7 с) в обеих сторонах.

**Вид владельца не тронут** (perf14 на Save zoom 0.4, серийный путь):
fill 0.26 / gates 0.37 / prune 0.08 / clone 0.02 / fences-лейн 2.9 /
whole set 2.9 / warmup 1.24 — форма и цифры master; snapshot→warmup 4.82 с
(диапазон записи №12: 4.56–4.77, дрейф машины).

**Пин**: `prepare::tests::the_overlapped_load_matches_the_serial_one` —
сетка навмеша, непустые калитки, портал и препятствия полимеша бит-в-бит
между путями на калиточной фикстуре (форма
`gates/tests.rs::a_sealed_plot_gets_its_gate_on_the_street_side`).
`check.sh` зелёный (build + тесты + clippy + fmt); bench map_meshing не
требовался — тела лейнов не менялись, только расписание вокруг них.

**Метод** (новое к 57):

- **Окно загрузки — по таймстемпам строк лога**, не обёрткой вокруг запуска:
  t0 после старта таска режет голову окна, а лог и так точен до миллисекунд.
- **Бинарник из worktree напрямую не стартует** (dyld: no LC_RPATH на
  libstd) — только `cargo run` из корня worktree; ворктриа-настройки
  (`.settings/settings.toml`) сеются первым запуском и правятся до него
  копией владельческого файла.
- **Скриншот в агентской сессии может быть чёрным при поднятом окне**
  (поверхность не рендерится в захват даже после `raise`) — визуальную
  проверку закрыть логами и счётчиками слоёв, не биться за пиксель.
