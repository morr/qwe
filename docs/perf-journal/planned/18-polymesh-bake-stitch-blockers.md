# Запланировано 18 — полировка полимеша: bake, components и сборка blockers по потокам

Приоритет: **1** — остатки `planned/15-startup-discovery.md` (её пункты 3–4,
оба «Мелкий пункт»), один заезд-полировка. Заезд 19. Полимеш-часть разведки
и её «дороги» уже взяты (`1f385c73`, записи 27/28); inspect-индекс в
лоад-поток (её пункт 2) — отдельная работа, требует DrawnPieces из дорожного
лейна (osm-map), сюда не входит.

## Проблема

После `1f385c73` полимеш-лейн Парижа — 1.4–1.7 с живьём (из стены ушёл
целиком), и его остаток — серийные хвосты вокруг уже поточного чанкинга:

- **bake 118 мс** — `mesh.bake()` (`vendor/polyanya`) зовёт `Layer::bake`
  по слоям в цикле; слои независимы (сшивка метит индексы после), обе фазы
  bake — только чтение вершин и полигонов слоя (R-tree поиска + острова).
  Кандидат в `map::parallel::in_parallel` — как чанки записи 22.
- **components ~?** — `components_of` по слоям серийно
  (`build.rs:166`, flood fill до сшивки) — вес покажет разрез.
- **stitch 133 мс** — серийный глобальный граф; сверка с текущим файлом и
  строкой `polymesh stitched:` покажет, что осталось после тайлирования.
  Внутри: `reorder_neighbors_ccw_and_fix_corners` (полный проход по всем
  вершинам всех слоёв, уже разделён «посчитал → записал»), поиск пар швов
  (`get_vertices_on_segment` — линейный скан слоя на шов), узлы сетки
  (`position()` по всем вершинам слоя на узел), `stitch_internals`.
- **сборка blockers ~150 мс** — серийные `ribbon_outline` по 7080 оградам,
  408 мостам, стенам и водотокам (`blocker_shapes`/`carve_contours`,
  `build.rs`). Шаблон — «вклад по дорогам в порядке входа» записи 24:
  вклад каждого элемента в потоках, слияние в порядке входа.

## Направление решения

1. **Разрез** (временные `eprintln`, снятые до коммита): сборка blockers
   по семействам (водотоки / стены / ограды + проёмы / мосты / резы),
   `components_of`, bake (finder / islands), stitch по фазам
   (граф-узлы / пары швов / узлы сетки / `stitch_internals` / `verify`).
   Живые строки `polymesh chunked / baked / stitched` — стартовая точка.
2. **bake по слоям**: QWE-патч в vendor (`compute_bake`/`apply_bake`,
   `BoundedPolygon` наружу — тип и так лежит в поле слоя) + `in_parallel`
   по слоям в `build.rs`, применить серийно. Формы те же — результат
   бит-в-бит. `Mesh::bake` остаётся как был (upstream API).
3. **components_of по слоям** — чистая функция `&Layer` → `in_parallel`
   (если разрез покажет вес; порядок слоёв — порядок входа).
4. **blockers по порядку входа** (запись 24): `ribbon_outline` каждого
   элемента в потоках — ограды (пары «ограда + её проёмы»), водотоки,
   стены, мосты (лента бордюров + обе стороны), резы; слияние серийно
   в исходном порядке. Разности мостов с чужими лентами (уже по рамкам,
   запись 22) не трогать.
5. **stitch** — только если разрез покажет дешёвый win тем же шаблоном
   «посчитал в потоках → записал серийно» (кандидат —
   `reorder_neighbors`; поиск пар швов по кромке — тоже кандидат).
   Глобальный граф вслепую не перекраивать; если win не дешёвый —
   задокументировать и оставить.

## Инварианты (не трогать)

- **Геометрия — функция входа, не потоков**: порядок blockers — порядок
  входа (порядок фигур определяет группировку клеток в
  `difference_of_shapes`/`union_of` — результат бит-в-бит); bake и
  components per-layer детерминированы. Класс перестановки — вслух, если
  появится.
- **Строка `polymesh stitched: N seam vertices, M component nodes, K
  edges` — бит-в-бит**; счётчик полигонов и obstacles — бит-в-бит.
- **Поиск эквивалентен**: 500 запросов `polymesh_bench` — те же
  found/missed, тот же список промахов (контракт записей 22/27-разведки).
- Ярды реплеев, `a_restart_replays_the_run`, швы бит-в-бит, парити-тесты
  в `tools/check.sh` — зелёные.
- **Не трогать**: `planned/07` (кровь — занята разведкой другой сессии);
  `navigation/navmesh/{gates,reach,fill}.rs` и `map/footprint.rs`
  (свежие правки записи 26); `map/roads/*` и `map/prepare.rs` (запись 28 —
  не размазывать); незакоммиченную инструментировку чужих сессий.
- Чужие процессы не убивать: 15702 — пользователь, 15703/15705 могут быть
  заняты сессиями; своя пара — 15704/15706.
- Vendor-патч — помечен `QWE:`, как `get_path_on_layers` и dedup
  (`references/polymesh.md`, «Divergence»); upstream API (`Mesh::bake`)
  не меняется.
