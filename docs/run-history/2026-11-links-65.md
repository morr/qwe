## Угол и что снято

Свип жизненного цикла заявки в три прохода:

1. **Подача**: четыре сайта (`human/systems/wander.rs:280`, `human/behavior.rs:272`
   flee, `demon/systems.rs:303` wander, `demon/behavior.rs:297` chase) — все
   через `request_wander_path` с `sift_target`; до диспетчеризации цель может
   переехать ретаргетом, после — нет (у `Movable` одна заявка, таск поверх).
2. **Диспетчеризация**: живой камерно-гейтнутый (QueuedWander-сетка + срочные
   архетипом, бюджет `MAX_PATHFINDING_IN_FLIGHT − tasks`) и детерминированный
   FIFO с бюджетом юнитов (`movement/pathfinding/budget.rs`, юнит-тесты);
   `stamp_pathfinding_requests` (Added→RequestedAt) и `_unstamped` debug-квери.
3. **Приёмка**: `accept_answer` — общий тело обоих приёмников; отброс
   устаревшего первой проверкой, `rescue_from_impassable` по провалу,
   подрезка пути по уже пройденному; `strip_movement` полный; `stop_moving`
   не трогает оплаченный таск (ответ уйдёт в устаревшие).

Что снято:

- Все четыре сайта подачи просеивают цель; «слот за стеной» — документированный
  отказ `destination.rs`, не дыра.
- FIFO/пере-штамп/бюджет запины тестами movement/tests.rs — контракт детерминированного
  режима держится.
- План углубления: пункт «сеть для stamp_pathfinding_requests» закрыт в коде,
  помечен ЗАКРЫТО (файл не коммитится по правилу владельца).

## Находки и фиксы

- **Загадка №40 разгадана** (не баг классификации — геометрия другого бэкенда):
  три живых шторма с TEMP-пробой в `accept_answer` (классы провалов + вердикты),
  затем офлайн-репро на живых парах. Итог в заголовке; деталь: `bounded_path`
  при исчерпании бюджета паникует, паник в логах нет — все живые None =
  locate-отказы (170 из 95k за прогон) либо `no_route` графа (99.8%).
  Разрез швов (какие проёмы запечатывает сшивка, чинить ли `stitch_chunks`
  или просеивать цели по мешу) — отложено в план.
- **Урок о пробах**: счётчик серии провалов пешки стоял до ветки классификации —
  каждый провал сам себя обнулял, детектор всегда молчал. Размещение
  инструментария вокруг ранних выходов проверять так же строго, как сам класс.
- Отложенное наблюдение: `PATHFINDING_TASK_HANG_SECS`=20 с против волн
  CPU-голода 1–3 мин (№40 пронесло) — запас тонкий; триггер — живая паника
  «pathfinding task hung».
