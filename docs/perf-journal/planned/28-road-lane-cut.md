## Направление — разрез лайны целиком, фикс крупнейшего куска

Разрез (временные `eprintln`, снятые до коммитов, патч в `/tmp`), один
инструментированный прогон: скелет — `Drawn::new` (верхний уровень, для сверки
с записью 39), stations, islands, Junctions::new (внутри — если крупный),
Turns::new, axes(Ribbon), splitters; затем `build_roads_steps` — RoadCommon::new
по фазам (скругления ступеней, кромки+карманы+площадки, gores/mouths, medians,
островки+кольца, обочины по улицам, лента, фартуки+краска узлов, трамвай+стоянки+
мосты+переезды+стены), take_common_layers, финалы ступеней. Сумма сверяется с
«roads in» и `road meshing:`.

Фикс — **крупнейший кусок ≥150 мс**, параллель по шаблону `in_parallel`
(`map/parallel.rs`; пробы пар, перепонки, поиск стежков — запись 39). Лента —
главный серийный проход — главный кандидат, но порядок заливки задаёт порядок
треугольников и находок; параллель требует раскладки в порядке заливки по
индексам улиц (как `verges_by_street`). Выходы обязаны остаться **бит-в-бит**.

**Правило выхода** (заезд 29): если рычаг в замороженных файлах (`map/footprint.rs`,
`navigation/navmesh/{gates,reach,fill}.rs`, vendor-полимеш — запись 26/29;
`map/inspect.rs`, `map/osm/download.rs`, `src/loading.rs`, `map/osm/model.rs`,
`map/osm/model/trees.rs` — запись 30; кровь — planned/07), или крупнейший кусок
<150 мс, или цена меньше планки — следующая по рейтингу фаза разреза, и это
фиксируется в этой спеке и записи 40.

## Ожидание и риски

- Цель: разрез закрывает «перед лентами» и общую середину именованными кусками
  с свежим рейтингом; фикс снимает ≥150 мс серийной работы дорожной лайны
  (`map meshes: roads in` и whole set медианой живой пары). Обещать больше без
  разреза нельзя.
- Эквивалентность: счётчики строки `road meshing:` (все счётчики, включая
  vertices) бит-в-бит во всех прогонах обеих сторон; пин-тест
  `corner_paving_contours_carry_the_drawn_fans`; `Drawn` и скелет не пишут в
  `MapData` — `SNAPSHOT_VERSION` не трогается.
- Риски: лента мутирует общие сборщики по порядку заливки — в потоки уходит
  только по-уличный расчёт с дизъюнктными записями; `paint::Painter` копится
  в порядке улиц (раскладка по индексам); `lays[0]` читается серийными фазами
  (копия узлового слоя для краски, `setback`, `butt`, gores) — порядок его
  заполнения не менять. Ступенезависимые финалы уже параллельны.
- Витрины и бенчи (`build_roads_from`, `map_meshing`) идут через ту же
  сборку — их отчёты остаются контролем.
