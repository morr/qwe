## Проблема

`Drawn::new` (`map/roads/drawn.rs`) — подготовка дорог перед сборкой слоёв.
На тёплом старте зовётся из `road_skeleton` внутри дорожной лайны
`build_world_meshes` (`map/prepare.rs`, скелет через `get_or_init`) — на
каждую загрузку мира, не только при промахе кеша. Второй зовущий —
`corner_paving_contours` (парс, промах кеша): углам нужны узловые ступени,
стежки и слияния они не читают.

По разрезу записи 38 серийная цена на тёплом Париже:

| кусок | время |
|---|---|
| `Drawn::nodal` целиком | **233** |
| `network::stitches` | **171** |
| `merges` | 30 |
| `across_median` | 8 |

Внутри `nodal` разреза нет: `RoadNodes::new`, `street_axes` (со сглаживанием),
подмены (`driveway_crossings`, `ring_arcs`/`leg_sections`), `Tapers::new` —
одной цифрой. Крупнейшие два куска вместе ≈404 мс серийной работы на каждый
тёплый старт.

## Направление — сначала разрез, фикс по разрезу

Разрез (временные `eprintln`, снятые до коммитов, патч в `/tmp`), все ступени
в одном прогоне: `RoadNodes::new`, `street_axes`, `driveway_crossings`,
`ring_arcs`/`leg_sections`, `Tapers::new` (сумма = nodal), затем в `new`
поверх nodal: `network::stitches` (внутри — сборка сетки отрезков,
`Obstacles::new`, поисковый проход по торцам), `across_median`, `merges`,
раскладка стежков в оси. Сумма кусков сверяется с nodal+стежки+merges+median
≈442 — расхождение указывает на потерянный кусок.

Фикс — **крупнейший кусок ≥150 мс**, параллель по шаблону `in_parallel`
(`map/parallel.rs`; входы — запись 14, `cut_verges`/`kerb_returns` — записи
36/38). Кандидаты по коду, до разреза:

- **стежки 171**: сборка сетки отрезков и `Obstacles::new` серийная и общая,
  но поисковый проход по дорогам пишет только в свои `ends[index]`/
  `targets[index]` — по дорогам в потоки; `widest` (reach) выносится дешёвым
  проходом раньше; `count` — сумма после сбора результатов.
- внутри nodal: `Tapers::new` (проход по `joints`/`continuations` сети),
  `driveway_crossings` (по дорогам), сглаживание в `street_axes` (по улицам
  или ранам; сборка осей после него серийная).
- `RoadNodes::new` — сортировка визитов; параллель требует менять сборку,
  брать только если разрез назовёт его крупнейшим.

**Правило выхода** (заезд 29): если разрез покажет, что рычаг в замороженных
файлах, или крупнейший кусок <150 мс — берётся следующая по рейтингу фаза
записи 38 (serde 385 — рычаг ≤55 за шов тегов, ways-цикл 144 — параллель
меняет сигнатуру `parse_way`, corners слим ≈71, вырез обочин 153 — цена
самого overlay, tile-union 487 и деревья 414 — записи 36/37, рычагов нет),
и это фиксируется в этой спеке и записи 39.

## Ожидание и риски

- Цель: разрез закрывает nodal именованными кусками; фикс снимает ≥150 мс
  серийной работы — сумма 442 → ≤292 медианой живой пары. Обещать больше без
  разреза нельзя.
- Эквивалентность: **выходы бит-в-бит** — пин-тест
  `corner_paving_contours_carry_the_drawn_fans`, строки `road meshing:`
  (все счётчики) бит-в-бит во всех прогонах обеих сторон. `Drawn` не пишет в
  `MapData` — `SNAPSHOT_VERSION` не трогается, снапшот не двигается.
- Риски: порядок `near_each` у сетки стежков задаётся порядком вставки —
  сборка сетки и препятствий остаётся серийной, в потоки уходит только
  поисковый проход; результаты по дорогам собираются по индексам, `count`
  после. Стежок читает `nodes.roads_at` и obstacles — оба готовы до прохода.
- Витрины и бенчи (`build_roads_from`, `map_meshing`) идут через ту же
  подготовку — их отчёты остаются контролем.
