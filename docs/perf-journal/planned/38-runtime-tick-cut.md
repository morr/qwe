## Единица измерения

Рантайм-куски не живут в стенах секунды, как лайны загрузки: планка
≥150 мс переводится в **мс CPU на секунду стены** (доля одного ядра):

- тиковые системы: `ms/с = sim/*_ms × 64 × actual` — на 30× тик = 1920/с;
- кадровые системы: `ms/с = кадр × fps`;
- планка: **≥150 мс/с** (15 % ядра). Жёсткий потолок тика —
  `SIM_FRAME_BUDGET_MS` (20.3 мс/кадр): при 30× бюджет тика ≈0.106 мс,
  превышение режет регулятор и frame-budget guard (TickDebt) — их работа
  не рычаг, а следствие.
- `sim/separation_ms` меряется **на прогон** (гейт «не чаще раза в
  кадр», ~60 прогонов/с), в тиковую сумму не входит — сравнивается с
  кадровой стороной отдельно.

## Инварианты сима (правка тика обязана их держать)

- **Поток решений бит-в-бит**: RNG-роллы живут в `behavior.rs` и
  переходах, не в `decide`; решение должно продвигать свой
  `WanderIndex` ровно на тех же тиках, что и раньше. Любая правка
  тик-систем — replay-breaking change, если сдвинула хотя бы один ролл;
  `tests/determinism.rs` пинует.
- **Telemetry**: `killed + escaped + alive == HUMAN_COUNT`
  (проверка на паузе — на высокой скорости два BRP-чтения из разных
  тиков врут).
- Порядок SimSet (`SpatialRebuild → DemonBehavior → HumanBehavior`),
  демо-спавнер до `SpatialRebuild`, гейты `RunFixedMainLoop` — не
  переставлять без причины из разреза.

## Направление — разрез из лога и спайк-детекторов, без правок кода

**Диагностики уже в приложении**, правок кода для тиковой стороны не
нужно: `LogDiagnosticsPlugin` (DevPlugin, INFO, раз в секунду) печатает
каждую `sim/*_ms` сглаженным значением и средним по истории — блок
`sim/…` из лога и есть разрез тика. Кадровая сторона — спайк-детекторы:

- `QWE_PERF_FRAME_SPIKES=30` — кадровые спайки (Time<Real>, работает на
  паузе) + тик-спайки с разрезом (`tick spike dissect` — последнее
  значение каждой `sim/*_ms` + `rest`, и `tick spike segments` — стены
  цепочки head/spatial/demon/human/move/tail);
- `QWE_PERF_PHASE_SPIKES=40` — разрез кадров длиннее порога на стены
  главного расписания (`main phases`: pre/trans/fixed/update/post/inter),
  сканы спрайт-материалов и фазы рендера;
- `archetype census: N total` раз в 5 с — заполняемость архетипного
  пространства (шторм архетипов записи 15).

**GAP-проверки** (суммы против totals):

- тик: сумма 10 тиковых `sim/*_ms` против `sim/tick_ms` — «rest»
  (командные флешки, синхронизации, исполнитель) виден прямо; полный
  разрез rest'а — только в момент тик-спайка (dissect);
- кадр: на спайк-кадре сумма сегментов `main phases` против длины кадра
  из строки `frame spike`; steady-кадр под vsync невидим (запись 35) —
  его стоимость оценивается долей `sim/tick_ms × 64 × actual` +
  `sim/wait_ms` против `SIM_FRAME_BUDGET_MS`.

**Протокол базы и разреза** (единый для обеих задач — разрез снимается
теми же прогонами, что и база):

- запуск из worktree: `BRP_PORT=15704 QWE_PERF_NOAPPNAP=1
  QWE_PERF_NOVSYNC=1 QWE_PERF_FRAME_SPIKES=30 QWE_PERF_PHASE_SPIKES=40
  caffeinate -i cargo run`, фоном, строго из каталога worktree;
- тёплый старт Парижа для контекста (строки `map meshes: …`, обе строки
  `road meshing:`), затем **3 прогона рантайма**: свежий процесс, первый
  холодный в медианы не берётся; сосед (пользовательский экземпляр на
  15702) на `brp pause` на время прогона, **32 с между прогонами** —
  урок записи 36;
- прогон: `brp speed 30` (губернатор читается обратно — actual
  оседает), ~60–90 с стен диагностики, затем пауза мира; из лога —
  медианы блоков `sim/…` по диагностикам, census, спайки; `SimSpeed`
  и `TickDebt` читаются по BRP до и после;
- инвариант телеметрии — раз за прогон: пауза, `killed + escaped +
  alive == HUMAN_COUNT`;
- шторм в прогоне натуральный: демоны копятся от портала на скорости,
  трупы растут — разрез снимает и спокойную фазу (первые секунды), и
  шторм (хвост); скорость/ город через BRP не меняются, кроме `speed` и
  `City` — **DemonStyle и прочие settings-группы не писать**: правка по
  BRP персистится в `settings.toml` пользователя.

**Фикс** (если разрез укажет кусок ≥150 мс/с): по умолчанию per-tick/
per-frame система; шаблон чанкинга по прецедентам записей 40–49 —
чанки + частичные сборщики + раскладка аппендами в исходном порядке;
**чанки, не по-штучные аккумуляторы** — урок 42. Выходы обязаны
остаться бит-в-бит: счётчики своих строк + сим-инвариант телеметрии +
реплеи. Если рычаг в замороженных файлах (см. запреты) или крупнейший
кусок < планки — плато-отметка в этой спеке и записи 50, следующий
уровень по свежему рейтингу.

## Ожидание и риски

- По старым цифрам (записи 03/35) тик в сумме 0.25–2 мс при подсистемах
  в сотых — даже на 30× тиковая сторона ~0.5 с/с целиком, и всё ниже
  планки по куску; вероятный вердикт — **плато рантайма** с фиксацией
  свежего разреза как базы будущих сравнений. Разрез обязан это
  подтвердить или опровергнуть числами, включая GAP и шторм-хвост.
- Кадровая сторона под vsync: только спайки судятся, steady-кадр
  невидим — перепутать «дёшево» и «невидимо» (запись 35) нельзя.
- Межпрогонный шум ±8–15 % (запись 35) — медианы 3 прогонов, куски
  сравнивать только против той же скорости.
- Мир на скорости деградирует (трупы, шторм) — фаза прогона обязана
  фиксироваться в отчёте (мир T+, census), иначе куски несравнимы.

5. Верификация (ниже), запись 50, артефакт, ff master, заезд 41.

## Верификация

- **GAP ~0**: сумма тиковых `sim/*_ms` против `sim/tick_ms` по медианам
  прогонов; на спайк-кадрах сумма сегментов против длины кадра.
- **Живая пара 3+3 вперемешку** (`perf40-base` против `perf40`, свежие
  процессы, холодные первые не в медиану, сосед на `brp pause`, 32 с
  между прогонами): `sim/tick_ms` и подсистемы медианами, спайк-кадастр;
  счётчики своих строк бит-в-бит, парсов при тёплых перезагрузках — 0
  (строка `osm: parsed`).
- **Сим-инвариант**: телеметрия на паузе после каждого прогона; реплеи
  (`tests/determinism.rs`) — если правка заденет то, от чего зависит
  реплей.
- `panicked`/`ERROR` — 0; `world reload … survived` — 0.
- **Тесты зоны зелёные; `tools/check.sh` одним фоном — зелёный**
  (переформатированные `planting.rs`/`node_paint*.rs` откатывать, не
  коммитить — урок 42).
- Свои фоновые процессы погашены перед живой парой (урок 41; после
  каждого гашения — `$b procs` / `pgrep -f target/debug/qwe`, выживший
  — `kill <pid>` — урок записи 49).
