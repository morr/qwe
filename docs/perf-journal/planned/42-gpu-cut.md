# Запланировано 42 — GPU-тайминговый инструмент и первый разрез кадра по GPU: сегменты Core2d через wgpu timestamp queries (Metal без vendor-патчей), зумы 4.5 / 0.8 / 0.15 и кроссинг 0.2; по каждому куску — рычаг или стенка/продуктовая

## Проблема

Приоритет: **1** — заезд 44. Рантайм при планке ~100 м/с закрыт целиком
(52), юзер-видимые джерки — плато с одной продуктовой территорией (53).
**GPU-время кадра не мерилось ни разу**: `RenderDiagnosticsPlugin` пуст
на 0.20 (23/35 — только sparse-buffer пасс), CPU-стены рендера известны
(52: extract ≈26 мс, render-CPU ≈55–84 размазаны), но GPU-сторона —
чёрный ящик. Подозреваемых полно:

1. **Слитые кроны ~956k вершин + тени крон 5.5M вершин** на дальних
   зумах (merged `tree_crowns` чанки + shadow-слой; вверху лествицы
   деревьев — дальняя ступень). Кандидат №1 на дальнем зуме 4.5.
2. **Флип кронных кусков на кроссинге 0.2** — CPU-сторона измерена
   (53: 54–63 мс кадр, перебатчировка 2d-фазы + мировая синхронизация
   ~28.6k крон-сущностей; render `prepare` 149.8 на флипе); GPU-сторона
   флипа неизвестна — ожидание: перебатчировка фазы — CPU-работа, GPU
   кадр флипа не должен отличаться от соседей. Проверить числом.
3. **Merged-слои города** (дороги, здания, поверхности — чанки
   1000 м; MSAA 4x + HDR + bloom поверх всей карты; запись 5 на старой
   до-чанковой версии рекомендовала render-scale/MSAA-off — продуктовое
   решение без чисел не принять).

Без GPU-чисел не принять ни одно продуктовое решение по кронам
(53: «меньше крон-сущностей / мердж / инстансинг / плотность») и по
MSAA (5). Цель заезда: построить GPU-тайминговый инструмент и снять
первый разрез кадра по GPU.

## Единица измерения

**мс GPU на сегмент кадра** — среднее за ~1 с окно (60 кадров) и
медиана окон на точке замера. Сегменты Core2d: opaque+alpha,
transparent, post (bloom+tonemapping), ui, upscale + total. На каждом
зуме (4.5 / 0.8 / 0.15, сим на паузе) — ≥3 окна, медиана. Кроссинг 0.2 —
пофреймово: `gpu spike`-строки по порогу против `frame spike` (CPU,
53) на тех же кадрах. Кросс-чек тотала — vsync-пробой (35):
`frame_time` 16.7 → total < слота, 33.3 → переполнение (NOVSYNC на
Metal сломан, `frame_time` бинарный — валиден как грубый пробой,
не как мера). Сегмент закрыт (рычаг найден), если его кусок назван
с числом и владельцем; стенка/продуктовая — с записью-владельцем.

## Не рычаги (стены, не пытаться)

- **Рендерные vendor-патчи** (bevy_render/wgpu через
  `[patch.crates-io]`) — только с доказанным куском и явным решением
  автора; правило записи 29 (полимеш) распространяется на рендер.
  Инструмент обязан подняться поверх публичного API 0.20
  (schedules + `RenderContext` + wgpu features) — если не поднимется,
  зафиксировать почему и добить A/B-профилем слоёв (`brp hide/show`).
- **`QWE_PERF_NOVSYNC` как мера** — на Metal wgpu не имеет uncapped
  present (35); только бинарный пробой слота.
- **MSAA / render-scale / пороги LOD** — продуктовые (5, 53, VISION
  12.6): инструмент их квантует, двигает только автор.
- **img2 / входной шторм** — апстрим (23), не GPU-тема.
- **Запреты чужих направлений**: `planned/07` (кровь);
  `map/footprint.rs` и `navigation/navmesh/{gates,reach,fill}.rs`
  (26); vendor-патчи полимеша (29); `map/inspect.rs`,
  `map/osm/download.rs`, `src/loading.rs`, `map/osm/model.rs`,
  `map/osm/model/trees.rs` (30).

## Инварианты (правка обязана их держать)

- **Тик не трогать**: инструмент живёт в RenderApp/Update, env-гейт.
  `FixedUpdate` не изменяется; детерминизм не в потоке риска (рендер
  вне потока решений) — реплеи не требуются, но `tools/check.sh`
  обязателен на код инструмента.
- **Ноль эффекта без env**: `QWE_PERF_GPU_CUT` unset — фичи устройства
  дефолтные, плагин не добавляется, ни одной лишней системы/строки.
- **Выходы бит-в-бит**: `road meshing:`, `osm map:`, `entities:` не
  двигаются — инструмент не трогает мир и парс.
- **Telemetry**: `killed + escaped + alive == HUMAN_COUNT` (на паузе).

## Дизайн

**Факты стека** (проверены по источникам 0.20.1 / wgpu 30.0.1):

- wgpu 30 на Metal поддерживает `TIMESTAMP_QUERY` и
  `TIMESTAMP_QUERY_INSIDE_ENCODERS` (hal `metal/adapter.rs`: все три
  timestamp-фичи в списке; `write_timestamp` энкодера =
  `sampleCountersInBuffer_atSampleIndex_withBarrier`,
  `Queue::get_timestamp_period` есть) — **timestamps поднимаются без
  vendor-патчей**;
- рендер 0.20 — расписания: `render_system` → `RenderGraph` →
  `camera_driver` → `Core2d` на каждую камеру; цепочка 2d:
  `msaa_writeback → main_opaque_pass_2d → main_transparent_pass_2d →
  [bloom → tonemapping] (PostProcess) → ui_pass → upscaling`;
- `RenderContext` — SystemParam с SystemBuffer-состоянием: энкодер
  каждой системы уходит в `PendingCommandBuffers` **в топологическом
  порядке систем** (док у `RenderContextState`), сабмит в конце
  `camera_driver`; GPU исполняет энкодеры в порядке сабмита →
  однотimestamp-система между пассами ставит кумулятивную GPU-границу,
  дельты соседних границ = GPU-длительности сегментов. Нужен только
  env-гейт на фичах устройства и системах — публичный API, без патчей.

**Инструмент** — коммитится (прецедент perf-тогглов `dev.rs`;
`QWE_PERF_GPU_CUT=1`), в future заездах переиспользуется:

- `dev.rs` — `gpu_cut()` (env), `main.rs` — условные
  `WgpuSettings { features: TIMESTAMP_QUERY | TIMESTAMP_QUERY_INSIDE_ENCODERS }`
  в `RenderPlugin`;
- `src/gpu_cut.rs` — плагин: `RenderStartup` — QuerySet (6 меток) +
  два ring-буфера MAP_READ (256-выровненные); в `Core2d` — маркер-системы
  (каждая — один `write_timestamp` в свой энкодер, гейт камеры на
  window-target, чтобы офскрин-камера не путала метки):
  ts0 перед opaque, ts1 после opaque (перед transparent),
  ts2 после transparent, ts3 после PostProcess, ts4 после ui_pass
  (перед upscaling), ts5 после upscaling; resolve-система после
  upscaling — `resolve_query_set` в ring-буфер + `map_async` в статики;
  poll-система раз в кадр (`RenderGraph` после Submit) —
  `RenderDevice::poll(Maintain::Poll)`, чтобы колбэки map_async шли;
- main-мир: `Update`-принтер — строка `gpu cut:` раз в секунду
  (`total | opaque | transparent | post | ui | upscale`, зум камеры в
  строке для сопоставления) + `gpu spike:` пофреймово при total выше
  порога (`QWE_PERF_GPU_SPIKES=<ms>`, при unset — только секундные);
- сегменты: opaque [0→1], transparent [1→2], post [2→3], ui [3→4],
  upscale [4→5], total [0→5]; msaa_writeback/clear — вне меток, внутри
  total (недостаток отмечается в записи).

**A/B-добор** (атрибуция внутри сегментов): `brp hide/show` слоёв
(`tree_crowns`, тени крон, здания/дороги/поверхности) на фоне
секундных `gpu cut` — доля слоя в transparent по дельте тотала;
vsync-пробой как независимый кросс-чек тотала.

**Темп-патч** (не коммитить, `/tmp/perf44-temp.patch`): перегонка
`/tmp/perf43-temp.patch` — кадровые стены + `crossing cut` + `cmd cut`
нужны для сопоставления GPU-спайков с CPU-джерками на кроссинге 0.2;
clippy-гейты патчей 43 (лет-чейны, `is_multiple_of`) учтены.

   `show`); развёртка зума колесом через 0.2 вниз-вверх — `gpu spike`

## Верификация

- Инструмент: `QWE_PERF_GPU_CUT` unset — ноль эффекта (плагин не
  добавлен, фичи дефолтные); числа сегментов неотрицательны и
  суммируются в total; total не противоречит vsync-пробою (пауза,
  дальний зум: total > 16.7 ↔ `frame_time` 33.3).
- Разрез: медианы ≥3 окон на зум; холодный первый прогон свежего
  процесса в медиану не берётся; A/B-дельты слоя больше шума окна.
- Фикс: `tools/check.sh` OK; живая пара 3+3 подтверждает GPU-числа;
  инварианты не тронуты (тик, бит-в-бит выходы).
- Плато: куски названы стенкой/продуктовой с владельцем; свежий
  рейтинг в конце записи 54.
