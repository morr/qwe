Цель: разрез post по системам и GAP по стыкам/типам команд; фикс

## Единица измерения

Как в спеке 38: рантайм-куски измеряются **мс CPU на секунду стены**
(доля одного ядра); стенка секунды у рантайма нет.

- тиковые куски: `мс/с = ms/тик × 64 × actual` — при actual ≈ 15 это
  960 тиков/с;
- кадровые: `мс/с = мс/кадр × fps` (60 под vsync);
- планка: **≥100 м/с** (10 % ядра);
- жёсткий потолок тика — `SIM_FRAME_BUDGET_MS` (20.3 мс/кадр): при 30×
  бюджет тика ≈ 0.106 мс, превышение режут регулятор и frame-budget
  guard (TickDebt) — их работа не рычаг, а следствие.

## Инварианты сима (правка тика обязана их держать)

- **Поток решений бит-в-бит**: RNG-роллы живут в `behavior.rs` и на
  переходах, не в `decide`; решение продвигает свой `WanderIndex` ровно
  на тех же тиках, что и раньше. Снижение объёма команд — правка тика:
  любая правка, сдвинувшая хотя бы один ролл, replay-breaking;
  `tests/determinism.rs` пинует.
- **Telemetry**: `killed + escaped + alive == HUMAN_COUNT` (проверка на
  паузе — на скорости два BRP-чтения из разных тиков врут).
- Порядок SimSet (`SpatialRebuild → DemonBehavior → HumanBehavior`),
  демо-спавнер до `SpatialRebuild`, гейты `RunFixedMainLoop` — не
  переставлять из разреза.

## Направление — два разреза, TEMP-патчи в /tmp, не коммитить

### Разрез post по системам

Инструмент — probe-скобки, прецедент `frame_phases.rs` (скобки
`sprite_check_*`/`sprite_mark_*` вокруг движковых систем PostUpdate
уже работают). Шаг 1 — состав PostUpdate снять с живого мира без
правок: `brp raw schedule.graph` (печатает системы и их порядок) — по
нему выбрать группы. Кандидаты (по составу PostUpdate в bevy 0.20):
распространение трансформов (`TransformSystem::TransformPropagate`),
видимость (`VisibilitySystems::CheckVisibility`), UI (`UiSystem`:
layout/text/focus), спрайтовые скобки (`calculate_bounds_2d`,
material-changed маркер — их стоимость frame_phases уже показывает
отдельно).

Шаг 2 — TEMP-патч: пара exclusive probe-систем на группу
(`.after(...)` движкового сета), аккумулятор секундных средних под
`QWE_PERF_CUT=1` — тот же идиом, что `CutAccum` патча записи 50
(`/tmp/perf40-cut.patch`): раз в секунду строка `post cut: <группа> …`.
Probe с явным `.after` сидит в топологическом порядке сразу за группой;
стена между соседними probe = время систем между ними, включая
параллельную работу (probe exclusive — синхронизирует executor).
Контроль полноты: сумма групп против стены `post` из frame cut.

### Разрез GAP по стыкам и типам команд

- **Стыки**: сегменты цепочки тика — TEMP-патч записи 50
  (`QWE_PERF_CUT`, `tick cut: … | seg/tick: …`) уже печатает
  head/spatial/demon/human/move/tail; GAP стыка = стена среза − сумма
  измеренных систем внутри (по `sim/*_ms` из диагностик + известные
  измерения записи 50). Стыки: head (флеш спавнера/предыдущего кадра),
  spatial→demon, demon→human, human→move, move→tail.
- **Типы команд**: TEMP-счётчики на местах команд поведения —
  переходы в Flee и из Flee (panic / calm-down), заявки пути
  (wander-таргет, urgent-репас, chase-репас), спавн/деспавн (демоны,
  kill, escape), прибытие to_idle. Атомарные счётчики Relaxed в
  тик-системах, печать раз в секунду из того же патча. Объём команд/с
  против GAP стыка — цена одной команды на стыке; рычаг — снижение
  объёма, осторожно: тик правит поток решений (см. инварианты).
  Перекрёстная проверка без правок: BRP-дельты счётчиков и маркеров
  за окно (`brp delta 30 Human HumanFleeTag Telemetry …`) — чистые
  объёмы волн.

## Протокол базы и разреза

- запуск из worktree: `BRP_PORT=15704 QWE_PERF_NOAPPNAP=1
  QWE_PERF_NOVSYNC=1 QWE_PERF_FRAME_SPIKES=30 QWE_PERF_PHASE_SPIKES=40
  QWE_PERF_CUT=1 caffeinate -i cargo run`, фоном, строго из каталога
  worktree (`cd <worktree> && pwd && cargo run` одной командой — урок 40);
  порт 15704 или свободный (15702 — пользователь; 15703 — не BRP);
- тёплый старт Парижа (`brp res set City . '"Paris"'`, готовность по
  `warmup: done`; парсы считать по `osm: parsed` — при тёплом старте 0,
  снапшот-хит), затем **3 прогона рантайма**: свежий процесс, первый
  холодный в медианы не берётся, **32 с между прогонами** — урок
  записи 36; перед парой гасить свои фоновые процессы прошлого прогона
  (урок 41; после quit — `procs`/`pgrep` — урок записи 49);
- прогон: `brp speed 30` (actual оседает ≈ 15 — читать обратно), окно
  60–75 с под диагностики, пауза; из лога — медианы блоков `sim/…`,
  строки `frame cut`/`tick cut`/счётчики патча; `SimSpeed`/`TickDebt`
  по BRP до и после;
- инвариант телеметрии — раз за прогон на паузе;
- шторм натуральный, фаза прогона (мир T+, census) фиксируется в
  отчёте; **DemonStyle и прочие settings-группы по BRP не писать** —
  правка персистится в `settings.toml` пользователя.

## Ожидание и риски

- GAP по записи 50 размазан ~30 м/с на стык — вероятен вердикт «нет
  куска ≥100»: тогда плато-отметка. Но разрез обязан это показать
  числами: если один стык (например, human→move на волне Flee⇄Wander)
  несёт непропорциональный кусок, у него появится свой рычаг.
- post — движковые системы на 20k спрайтов; кандидаты на тяжёлые —
  распространение трансформов и видимость (каждая пешка двигается
  каждый тик при 960 тик/с → `Changed<Transform>` на всё население
  каждый кадр). Если разрез покажет ≥100 в одной группе, рычаг
  обсуждается по её механике; «движковый» не значит «не рычаг» —
  но и переписывать движок ради прототипа не будем.
- Probe-скобки искажают: сами probe-системы стоят стену (Instant +
  запись) — на фоне 2.18 мс/кадр их вклад <1 %; контроль — сумма групп
  против целой стены post.
- Межпрогонный шум ±8–15 % (запись 35) — медианы 3 прогонов; куски
  сравнивать только против той же скорости и фазы мира.
- Мир на скорости деградирует (трупы, шторм) — фаза фиксируется.
