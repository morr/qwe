## Runtime-кадр под нагрузкой

- **Сим не стена ни на одной скорости.** Спокойный 1×: тик 0.44 мс (медиана,
  n=83, полный набор 20K человек + 20 демонов + шторм у портала). Скорость 20
  (губернатор: effective 20, actual 15.0, affordable 30, pipeline 30): тик
  0.25 мс, max 0.39; `wait`/`wait_peak` 0; **TickDebt 0/0** —[frame-budget
  guard](determinism) ни разу не вступил. Все `sim/*_ms` в сотых долях мс.
- Очередь pathfinding в равновесии 1×: ~19.7K в очереди при ~90 ответах/с
  (1.5/кадр, avg 0.06 мс) — пешка получает маршрут раз в ~3.7 минут, очередь
  не растёт; на 20× осушается (24.6/кадр, 1476/с), wait 0.
- **Кадр прижат vsync — fps больше не сигнал стоимости.** `frame_time` стоит
  на 14.8–17.9 мс во всех состояниях: живой 1× и 20×, пауза, дальний 4.5,
  средний 0.82, ближний 0.085. Контрольный пробой — пауза на ближнем зуме:
  сим-работа нулевая, кадр тот же 14.8–16.8. Мгновенный fps ~60 с первого
  сэмпла в обоих процессах (avg > 60 в первой строке — артефакт кумулятивного
  среднего). `QWE_PERF_NOVSYNC=1` ставит `PresentMode::AutoNoVsync`
  (`dev.rs::perf_present_mode`), но на macOS/wgpu Metal некапнутого present
  нет — AutoNoVsync откатывается в Fifo, такт 60 Гц. Стоимость кадра ниже
  слота невидима; валиден только спайк-детектор (`Time<Real>`). Поправка в
  `.claude/live-app-project.md` — тем же изменением.
- **Спайки — только дискретные события** (порог 30 мс, за оба процесса):
  кроссинги зума по порогам — 0.35: 33 мс, 0.20: 42, 0.15: **57 (кроны)**,
  0.09: 41; фаза заполнения архетипов в первые ~30 с после входа — 3–5 кадров
  по 30–40 мс (census 1271 → 1280, потом замер); входные кадры (0.6–1.2 с
  main, выше); один необъяснённый 270.6 мс после телепорта камеры с оф-мап
  позиции (повторить не пытался — одиночка). Установившийся кадр живёт внутри
  vsync-слота.

## Остаток: рейтинг по убыванию цены

1. **Ground pockets парса — 1.95 с, 44 % parse-стены** — крупнейшая
   единичная фаза всей оставшейся измеренной работы проекта, ни разу не
   резалась. Платится на первом прогоне города и после бампа `QUERY_VERSION`
   (для нового города — вторая по величине статья после скачивания). Спеки
   нет; первый шаг — `planned/24-*.md` (метод записей 20–34). **Цель заезда
   26.**
2. **Кроссинги зума 32–57 мс** — юзер-видимый джерк на колесе, максимум на
   кронах (0.15). Под стену не дотягивает; заезд, только если джерк станет
   темой (альтернатива карманам, если автор preferует ощущение от прокрутки
   цене редкого пути).
3. **Заполнение архетипов** — 30–40 мс в первые ~30 с после входа; шторм
   записи 15 на новых цифрах на порядок меньше и больше не стена.
4. **Входное окно ~1.5 с** (флеш 0.45 + extract 0.46 + сканы 0.10 + гейты
   0.37) — каждый кусок ≤0.5 с, апстрим/каунт/закрыто (записи 23/30; дороги
   whole set — 28/32/33/34).
5. Мелочь: 270-мс телепорт-одиночка (не воспроизведена); fences ближнего
   входа 0.8–1.1 — фоновая сборка записи 17, кадр не держит.

## Метод

- Worktree-пара (`.worktrees/perf25-base` @ `b88a5d43` / `perf25`), кеш
  `assets/osm` скопирован с mtime, `tools/seed-worktree-target.sh`; порт

- Тёплый старт — таймстампы (снапшот-хит → `warmup:`), 4 перезагрузки Paris
  в процессе 1 + контрольная в процессе 2; свежий процесс каждого — холодный,
  в медианы не взят. Перезагрузка — `brp res set City . '"Paris"'`, ожидание
  новой `warmup:`-строки по смещению в логе (`brp ready` матчит старую).
- Парс при промахе — `paris_*.bin` убран в /tmp перед процессом 2; после
  успешного парса приложение записало свежий снапшот (JSON не менялся,
  заголовок сошёлся), временная копия удалена.
- Стресс — `brp speed 20` (губернатор читается обратно), TickDebt, 25 с
  диагностики; зумы — колесо через `brp hover`+`MouseWheel` с чтением `brp
  cam` (кламп 0.05–4.5), кроссинг — 8 шагов за ~2 с.
- Шум межпрогонный ±8–15 %; по Mercator — vsync-пробой (пауза × ближний зум)
  важнее любых абсолютов fps.
