# 62. Кеш проёмов оград строится рядом с fill_base

Дата: 2026-11-20 (Обзор №19). Хвост записи 61: серийный префикс тёплой
загрузки Парижа — рид 0.09 + fill 0.26 + gates 0.146 + prune 0.08; в шаге
калиток малых кандидатов не осталось, поэтому разрез взял сам fill-шаг —
самый крупный серийный остаток.

Дорожная половина кеша проёмов — индекс отрезков всех дорог города
(`Grid::insert_segment` по каждому отрезку каждой не-мостовой дороги,
сотни тысяч вставок) плюс `RoadNodes::new` (сортировка всех вершин всех
дорог) — ~84 мс заливки, при том что `fill_base` её не читает вовсе: кеш
нужен только `fill_fences` и раундам калиток после.

## Что стало

`fill_from_mapdata` строит кеш на вспомогательном потоке рядом с
`fill_base` (`std::thread::scope` — та же механика, что у
`map/parallel.rs::in_parallel`): оба шага читают только `MapData`, кеш —
чистая функция карты, порядок результата от гонки не зависит. Готовый кеш
кладётся в `fence_cache` до `fill_fences` (её `unwrap_or_else`-сборка
остаётся для сеток, миновавших заливку, — рукописные тестовые сетки). На
пустых оградах кеш не строится вовсе.
