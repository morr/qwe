# Запись 28 — общая работа двух ступеней дорог: скелет сети один, CPU пары −10 % — стену дележ не двигает

Статус: фикс заезда 18 (`planned/17-road-skeleton.md`), гипотеза записи 27
разрешена измерением — в пользу CPU, не стены. Двухступенчатый бенч (3+3
вперемежку, один прогон разогрева, одно состояние машины), живая пара (3+3
перезагрузки Парижа, два worktree — master против ветки фикса, порты
15706/15704, сосед на `brp pause` во время перезагрузок измеряемой
стороны), разрез — отпечатки фаз: временные `eprintln` в `build_roads`
(cumulative wall + вершинный отпечаток слоёв и счётчиков), сняты до
коммита; свип вызовов тестов — механический, с ассертом на каждый файл.

**Гипотеза.** Запись 27: «s1 платит за drawn/gores/medians/node_paint
почти столько же, сколько s0 (582/457/301/362 против 513/442/314/335)» —
скелет сети общий, считается дважды; ожидалось «−1.5–2 с второй ступени и
половина дележа ядер».

Пофазно (cumulative wall, s0 против s1): drawn+stations 283/288,

**Правка** (коммит `052a6975`, `perf18`): ступень — аргумент, не поле.
`Drawn::new` теряет `verge_step`, `verges_drawn(index, step)` принимает
её сам (и `kerb_returns(drawn, scale, step)`,
`street_verge_geometry(..., step)` — оба её читателя); `build_roads`
разделён на `road_skeleton(map, style, shape)` — подготовка сети,
станции краски, островки узлов, узлы с краской (с островками подходов
уже в разрывах), траектории — и `build_roads_from(&skeleton, verge)` —
обочинные куски и укладка. `prepare.rs` строит скелет один раз
(`OnceLock`, `get_or_init` — первый дорожный поток строит, второй ждёт);
`rebuild_roads`/`show_road_steps` зовут прежнюю дверь — скелет и есть
общий префикс одноступенчатой сборки, на пересборке регрессии нет.
~25 тестовых вызовов `Drawn::new`/`kerb_returns` переведены механическим
свипом.

**Главный вывод — стену дележ не двигает, и это теперь измеренный факт,
не догадка.** Стена whole set — лейн ступени 0, а он равен «скелет + свой
финал» при любой схеме: общий скелет обязан быть готов до начала любого
финала, так что критический путь пары — скелет + max(финал s0, финал s1)
— совпадает с прежним max(полная s0, полная s1). Выигрыш только в CPU:
минус один скелет (~0.4 с бенча, ~0.5–0.9 живьём с дележом), который
раньше молотился параллельно с первым. Дележа ядер на скелетных фазах
больше нет, но давление остальных лейнов (buildings 3.0, polymesh 1.6,
мелочь, заборы) заполняет ядра и без второй копии — живые лейны не
двинулись. Ступень 1 живьём даже чуть тяжелее (2.5 → 2.9): её финал
теперь стартует ровно вместе с финалом s0, а не со сдвигом в полскелета.

**Цена и отвергнутое:**

- **Краска узлов ~330 мс бенча строится обеими ступенями, а спавнится
  одна** (выход ступеней доказанно одинаков — «у краски нет ступеней
  обочин»). В скелет её не вынести: `paint_junction_marks` читает слой
  улиц финала. Обмен готовым painter-ом между финалами — сериализация,
  стены не двигает (краска нужна обеим). Пунктир.
- **`kerb_returns` остался в финале** и тащит устья (`mouths` читает
  `streets()`) и клинья развилок: его gather монолитен, обочины собраны
  в общем проходе — разделение уличной и обочинной частей (скелет мог бы
  забрать ещё ~124+165 мс) — отдельная работа в `corners/gather.rs`
  (1199 строк, порядок укладки закреплён тестами).
- **scraps 600 мс ступени 0 — крупнейшая фаза финала** — параллель
  насыщен (431 wall / 4300 CPU, запись 27); рычаг — правила лоскутов,
  решение записи 24 в силе.
- **Слияние проходов двух ступеней** (одна лента кладёт асфальт один раз,
  тротуары/обочины — дважды) — единственный рычаг самой стены; большой
  отдельный заезд, теперь с готовым списком того, что ступенезависимо.
- Следующая стена после дорог (3.3–3.4) — **buildings 3.0**.
