# 73 — Экономика демонов на 3500: инкрементальная сетка и четверти acquisition (план ×10, фаза 6)

2026-11-22, звено №52, ветка pop52 (1 коммит, ff на a9914770), Тула 200k живьём,
A/B чередованием base (master 1d842d65) → new → base → new в одной сессии,
на каждого: кап демонов 3500 (интервал 0.03 с), Astar, скорость 30.

## Что сделано

Две части плана Ф6, обе механики):

- **Сетка демонов инкрементальная**, как людская: обсерверы `Add/Remove<Demon>`
  (спавн читает `Transform` — `SimPosition` у новорождённого ещё дефолтный)
  плюс отчёты `moved`/`insert` от всех писателей `SimPosition`: шаг мовера,
  толчок сепарации (раньше демонов пропускал), три места спасения, бросок
  в `chase` (плюс-сверка: `moved(entity, было, стало)`). `rebuild_demon_grid`
  удалён вместе с диагностикой `sim/spatial_ms` — её предмет исчез;
  `SpatialGrid::rebuild` остался (сброс `reset_queued_wanderers`). Рождённый
  на тике демон сидит в сетке на своём тике: флейш спавна падает на грань
  `Spawner`→`DemonBehavior` (щель порядка `DemonGrid` стала пустым слотом
  расписания), обсервер срабатывает на ней — прежний пин
  `a_demon_born_on_a_tick_enters_the_demon_grid_on_that_same_tick` держит
  без изменений; эквивалентность rebuild/инкрементально — новый тест
  `the_incrementally_kept_demon_grid_matches_a_rebuilt_reference`.
- **Acquisition четвертями в `Live`** (паттерн Ф2): `DemonSlice<S>` по
  `PawnId % 4` в спавне, `acquire_slice::<S>` с `run_if(tick % 4 == S)` —
  одна четверть блуждающих за тик; ядро общее с детерминистским
  `acquire_targets` (`acquire_pass`). Ровно один срез на тик ⇒ каждый
  проход видит полные `ChaseClaims` (заявка этого тика доехала до
  следующего среза), перезаявки нет; задержка агро ≤3 тика (~100 мс)
  невидима за темпом спавна. Под тумблером детерминизма срезов не
  существует — реплей идёт цельным проходом каждый тик.

- Критерий плана «демоны 3500 ≤ ~0.3 мс/тик» для изменённых частей Ф6:

## Урок инициализации расписания (не перф)

Регистрация «веток» — `acquire_targets` и срезов — отдельными элементами
**внешней цепочки** кортежа с явными рёбрами `.after(pick).before(chase)`
роняет расписание: ребро цепочки ложится после всей тройки
`pick→chase→devour`, явное ребро назад в `chase` замыкает отношение
с множеством, членом которого `chase` остаётся по собственному
`SystemTypeSet` — `CrossDependency` на инициализации `FixedUpdate`. Пять
демон-тестов падали на месте, а реплей-тест Ф2 (`no_far_tag…`) висел
наглухо в pump-цикле — инициализация расписания никогда не доезжала.
Правка: у кортежа `DemonBehavior` внешней цепочки нет; порядок
`sync_demon_speed` против веток держит прямое ребро
`.before(pick_wander_targets)`. Симптом-подсказка на будущее: «тест
висит в цикле обновления» + «пять тестов падают разом» = читать панику
**инициализации**, а не выполнения.

## Вердикт

Ф6 выполнена по механике и замерам плана; суммарный тик в бюджете 15×
(8.2 мс/тик стационара шторма; тихий мир по журналу 51 — 6.3). Полка
дальше: acquisition 0.49 и chase ~0.4 — цена по-прежнему штормовая
(погоня/бег), целиться ниже без изменения семантики заявкок — граница
дизайна (`ChaseClaims` обязаны быть полными у каждого прохода). Владе́ль-
ческий Париж не замерялся — демон-экономика не зависит от города.
