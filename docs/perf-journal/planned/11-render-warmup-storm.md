# Запланировано 11 — рендер-сторона шторма warmup: заливка render-мира, спавн-флеш 20k, первый extract

Приоритет: **1** — заезд 13. После записи 21 строковая метрика warmup упёрлась в
рендер: фиксы main-потока сделаны (подача без переспроса, один inspect-перебор),
осталось окно рендера. 07 занята разведкой крови — не трогать;
10/полимеш закрыт записью 22. Гейты 1.44 с и дорожная стена whole set —
не цель этого заезда, фокус не размазывать.

## Проблема

Тёплый старт Парижа (снапшот-хит, свежий процесс), запись 21: строка
`warmup:` — **1.67 с**, wall окна (`transition: Some(Loading)` → `warmup:` по
таймстампам лога) — **1.01–1.04 с**. В окне сидит заливка мира render-миром:
render-кадр спайком **1634–1657 мс** (диагностика fps 0.6), а wall держат
спавн-флеш 20k и первый extract.

Рядом (запись 15 «Отвергнутое»): `AssetChangeCheck` на
`MeshMaterial2d<SpriteMeshMaterial>` — самый горячий лист шторм-профиля
(+1422 сэмпла/10 с): медленный путь фильтра `Changed<Mesh2d> || AssetChanged`
сканирует ~21k пешек, пока силуэты мутируют материалы. Заезд 15 не тронул его
дважды: правка — партия материалов в `bevy_sprite_render` (апстрим), и на
здоровой фазе кадр и так помещается в пин. Теперь у кандидата своё окно —
вход в мир — и своя метрика.

## Механика (из кода, ноябрь 2026)

**Окно входа, main-поток.** `OnEnter(Playing)` спавнит весь мир одним флешем
(`WorldInitSet::Spawn`): слои карты из `PreparedMeshes` (спавн-флеш уже
разгружен лоад-потоком — заезды 11/12), рельсы, машины, деревья, заборы,
портал, и `spawn_population` — 20k пешек по 15+ компонент. На каждый спрайт
обсервер `bevy_sprite_render` вешает `Mesh2d` (общий квад), `add_material`
проводит все свежие спрайты через бакет-кеш материалов (ключ — полный набор
полей `Sprite`: картинка, атлас, **цвет**, `custom_size`, …; цвет одежды
квантован — ~1000 бакетов, запись 02) — первый заход в каждый бакет это
новый материал `materials.add`. Дальше два апстримных конвейера:

- `check_entities_needing_specialization::<SpriteMeshMaterial>` —
  `Or<(Changed<Mesh2d>, AssetChanged<Mesh2d>, Changed<MeshMaterial2d>,
  AssetChanged<MeshMaterial2d>)>` — на входе матчатся все 21k (спрайт только
  что вставлен);
- `mark_2d_meshes_as_changed_if_their_materials_changed` — тот же лист, но
  с мутацией `Mesh2d`.

`AssetChanged` — не архетипный фильтр (`bevy_asset::asset_changed`):
когда **хоть один** материал типа изменился с прошлого прогона системы, путь
проходит **все** сущности с компонентом — по одному hash lookup на сущность;
когда не изменился — нулевой. Новые материалы в окне: ~1000 уникальных
цветов спавна; каждый зум-лаг (`resize_silhouettes_on_zoom`, 2048 спрайтов за
кадр) заново заводит бакеты нового размера — ~1000 добавлений на первый кадр
лапа; в шторме 30× лист держат тинты паники и те же зум-лаги. Кеш материалов
`add_material` — `Local`, эвикт-проход по всему кешу на каждый прогон
системы (~0.5 мс/кадр на простое, запись 02).

**Окно входа, render-поток.** `RenderDiagnosticsPlugin` (`QWE_PERF_RENDER_DIAG=1`)
даёт CPU-время каждого пасса (`render/<pass>/elapsed_cpu`) в выводе
`LogDiagnosticsPlugin` (строка раз в секунду — окно ~1.6 с даёт 1–2 строки,
но спайк кадра доминирует в среднем). `RenderAssetBytesPerFrame.max_bytes`
по умолчанию `None` — загрузка мешей карты в GPU не размазана, идёт разом.
На Metal пишется только CPU — этого и надо.

**Метрики окна** (запись 21, «Методическая находка»): `warmup:`-строка и
`frame spike` (`QWE_PERF_FRAME_SPIKES=30`) меряют **рендер** (`Time<Real>`
обновляется из канала render-мира); wall окна — только по таймстампам лога.
Сравнивать их между собой нельзя; wall-замер — таймстампы.

## Направление решения — решение по разрезу

1. **База** — 2–3 прогона тёплого старта до правок (`RENDER_DIAG` +
   `FRAME_SPIKES`), таблица пассов и спайков; wall по таймстампам.
2. **Разрез** — что именно в окне:
   - пассы render-потока (`elapsed_cpu`): extract / sync / prepare / queue —
     где сидит спайк 1.6 с;
   - main-поток: флеш спавна (гейт `WorldInitSet::Spawn` — таймстампы строк
     лога вокруг), PostUpdate-конвейеры спрайтов;
   - `AssetChangeCheck`-медленный путь: доля в окне (контроль `QWE_PERF_POP`
     0/2000/20000 — пропорционально населению, значит по пешкам, не по карте).
   Временные приборы — `info!`-фазы до коммита (прецедент записи 21), снять
   до коммита (`git restore`, пока дифф состоит только из замеров).
3. **Фикс по вердикту** — один кандидат, не все сразу:
   a. **Материалы силуэтов** (заданный кандидат): уменьшить цену медленного
      пути или число новых материалов. Порядок проверки —
      **сначала достижимость через публичный API** (прецедент-блокер
      `bevy_tasks::spawn_many`, запись 16): оба конвейера и кеш — апстримный
      код `bevy_sprite_render`/`bevy_asset`, проектного хука туда нет.
      Если достижимого проектного рычага нет, а доля пути в окне значима —
      vendor-патч (прецедент polyanya) — только по цифрам, взвесив цену
      носимки патча.
      Порог: если медленный путь < ~10 % окна — не брать вовсе (запись 15
      отвергла его и на здоровой фазе).
   b. **Заливка render-мира** (extract/sync/prepare): кандидат берётся
      по доминирующему пассу — решение за разрезом (например, размазать
      первый extract нечем — он по дизайну один; если доминирует prepare
      больших мешей — проверить, чем ограничена загрузка). Рычаги брать
      только те, что не меняют картинку и не трогают симуляцию.
   c. **Спавн-флеш 20k** (main-поток): если доминирует флеш — кандидат
      «разнести по кадрам» меняет холд warmup и механику входа, тяжёлый;
      брать только если всё прочее дешевле, и только по цифрам.

## Инварианты (не трогать)

- **Диспетчер, `rescue_trapped_entities`, warmup-каунт** — записи 21/16.
- **Рендер не меняет картинку**: оффскрин-кадры до/после (силуэты пешек,
  гало демонов, кровь, портал, вуаль) — идентичны на глаз; правки только
  пути к той же картинке.
- **Симуляция не трогается**: ярды реплеев и `a_restart_replays_the_run`
  зелёные (`tools/check.sh`); правки рендера не заводят компонентов, тегов
  и систем в `SimSet`/`FixedUpdate`.
- **Новых спавн-сайтов не заводить** (`DespawnOnExit`, счётчик
  `world reload: N scene entities survived` — 0).
- **`AssetChangeCheck` уже отвергался** (запись 15): сначала прочитать
  «Отвергнутое» и проверить достижимость через публичный API — не повторять
  отвергнутый заход вслепую.
- Кеш материалов и квантование цвета (запись 02) — не деградировать: число
  бакетов и эвикт-проход остаются дешёвыми.

## Шаги

1. Спека (этот файл).
2. База: 2–3 живых прогона тёплого старта Парижа до правок — снапшот-хиты,
   `caffeinate -i`, `QWE_PERF_NOAPPNAP=1`/`NOVSYNC`/`FRAME_SPIKES=30`,
   `QWE_PERF_RENDER_DIAG=1`, фоном; wall — по таймстампам строк лога
   (`transition: Some(Loading)` → `warmup:`), пассы — `elapsed_cpu`,

3. Разрез (временные `info!`-фазы/контроль `QWE_PERF_POP`, до коммита);
   вердикт: где время окна.
4. Фикс по вердикту (мелкими коммитами, стиль git-скилла) →
   `tools/check.sh` по изменённым файлам.
5. Живые замеры после: 2+ прогона в том же состоянии машины; контроли ниже.
6. Запись 23 в `docs/perf-journal/` (стиль записей 16–22), строки в артефакте
   (get_artifact → правка → update_artifact с expectedRev — свежая ревизия),
   коммиты.

## Верификация

- Окно: база 2–3 прогона → после 2+; дельта против межпрогонного шума
  (±8–15 %); сравнение только в одном состоянии машины; wall — только по
  таймстампам; `warmup:` и `frame spike` — только как render-метрики.
- Контроли: `osm map:` бит-в-бит между прогонами; `scene entities survived`
  — 0; `panicked`/`ERROR` — 0.
- Картинка: оффскрин-кадры до/после в одном состоянии машины — пешки,
  гало демонов, кровь, портал, вуаль на месте, различий на глаз нет.
- Симуляция: ярды реплеев и `a_restart_replays_the_run` зелёные.
