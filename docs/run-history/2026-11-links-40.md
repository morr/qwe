Задача: сороковое звено — обзорная форма (меню оптимизаций исчерпано,
№37–39). master на старте 5914fdbe. Угол свежий: ни одно звено не гоняло
сим на длинной дистанции — №10 делал пять загрузок с короткими наблюдениями
после warmup, №9 свипал рост коллекций статически; динамика сущностей и
памяти на часах сим-времени не была проверена никем, включая конечное
состояние вымирания населения.

## Методика

Worktree perf40 (сид owner-view settings.toml: Париж@0.4, Astar), тёплая
сборка, `QWE_PERF_FRAME_SPIKES=30 QWE_PERF_NOAPPNAP=1 caffeinate -i`, BRP
15703. requested 30 с T0; 7 точек за ~25 мин стены, ~4700 сим-с (~1.3
сим-ч) мира. Сэмпл = пауза → counts/ресурсы/память → resume.

## Найдено

- **Договор населения держится на всей дистанции**:
  alive+killed+escaped==20000 бит-в-бит на всех шести сэмплах (T0
  19984+16+0 … T5 17003+2800+197); debug-census-ассерт не сработал ни разу
  за ~286k тиков. Население убывает монотонно (спавн людей только на входе
  в мир), escaped работает (197), трупы 1:1 с killed, BloodPool 1:1 с
  трупами, души транзиентны; сущности 28310 — рост следует за трупами
  (потолок HUMAN_COUNT).
- **Демоны стоят на капе 20 — и это не баг**: сохранённый pref владельца
  `DemonStyle.cap=20` (ползунок Sim-вкладки персистится); спавнер честно
  остановился на капе — таймер замораживается при spawned>=cap
  (demon/systems.rs::tick_spawner). Первая живая демонстрация договора
  «настройки переживают выход» в динамике мира.
- **Регулятор и guard пережили волны голода по дизайну**: под волнами CPU
  effective отступал до 0.135×, guard абсорбировал взрывы в TickDebt
  (deferred 3241 с кумулятивно), в тихих окнах долг стекал до owed 0 и
  скорость возвращалась к ~19×. 0 паников/ERROR за весь soak; WARN 2
  (известные load-time degenerate polygons).
- **Спайки волн — rest-сигнатура**: разборы tick spike называют rest
  100–500 мс (флеши/синк-поинты/пул) при тихих сегментах — голод машины,
  не работа какой-то системы (шторм 04:36:59–04:37:19 совпал с обработкой
  сэмпла T1; уроки №31/№33/№34 подтверждены soak-ом).
- **Шаг footprint 3.3→7.0G** в самом тяжёлом штормовом окне, плато
  7.0–7.1G до конца прогона (peak=current); не коррелирует ни с сущностями
  (+69 трупов за окно), ни с долгом (owed уже 0). Отложен в
  docs/deepening-plan.md с триггером (жалоба владельца на память
  длительных сессий / воспроизведение в нормальной сессии): разрез
  heap-гистограммой по методу №23 — отдельная работа; стационарные числа
  №23 (2.2–2.3G Париж) не опровергнуты — шаг случился только под голодом.

## Негативы, остатки и уроки (следующим звеньям)

- Soak на машине с живой агентской сессией contaminated по определению:
  каждый сэмпл/вызов модели = 1–3 мин CPU = волна голода. Осмысленны
  инварианты/консервация/восстановление, НЕ абсолютные скорости и спайки.
  Честный горизонт сим-времени — дельта SimClock между сэмплами, не
  SimSpeed.actual (окно усреднения + волновые отступания).
- vmmap-грепка: `grep 'Physical footprint'` — строки «Physical footprint:»
  и «(peak):»; старый паттерн `physical footprint|dirty` ловил мусор типа
  «unused but dirty shlib».
- `texts tick` матчит строку pathfinding-оверлея (в ней «, tick N»), а не
  третью строку панели скорости. Стоимость тика читать через `res get
  SimLoad` (registered: tick_ms/wait_ms/wait_peak_ms/frame_sim_ms/frame_ticks).
- failed% ответов pathfinding 0→27.6→17.3 под нагрузкой — не расследован
  (in-flight ограничен, поиск здоров 0.04–0.72 ms avg); при желании —
  отдельный микропрос accept_answer/retire.
- Archetype census 1324→1339 за ~1.3 сим-ч — почти застыл; рост дают
  переходы поведения (новые комбинации компонентов), волны №33 не
  размораживают его существенно.
- worktree perf40 + ветка perf40 без коммитов (правок кода не было) —
  удалить (`git worktree remove .worktrees/perf40 && git branch -d perf40`).
- Повторяемый порядок soak: worktree-сид owner-view → ready → T0-сэмпл →
  `speed 30` → фоновый `sleep 240` → сэмпл (пауза→чтения→resume) → в конце
  vmmap footprint + гигиена лога.
