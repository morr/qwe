# Запись 6 — Холостой кадр растёт с числом трупов; MSAA/bloom/фактура — не виноваты

Статус: гипотеза → замер.

Идле-кадр на паузе (zoom 0.4, 4K-физический буфер): свежий мир — 15.6–16.6 мс;
после 4 334 трупов (+4 334 луж, 13k спрайтов) — 17.9–22.5 мс. Рост ~1 мкс на
спрайт-кадр — **трупы не деспонятся никогда, и карта замедляется сама**:
эндшпиль на 12.6k трупов даёт +25 мс к каждому кадру навсегда. Направления (продуктовые):
колпак/растворение трупов, либо — как с кронами деревьев — слияние трупов в чанковые
меши на дальнем плане. Требует решения автора: поле боя из трупов — часть эстетики.

**Негативные результаты** (проверено на живом, вклад в кадр 4K):
MSAA 4x → off: −0.6 мс; bloom → снятие компонента: 0 мс; фактура поверхностей
(`SurfaceStyle.texture` 1→0): −1 мс. GPU-стоимость приходит не из них,
а из базовой заливки слоёв карты и спрайтов на 4K-буфере (при физическом 1920×1080
весь холостой кадр умещается в 16.6 мс).

Тик-вспышки: строка лога обогащена контекстом мира (люди/души/трупы/убийства,
eb573bd2) — монотики 12–114 мс остаются неатрибуированными; повторяются в обоих
городах. Первый вариант порога («кадр дороже 25 мс») на высокой скорости писал строку
каждый кадр — 4280 строк за сессию; исправлено на порог **на тик** (c15bf300):
аномалия — дорогой одиночный шаг, а не заполненный кадр. Ловятся в моменте только
`sample` в живом мире — следующим заходом.
