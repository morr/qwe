# Запланировано 40 — разрез рендерной стороны кадра на планке 100 м/с: pre-extract sync, ExtractSchedule по системам, фазы RenderSystems; фикс крупнейшего куска, иначе плато

## Проблема

Приоритет: **1** — заезд 42, разрез-заезд по свежему рейтингу записи 51.
Рантайм на планке ~100 м/с — плато с разрезанными симом и GAP: сим 207 —
структурный кап (запись 50), GAP 134 — сантехника стыков, подтверждена
объёмами команд (запись 51), post ~126 — экстракция рендера и
executor-сантехника bevy 0.20 на 20k сущностей (запись 51), update ≤20.
Следующая территория — **рендерная сторона кадра целиком**, у неё нет
свежего секундного разреза:

- **inter 10.4 м/с** (кадровый разрез записи 50) — весь хвост кадра
  после `Last`: pre-extract sync + extract + render-расписание + сон
  vsync. Под vsync невидим (запись 35: `AutoNoVsync` на Metal откатывается
  в Fifo, слот 16.7); вывод штампов записи 35 — спайк-кадры входа
  (total 1.85–1.94 с, img2 ~1.0), не steady-state.
- **extract_2d_meshes 0.31 мс/кадр ≈ 19 м/с** (скобка записи 51) —
  единственный известный кусок extract, ниже планки.

Архитектура (registry bevy 0.20): без `PipelinePlugin` `SubApps::update`
гоняет рендер синхронно на main-нити после Last — сначала
`SubApp::extract(main.world)` (pre_extract: `update_state` +
`entity_sync_system` — мировая синхронизация, потом `ExtractSchedule`
на скретч-мире), затем Render-расписание (`apply_extract_commands` в
`ExtractCommands` → `PrepareAssets` → … → `Render`/`PostCleanup`).
Extract-системы идут мультипоточным executor'ом: main паркуется в
executor'е, воркеры жрут extract (sample записи 51: ~2.3 мс/кадр парка).

Цель: секундный разрез рендера под `QWE_PERF_CUT` — pre-extract sync,
ExtractSchedule целиком и по крупным системам, фазы RenderSystems из
прецедента `frame_phases.rs` (штампы записи 35), vsync-остаток; полнота —
сумма против стены кадра и против inter 10.4. Фикс крупнейшего куска
≥100 м/с, если рычаг есть и он не в движковых стенах; иначе
плато-отметка в спеке и записи, следующий уровень по свежему рейтингу.

## Единица измерения

Как в спеках 38/39: рантайм-куски — **мс CPU на секунду стены** (доля
одного ядра), у рантайма стенки секунды нет.

- кадровые куски: `мс/с = мс/кадр × fps` (60 под vsync);
- тиковые (контекст прогона): `мс/с = ms/тик × 64 × actual` (≈960 тиков/с
  при actual ≈ 15);
- планка: **≥100 м/с** (10 % ядра); vsync-слот 16.7 мс/кадр — сумма
  сегментов frame cut обязана на него сходиться.

## Не рычаги (стены, не пытаться)

- **Структурные капы рантайма** (запись 50): actual = `MAX_FRAME_DELTA`
  0.25/16.7 = 15× на 60 Гц; целиком тик под `SIM_FRAME_BUDGET_MS`; сим
  207 м/с.
- **GAP 134** — сантехника стыков (запись 51).
- **post ~126** — экстракция/executor движка (запись 51); UI серийно
  ~0.08 мс/кадр ≈ 5 м/с, троттлинг телеметрии 8 Гц уже в master.
- **vsync-сон и present-ждание** — слот дисплея (запись 35): uncapped
  present на Metal/wgpu нет; стена фазы `render` включает present-ждание —
  её CPU-часть отделять от сна, сон не рычаг.
- **vendor-патчи рендера — тоже движок**: обсуждать как кандидата только
  с доказанным куском и явным решением автора.
- **Дорожная лайна** (40–49), **buildings union 514** (31), **polymesh
  vendor** (22/29), **fences фоновая** (17/19), **парс** (38), **деревья
  парса** (37), **сетки стежков** (39/44), **трупы** (06 — продуктовое).
- **Запаркованные кандидаты записи 03** — Update целиком ≤ 20 м/с.
- **Запреты чужих направлений**: `planned/07` (кровь); `map/footprint.rs`
  и `navigation/navmesh/{gates,reach,fill}.rs` (запись 26); vendor-патчи
  полимеша (29); `map/inspect.rs`, `map/osm/download.rs`, `src/loading.rs`,
  `map/osm/model.rs`, `map/osm/model/trees.rs` (запись 30).
- **Регулятор и frame-budget guard** (`sim_time.rs`) — следствие дорогого
  тика, не самостоятельная стоимость.

## Инварианты (правка обязана их держать)

- **Тик не трогать**: рендерный фикс не касается `FixedUpdate`; если
  вдруг коснулся — поток решений бит-в-бит, реплеи `tests/determinism.rs`.
- **Telemetry**: `killed + escaped + alive == HUMAN_COUNT` (на паузе).
- **Выходы бит-в-бит**: счётчики своих строк (`road meshing:`, `osm map:`,
  `entities:`) не двигаются — рендерная правка не меняет парс, геометрию
  и население.
