## Проблема

Парс при промахе кеша — ≈4.5 с на Париже (разведка 35, процесс 2, снапшот
убран, JSON на месте); из них **ground pockets — 1.946 с (44 %)**. Остальные
помеченные фазы на порядок меньше (деревья 0.624, дома-с-тротуаров 0.229,
блоки 0.192, footway-стороны 0.191, скверы 0.136, входы 0.134, парковки
0.134); на непомеченное (чтение JSON, serde) — ≈1 с.

Проход один — `parse/pockets.rs::fill_ground_pockets`, и структура его
стоимости неизвестна: тайминг снимается одной строкой на весь проход.
Внутри:

1. `Scene::of` — покрытия (дороги кусками по `RUN` 16 звеньев с объединением
   по дороге, площади восьми слоёв, острова колец, нарисованные углы
   `corner_paving_contours`) и шесть сеток (`cover_grid`, `link_grid`,
   `apron_grid`, `corner_grid`, рёбра кварталов и зелени `Rim::of` ×2);
   дороги — в `in_parallel`, сетки — однопоточно.
2. Плиточный проход `in_parallel(&tiles, …)` — на плитку 400 м с окном
   ±30 м: собрать покрытия окна, **одна булева операция** (`simplify_shape`
   = полный `FloatOverlay`, NonZero), дырки ≤ 400 м², касающиеся мощёного и
   не касающиеся грунтового.
3. Вливание в зелень (`merge_into_green`) — **полный boolean всей зелени на
   каждый влившийся карман**, по порядку плиток.
4. Фартуки (`green_aprons`) — пробы каждый 1 м по всем рёбрам всей
   замапленной зелени (`parks` + `grass`) **после** вливаний.

## Направление — сначала разрез, фиксы по факту

Разрез (временные `eprintln`, снятые до коммитов, патч в `/tmp`): таймеры
подфаз `Scene::of` (дороги/площади/острова/углы/каждая сетка), плиточного
прохода (сумма точек на объединения, распределение per-tile времени,
число дырок), вливаний (сколько, время), фартуков (проб, время).

Кандидаты фикса — по убыванию ожидания, уточняются разрезом:

- **Плиточный проход** — главный подозреваемый: покрытие у границы плитки
  попадает в 2–4 окна и объединяется заново каждый раз; плотный центр
  Парижа — сотни покрытий на окно. Следующий уровень амортизации после
  объединения по дороге (оно уже сняло −25 % плиточного прохода).
- **`merge_into_green`** — boolean всей зелени (кольцо парка — сотни точек)
  на каждый карман; батчинг карманов по зелени в одну операцию.
- **`green_aprons`** — сотни тысяч проб по сетке; вторично, но измерить.
- **Сетки `Scene::of`** — `link_grid` + `apron_grid` + две `Rim`-сетки
  однопоточно на все звенья и рёбра города.

## Ожидание и риски

- Цель: карманы 1.946 → ≤1.0 с медианой живой пары, parse-стена ≈4.5 → ≈3.6.
  Меньше 0.5 с без потери механизма не обещаю — резать правило (пороги,
  покрытие) нельзя, это геометрия витрин.
- Риски: набор засеянных карманов, их трава и вливания обязаны остаться теми
  же; FP-сдвиги от переупорядочивания объединений — контролировать
  эквивалентным прогоном (счётчик `{sown}`, снапшот). Если разрез покажет
  размазанную стоимость без рычага — зафиксировать в записи 36 и закрыть
  направление (прецедент записи 34).
