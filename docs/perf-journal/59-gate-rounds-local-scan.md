# Запись 59 — раунды калиток перестают пересканировать сетку

Статус: фикса влита (Обзор №16, ветка `perf16` → ff master). Шаг калиток
(`Navmesh::open_sealed_fences`) — самый дорогой серийный остаток тёплого
входа после записи 58. Разрез шага на Париже (probe, release, полный парс):
rounds 226 мс (scan ~166 — по полному проходу сетки на каждый из 6 раундов,
refill ~55 — сброс к базе + перезаливка оград, extend ~3), floods 78
(два полных обхода), doors+idx 18 — из 324 мс всего шага; в игре шаг был
0.36–0.58 с (вид владельца).

**Дизайн** (`gates.rs`, `fill.rs::gate_gap_tiles`, `reach.rs::component`):
за раунды `reachable` только растёт, а `passable` меняется только в боксах
слитых проёмов свежих калиток, поэтому тайл может стать отрезанным карманом,
лишь войдя в такой бокс или уже быв карманным. Раунд 1 — полный проход;
раунды 2+ обходят накопленный набор «когда-либо карманных» тайлов с дельтой
свежих проёмов. Дельта — не разблокировка, а **снимок сетки в боксах до и
после пересбора** (`gate_gap_tiles`): бокс = reach слитого проёма + запас
тайла + `JOIN_EPSILON` (до пересбора слитых списков ещё нет, калитка ищется
среди старых проёмов ограды; промах — открывает ровно свою ширину). Карманы
раунда сортируются по первому тайлу — это порядок, в котором полный проход
нашёл бы их сам; от него зависит разнос калиток (`GATE_SPACING`), поэтому
порядок обязан совпадать с полным проходом бит в бит. Компакт набора —
`retain(!reachable)`: тайл, которого достижимость догнала, карманом больше
не бывает никогда; закрытый пересбором обратно держится (см. трапу). Отметка
«в кармане раунда» — номер раунда в одном `u8`-массиве на все раунды
(`component` принял поколенческую отметку вместо булева `seen`).

**Трапы** (обе пойманы probe-сверкой на Париже, 1288 / 772 506):

- **`passable` между раундами НЕ монотонна.** Калитка, вставшая на дорожный
  проём (в пределах `JOIN_EPSILON` 0.5 м), при пересборке слитых списков
  тянет его диск на себя (`merge_gaps` кладёт калитки раньше дорожных
  проёмов), и по краю старого положения диска тайлы закрываются обратно.
  Первая версия — «дельта = открыть тайлы нового проёма» (без сброса к базе)
  — расходилась с полным пересбором: применение наблюдаемых открытий к
  сетке прошлого раунда не совпадало с сеткой полного пересбора ни в одном
  раунде с 2-го. Отсюда снимок в боксах вместо разблокировки.
- **retain по `cut`, а не по `!reachable`, теряет карманы.** Тайл,
  закрывшийся пересбором обратно, выпадает из набора и может открыться
  следующим раундом — компакт держит всё ещё недостижимое.

Плюс рядовая ловля: в `filter_map` по `zip(watched, before)` индекс тайла
нужно разворачивать из паттерна, а не брать от `enumerate` — первая правка
подсунула скану позиции в списке вместо индексов тайлов.
