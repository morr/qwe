## Проблема

Стены без разреза внутри (бенч `map_meshing paris` записи 45, числа под
contention живой пары):

- **verges prep** — обочины по улицам в потоках на каждую ступень
  (`map/roads.rs` ~1097–1115 → `verges::street_verge_geometry` через
  `in_parallel(&order)`); проходы по ступеням серийные (live 162+80, соло
  wall 97.6 на ступень 0 против CPU/10 ≈ 47 — расхождение не объяснено:
  либо медленные улицы, либо аллокационный хвост 30 000 по-штучных вкладов).
  Внутри по-уличного прохода разреза по-уличной работы нет — распределение
  длительностей улиц не измерялось.
- **corners returns** — сбор лучей (`road_arms`) и поузловой расчёт
  (`node_returns`) под двумя внешними потоками ступеней
  (`map/roads.rs::RoadCommon::new`, `in_parallel(steps)`), каждый разводит
  свои внутренние `in_parallel` — 2 × 10 потоков на 10 ядрах. Фазы внутри
  разрезаны (запись 44: contrib 35 + nodes_list 13 + yards 7.4 + partials
  37–45 + apply 6), стена — сам вложенный параллель.
- layout ленты 48 (appends 19 / verges_apply 24 / bridges 1.8 — запись 42)
  и nodal-стены `Drawn::new` ≈100 — разрезы есть, куски < планки.

**Не рычаги** (отмечено записями 34/39/43/44/45, не пытаться):

- mesh обочин 366 CPU — насыщенный параллель по улицам (earcut плотных
  лент, как `find` записи 34);
- `find`/`find_green` лоскутов 424 — насыщенный параллель, батчинг
  опровергнут цифрами (записи 34/44);
- сетки звеньев/препятствий стежков 21+16 — порядок вставки пинит выбор
  стыка (записи 39/44);
- итоговый union устьев 47 — однопроходный якорь дыр (записи 43/44);
- сетка `Meadows` уже стоит (запись 45: meadows 0.4–4 в обоих проходах).

## Направление — разрез хвоста verges-прохода, фикс крупнейшего ≥150

**Разрез** (временные `eprintln`; патчи разреза 35 на пост-фиксный код не
накатываются — таймеры вносятся руками, урок записи 44; свой патч в
`/tmp/perf36-drill.patch` до любого отката, держать, пока правка не
закоммичена, урок записи 42):

- per-street CPU: `Instant` на вызов `street_verge_geometry`, слоты
  `AtomicU64` по индексу улицы; после прохода — сумма, максимум, верхние
  улицы (позиция, индекс, длина оси), доли свыше 1/5/10 мс; wall прохода —
  `Instant` у вызывающего (как в разрезе 35);
- суммы CPU по фазам (queries / bites / seam / meadows / profile / mesh /
  bands / pieces) — расстановка из `/tmp/perf35-drill.patch` руками;
- суммы CPU по чанкам (`ribbon_lane::chunks`): сумма уличных длительностей
  куска против wall прохода — подтверждение или опровержение дисбаланса;
- corners: свежие walls (`returns` / `lay` на ступень) соло-бенчем и живьём
  — база для сведения пула.

Соло-бенч `map_meshing paris` ×3 (свои живые процессы заглушены — урок
записи 42), живой прогон — под contention фоновых лайн.

**Фикс** — крупнейший кусок ≥150 мс wall; кандидаты по разрезу:

1. **verges: чанки + сведение двух проходов ступеней в один пул.** Кусок
   (`ribbon_lane::chunks` — тот же список чанков, по которому раскладка
   ленты уже итерирует диапазоны) строит **частичный вклад ступени**: один
   `StreetVerges` на кусок (3 сборщика + `Scraps` + pieces), улицы внутри
   куска пишут прямо в него — без по-штучных аккумуляторов, урок записи 42.
   Оба прохода (ступени) — один пул `in_parallel` по парам (ступень, кусок);
   раскладка — аппенды частичных вкладов в порядке кусков в существующем
   цикле по чанкам ленты (список тот же — выравнивание бесплатное). Порядок
   совпадает по построению: внутри куска улицы в порядке заливки, куски
   аппендятся по порядку — та же последовательность, что у по-уличной
   раскладки; `Scraps::merge` требует чистой сетки (assert) — чанковые
   `Scraps` её до слияния не строят.
2. **corners: сведение вложенного параллеля в один пул.** `road_arms` по
   парам (ступень, дорога) и `node_returns` по парам (ступень, узел) —
   одними пулами вместо 2 внешних × 10 внутренних потоков; вклады сливаются
   по ступеням в порядке дорог/узлов — то же, что у серийного сбора каждой
   ступени; `lay` ступеней — после возврата, по ступеням в потоках.

Выходы обязаны остаться бит-в-бит: счётчики **обеих** строк `road meshing:`
— контроль (заявленный класс перестановки тайлов — `+N` vertices, не
молчаливая смена); строка `roads` бенча бит-в-бит (различается только
build-время). Лента не пишет в `MapData` — `SNAPSHOT_VERSION` не трогается.

**Правило выхода** (заезды 29–35): рычаг в замороженных файлах
(`map/inspect.rs`, `map/osm/download.rs`, `src/loading.rs`,
`map/osm/model.rs`, `map/osm/model/trees.rs` — запись 30), или крупнейшая
фаза <150 мс wall, или цена меньше планки — следующая по рейтингу фаза
записи 45 (corners flatten → layout appends/verges_apply → nodal-стены) и
отметка в этой спеке и записи 46.

## Ожидание и риски

**Итог разреза (заезд 36, соло-бенч ×3, разброс 1–2 %)** — гипотеза
дисбаланса улиц **опровергнута**: максимум по улице 5.4–8.7 мс (свыше
10 мс — ноль улиц), максимум по чанку 12–14 мс, притом wall прохода 94–100
против CPU 554–557 (CPU/10 ≈ 55.5). Хвост держала **сантехника
результатов**: 123k+ по-штучных `StreetVerges` на проход — sort+collect
результатов после join, аллокационный шторм по-штучных сборщиков
(~107 мс CPU не тированных фазами). Дорогие улицы кластеризуются в конце
порядка заливки (чанки 1148–1249 по 10–14 мс), но их мало — сами по себе
они хвост не объясняют.

- Фикс 1 (чанки + один пул) принят: бенч-пара roads 1237.1 → 1183.1
  (−54.0, чистый прогон ×3), CPU прохода 554 → ~404, live verges 178.5
  (104+74.5) → 70.1–95.2 одним пулом, раскладка verges_apply 21–25 →
  14–17 своих.
- Фикс 2 (сведение corners в один пул) **отвергнут**: бенч на одной
  ступени паритет (108.7–115.0 против 105–108), но живьём — регрессия:
  returns_steps 334.8–379.5 против 203.4–207.0 у вложенного конвейера.
  Вложенный конвейер прятал серийные стадии (слияние вкладов ~60,
  список+сортировка, apply ~8, yards) под параллельными стадиями соседней
  ступени; staged-структура делает каждую стадию отдельной стеной. Revert
  коммитом; вложенный параллель ступеней — не рычаг (два × 10 потоков
  ядро делит само).

- Цель: разрез подтверждает или опровергает дисбаланс verges-прохода
  (сумма CPU по чанкам против wall, верхние улицы) и даёт свежие walls
  corners; фикс снимает крупнейший кусок (`map meshes: roads in`, whole
  set медианой живой пары, обе строки `road meshing:`).
- Ожидание по фиксам: verges live 242 → ~130–150 — сведение ступеней
  снимает серийную часть двух проходов, чанки — аллокационный хвост
  30 000 по-штучных вкладов, если он есть; corners live ~245 → ~130–160 —
  двойной пул на 10 ядрах, wall ≈ CPU/10. Соло-бенч надёжнее живой пары
  (записи 27/43/44/45).
- Риски: если хвост держит одна улица (max ≈ wall − CPU/10) — чанки её не
  снимают, снимает сведение ступеней в один пул (второй элемент фикса 1);
  если wall гуляет от аллокаций — чанки с прямым письмом в частичный вклад
  снимают и её. Если разрез покажет иную картину — фикс по данным, отметка
  в спеке. Малый вход (тесты, витрины) — прежний путь: `in_parallel`
  сводит к одному потоку, чанки вырождаются в один.
